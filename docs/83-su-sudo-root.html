su et sudo — Devenir root et exécuter avec privilèges

Introduction

Sur Linux, certaines actions nécessitent des droits spéciaux. Installer un logiciel, modifier la configuration système, redémarrer un service… Tout cela exige d'être root, le超级 utilisateur qui a tous les droits. su et sudo sont les deux méthodes principales pour obtenir ces privilèges. Comprendre leur différence et savoir les utiliser est essentiel pour tout administrateur Linux.

Le compte root

Qui est root ?

Le compte root (aussi appelé superuser) est l'administrateur du système. Il peut :

  • Lire, modifier ou supprimer n'importe quel fichier
  • Installer ou supprimer des logiciels
  • Modifier les utilisateurs et les groupes
  • Redémarrer des services ou le système
  • Accéder à tous les périphériques
# Vérifier son identité whoami # root si vous êtes connecté en tant que root # david si vous êtes un utilisateur normal # Voir l'UID de root (toujours 0) id root # uid=0(root) gid=0(root) groupes=0(root)

Risques de l'utilisation root

Être root est puissant mais dangereux. Une erreur peut détruire le système. C'est pourquoi Linux recommande d'utiliser le principe du moindre privilège : utiliser root uniquement quand c'est nécessaire.

su — Switch User

Basique : devenir root

# Devenir root (demande le mot de passe root) su - # Les options : # su - → root avec un shell de login (environnement propre) # su → root sans changer d'environnement # su - user → devenir "user" spécifique

Différence entre su et su -

# sans "-" : conserve l'environnement de l'utilisateur actuel su echo $HOME # Affiche /home/david pwd # Reste dans /home/david # avec "-" : charge l'environnement de root comme un vrai login su - echo $HOME # Affiche /root pwd # change pour /root exit # Retourne à l'utilisateur initial

Devenir un autre utilisateur

# Devenir un autre utilisateur (sans être root) su - marie # Exécuter une commande unique en tant que autre utilisateur su - marie -c "ls /home/marie" # Devenir root et exécuter une commande précise su -c "apt update"

Comprendre le mécanisme de su

# Ce qui se passe : # 1. Vous tapez "su -" # 2. Le système demande le mot de passe de root # 3. Un nouveau shell s'ouvre avec les droits root # 4. Vous avez un accès complet au système # Pour quitter le shell root : exit # ou Ctrl+D

sudo — Super User DO

Principe de sudo

sudo permet à un utilisateur autorisé d'exécuter des commandes en tant que root (ou un autre utilisateur), sans avoir besoin du mot de passe root. L'autorisation est gérée par le fichier /etc/sudoers.

# Exécuter une commande unique avec les droits root sudo apt update # Le système demande le MOT DE PASSE DE L'UTILISATEUR COURANT # (pas le mot de passe root !)

Pourquoi sudo plutôt que su ?

Configuration de base

# Ajouter un utilisateur au groupe sudo (Debian/Ubuntu) sudo usermod -aG sudo david # Sur CentOS/RHEL, le groupe s'appelle "wheel" sudo usermod -aG wheel david # Vérifier si un utilisateur est dans le groupe groups david # david : david sudo

La première utilisation de sudo

# Après l'installation d'Ubuntu, le premier utilisateur est déjà sudoer # Sur certaines distributions, il faut configurer manuellement : # Se connecter en tant que root su - # Ajouter un utilisateur aux sudoers usermod -aG sudo nom_utilisateur # Ou modifier le fichier sudoers (méthode recommandée) visudo # Ajoute cette ligne : # nom_utilisateur ALL=(ALL:ALL) ALL

Le fichier /etc/sudoers

Syntaxe de base

# Format général : # qui où=(qui:groupe) quoi # Autoriser l'utilisateur david à exécuter tout david ALL=(ALL:ALL) ALL # Autoriser le groupe "developers" à exécuter apt %developers ALL=(ALL) /usr/bin/apt # Permettre à un utilisateur d'exécuter sans mot de passe david ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart apache2

Édition sécurisée avec visudo

# TOUJOURS utiliser visudo pour éditer sudoers sudo visudo # Pourquoi ? visudo valide la syntaxe et bloque les erreurs # Une erreur de syntaxe peut vous verrouiller hors du système ! # Si vous faites une erreur : # L'éditeur nano vous montre les erreurs #wq! pour forcer la sauvegarde (déconseillé en production)

Exemples de configurations

# Autoriser un utilisateur à exécuter toutes les commandes alice ALL=(ALL:ALL) ALL # Autoriser un groupe à exécuter apt-get (installation) %installers ALL=(ALL) /usr/bin/apt-get, /usr/bin/dpkg # Permettre sudo sans mot de passe (WORKSPACE ONLY!) %admin ALL=NOPASSWD: ALL # Autoriser un utilisateur à redémarrer un service spécifique david ALL=(ALL) /usr/bin/systemctl restart nginx

Options utiles de sudo

-i : Shell interactif

# Ouvrir un shell root interactif (similaire à su -) sudo -i # Équivalent à : sudo su - # Vous êtes root sans connaître le mot de passe root # Pour un autre utilisateur : sudo -i -u marie # Équivalent à : su - marie (avec le mot de passe de l'utilisateur courant)

-s : Shell non interactif

# Obtenir un shell root non interactif sudo -s # Pas de changement d'environnement, juste les privilèges # Comme utilisateur spécifique sudo -s -u www-data

-u : Exécuter en tant qu'utilisateur

# Exécuter une commande en tant qu'un autre utilisateur sudo -u www-data whoami # Affiche : www-data # Utile pour les services web sudo -u apache /opt/scripts/backup.sh

-l : Lister les permissions

# Lister mes permissions sudo sudo -l # Exemple de sortie : # User david may run the following commands on this host: # (ALL : ALL) ALL # (root) /usr/bin/systemctl restart apache2 # Lister les permissions d'un autre utilisateur sudo -l -U marie

-k : Invalider le ticket

# Forcer sudo à redemander le mot de passe sudo -k # Vérification : après -k, toute commande sudo redemande le mot de passe

Logs sudo

Où sont stockés les logs ?

# Voir l'historique des commandes sudo (journalctl) sudo journalctl SYSLOGFacility=auth | grep sudo # Sur certaines distributions, dans /var/log/auth.log (Debian) cat /var/log/auth.log | grep sudo # Sur RHEL/CentOS : cat /var/log/secure | grep sudo

Analyser les logs

# Trouver toutes les commandes sudo d'un utilisateur sudo journalctl _COMM=sudo | grep david # Voir les tentatives échouées sudo journalctl _COMM=sudo | grep "AUTH FAIL" # Afficher les commandes récentes (last hour) sudo journalctl -u sudo --since "1 hour ago"

Bonnes pratiques

Règles de sécurité

  • Ne jamais partager le mot de passe root
  • Utiliser sudo plutôt que su en production
  • Limiter les permissions au strict nécessaire
  • Toujours utiliser visudo pour modifier /etc/sudoers
  • Vérifier les logs régulièrement pour détecter des anomalies
  • Expirer les sessions sudo après quelques minutes

Configuration sécurisée

# Exemple de configuration sudoers sécurisée # Limiter aux commandes nécessaires uniquement # L'utilisateur peut installer des logiciels alice ALL=(ALL) /usr/bin/apt-get, /usr/bin/dpkg # L'utilisateur peut redémarrer nginx alice ALL=(ALL) /usr/bin/systemctl restart nginx # L'utilisateur peut lire les logs mais pas les modifier alice ALL=(ALL) /usr/bin/tail /var/log/nginx/*.log

Timeout de session sudo

# Par défaut, sudo mémorise le mot de passe pendant 15 minutes # Pour changer ce délai (dans /etc/sudoers) : # Timeout de 5 minutes (par défaut) Defaults env_reset # Timeout de 30 minutes Defaults env_reset, timestamp_timeout=30 # Demander le mot de passe à chaque fois Defaults timestamp_timeout=0

Erreurs courantes

"User is not in the sudoers file"

# Problème : l'utilisateur n'a pas les droits sudo # Solution : se connecter en root et ajouter l'utilisateur # Option 1 : utiliser su (si vous connaissez le mot de passe root) su - usermod -aG sudo nom_utilisateur exit # Option 2 : depuis un autre utilisateur avec sudo sudo usermod -aG sudo nom_utilisateur # Option 3 : éditer /etc/group directement (solution de secours) # Ajouter l'utilisateur au groupe sudo sudo usermod -aG sudo nom_utilisateur

"sudo: command not found"

# sudo n'est pas installé # Solution : installer sudo su - apt install sudo # Ou sur CentOS/RHEL : yum install sudo

Trop de tentatives sudo

# Le message "sudo: 3 incorrect password attempts" # Attend quelques minutes ou，出口，重新试试 # Si vous êtes bloqué, utilisez su (si root connu) su - visudo # Réparer la configuration

Cas pratiques

Gestion des services

# Redémarrer un service (sans être root directement) sudo systemctl restart nginx # Voir les logs d'un service (avec permissions) sudo journalctl -u nginx # Arrêter un service critique sudo systemctl stop mariadb

Installation de logiciels

# Mettre à jour le système sudo apt update && sudo apt upgrade -y # Installer un nouveau paquet sudo apt install nginx # Supprimer un logiciel sudo apt remove --purge apache2

Modification de fichiers système

# Éditer un fichier protégé sudo nano /etc/hosts # Lire un fichier root-only sudo cat /etc/shadow # Copier un fichier en root sudo cp /tmp/config.cfg /etc/app/config.cfg

Scripts d'automatisation

#!/bin/bash # Script avec sudo intégré if [ "$EUID" -ne 0 ]; then exec sudo "$0" "$@" fi # Le script s'auto-exécute avec sudo si pas lancé en root apt update systemctl restart mon_service

Exercices pratiques

  1. Basique : Utilisez sudo whoami pour vérifier que vous avez les droits sudo.
  2. Shell root : Ouvrez un shell root avec sudo -i, vérifiez avec whoami, puis tapez exit.
  3. Lister les permissions : Exécutez sudo -l pour voir toutes vos permissions sudo.
  4. Utilisateur alternatif : Utilisez sudo -u www-data whoami pour exécuter une commande en tant qu'utilisateur www-data.
  5. Configuration : Ajoutez un nouvel utilisateur au groupe sudo avec sudo usermod -aG sudo newuser.
  6. Logs : Consultez les logs sudo dans /var/log/auth.log (Debian) ou /var/log/secure (RHEL).
  7. Script sécurisé : Créez un script qui s'auto-exécute avec sudo si lancé par un utilisateur non-root.
  8. Défi : Configurez sudoers pour qu'un utilisateur puisse ONLY redémarrer nginx et pas faire autre chose.

Conclusion

su et sudo sont vos alliés pour gérer les privilèges sous Linux. su vous donne un accès complet quand vous en avez besoin, tandis que sudo permet un contrôle fin et une traçabilité. En production, privilégiez toujours sudo : c'est plus sécurisé, plus traçable, et cela évite de partager le mot de passe root. Configurez vos permissions avec soin, utilisez visudo, et consultez régulièrement les logs pour garder le contrôle de votre système.
