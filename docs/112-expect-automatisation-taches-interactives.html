Leçon 112 : expect — Automatiser les tâches interactives

Vous êtes-vous déjà retrouvé face à un script ou une commande qui demande un mot de passe en interatif, vous empêchant de l'automatiser complètement ? expect est l'outil qui résout ce problème. Il permet de contrôler des programmes interactifs en envoyant des réponses automatiques à des invites (prompts) précises. Dans cette leçon, vous apprendrez à maîtriser expect pour automatiser les tâches qui sonst impossibles à pipeline.

Pourquoi expect ?

La plupart des outils Linux peuvent être chainés avec des pipes ou scriptés. Mais certains programmes posent des questions en cours d'exécution :

  • Connexion SSH avec mot de passe (non par clé)
  • Commandes qui demandent confirmation (yes/no)
  • Interfaces en ligne qui nécessitent une interaction humaine
  • Scripts de déploiement qui demandent un mot de passe root
  • Utilitaires comme ftp, telnet, passwd

expect remplace l'humain : il lit la sortie du programme, détecte les patterns que vous définissez, et envoie les réponses appropriées.

Installation

# Debian/Ubuntu
sudo apt update && sudo apt install expect
# Fedora / RHEL / CentOS
sudo dnf install expect
# Arch Linux
sudo pacman -S expect

Le principe de base

expect fonctionne avec un interpréteur spécialisé qui lit la sortie stdout/stderr d'un programme et y répond automatiquement. Le principe est simple :

  1. spawn — Lancer le programme à contrôler
  2. expect — Attendre un motif (pattern) précis dans la sortie
  3. send — Envoyer une réponse au programme
  4. interact — Rendre la main à l'utilisateur (optionnel)

Premier exemple : automatiser SSH avec mot de passe

C'est l'utilisation la plus classique de expect. Imaginons que vous devez vous connecter en SSH avec un mot de passe (sans clé SSH) et exécuter une commande :

#!/usr/bin/expect -f
# Timeout en secondes pour chaque expect
set timeout 20
# Variables
set user "admin"
set host "192.168.1.10"
set password "MonMotDePasse123"
# 1. Lancer SSH
spawn ssh ${user}@${host}
# 2. Attendre le prompt du mot de passe et envoyer le mot de passe
expect "password:"
send "$password\r"
# 3. Attendre l'invite du shell et exécuter une commande
expect "$ "
send "uname -a\r"
# 4. Quitter
expect "$ "
send "exit\r"
# 5. Rendre la main à l'utilisateur (ici on quitte tout de suite)
expect eof

Enregistrez ce script, rendez-le exécutable, et lancez-le :

chmod +x script_ssh.expect
./script_ssh.expect

La ligne shebang

Tout script expect commence par la ligne shebang qui indique au système d'utiliser l'interpréteur expect :

#!/usr/bin/expect -f

L'option -f signifie "lire les commandes depuis le fichier". Vous pouvez aussi utiliser #!/usr/bin/expect -df pour le mode debug (affiche chaque commande exécutée).

Les commandes expect fondamentales

set — Définir des variables

set nom_variable valeur
# Exemple
set timeout 30
set mon_port 22
# Accéder à une variable : $nom_variable
puts "Le port est $mon_port"

spawn — Lancer un programme

spawn commande [arguments]
# Exemples
spawn ssh user@host
spawn scp fichier.txt user@host:/dest/
spawn ftp serveur.com
spawn passwd

expect — Attendre un motif

expect pattern

expect bloque l'exécution jusqu'à ce que la sortie du programme contienne le pattern spécifié. Le pattern peut être :

  • Une chaîne exacte : "password:"
  • Une expression régulière : "(yes/no)"
  • Un timeout : "timeout" (par exemple expect "password:" suivi de expect "password:")
  • Une réponse par défaut (si timeout) : expect { "password:" { send "pwd\r" } timeout { puts "Trop long!"; exit 1 } }
# Attendre plusieurs possibilities (répond à la première qui match)
expect {
"yes/no" { send "yes\r" ; exp_continue }
"password:" { send "$password\r" }
timeout { puts "Timeout!" ; exit 1 }
}

L'instruction exp_continue permet de continuer à attendre après un match sans quitter le bloc expect.

send — Envoyer du texte

send "texte\r"

Le \r simule la touche Entrée (carriage return). Sans lui, le texte est envoyé mais la commande n'est pas validée.

send "mon_mot_de_passe\r"
send "yes\r"
send "\r" # Simplement appuyer sur Entrée

interact — Rendre la main à l'utilisateur

Quand vous voulez自动化 certaines étapes mais laisser l'utilisateur intervenir manuellement :

#!/usr/bin/expect -f
spawn ssh user@serveur
expect "password:"
send "MonPassword\r"
# À partir d'ici, l'utilisateur reprend le contrôle du terminal
interact

expect_out — Capturer la sortie

Vous pouvez capturer le texte qui précède le match dans une variable :

expect "utilisateur@(.+):~$ "
puts $expect_out(1,string) # Affiche le hostname capturé

Exemples pratiques complets

Exemple 1 : automatiser la commande scp avec mot de passe

#!/usr/bin/expect -f
set timeout 30
set file [lindex $argv 0] # Premier argument : fichier source
set dest [lindex $argv 1] # Deuxième argument : destination
spawn scp $file $dest
expect {
"yes/no" { send "yes\r" ; exp_continue }
"password:" { send "MonPassword\r" }
}
expect eof
catch wait result
exit [lindex $result 3]

Utilisation :

./scp_auto.expect mon_fichier.txt user@serveur:/home/user/

Exemple 2 : répondre automatiquement à une installation interactive

Parfois, un script d'installation pose plusieurs questions. Avec exp_continue, vous pouvez chaîner les réponses :

#!/usr/bin/expect -f
set timeout 60
spawn ./install_script.sh
expect {
"Enter your name:" { send "David Hinni\r" ; exp_continue }
"Select option (1/2/3):" { send "2\r" ; exp_continue }
"Continue? (y/n)" { send "y\r" ; exp_continue }
"password:" { send "rootpwd\r" ; exp_continue }
eof
}

Exemple 3 : expect dans un script bash (bloc embeddé)

Vous pouvez aussi utiliser expect directement dans un script bash avec la commande expect -c (utile pour les one-liners) :

#!/bin/bash
# Automation SSH en une seule ligne (avec expect -c)
expect -c '
spawn ssh utilisateur@serveur
expect "password:"
send "MotDePasse\r"
expect "$ "
send "df -h\r"
expect "$ "
send "exit\r"
expect eof
'

Ou avec un here-doc dans un script bash :

#!/bin/bash
/usr/bin/expect <
spawn ssh user@host
expect "password:"
send "password123\r"
expect "$ "
send "uptime\r"
expect "$ "
send "exit\r"
expect eof
EOF

Exemple 4 : boucle pour plusieurs serveurs

#!/usr/bin/expect -f
set timeout 15
set password "MonMotDePasse"
# Liste des serveurs (séparés par des espaces)
set servers { "serveur1" "serveur2" "serveur3" }
foreach server $servers {
spawn ssh admin@$server
expect {
"yes/no" { send "yes\r" ; exp_continue }
"password:" { send "$password\r" }
}
expect "$ "
send "uname -n && uptime\r"
expect "$ "
send "exit\r"
expect eof
puts "=== $server terminé ==="
}

Les motifs (patterns) courants

MotifUsage
"password:"Invite de mot de passe SSH, sudo, FTP...
"yes/no"Confirmation de clé SSH
"$ "Invite shell standard utilisateur
"# "Invite root
"--More--"Sortie paginée (avec espace pour continuer)
"Continue? (y/n)"Confirmation générique
"Enter selection:"Menu interactif
timeoutDépassement du délai d'attente
eofLe programme s'est terminé

Gestion des erreurs et timeouts

Timeout global

# Timeout de 30 secondes pour TOUS les expect suivants
set timeout 30

Timeout par expect

expect {
"password:" { send "$pwd\r" }
timeout {
puts "Le serveur ne répond pas après 20 secondes"
exit 1
}
}

Code de retour

# Capturer le code de retour du programme spawné
expect eof
catch wait result
set exit_code [lindex $result 3]
if {$exit_code != 0} {
puts "Erreur: le programme a échoué avec le code $exit_code"
exit $exit_code
}

Variables d'environnement expect

VariableDescription
timeoutDélai d'attente par défaut en secondes (par défaut : 10)
expect_out(buffer)Tout le texte lu avant le match
expect_out(1,string)Première parenthèse capturante du pattern
env(HOME)Variable d'environnement HOME

Expressions régulières dans expect

Vous pouvez utiliser des expressions régulières pour des patterns plus souples :

# Accepter "password:", "Password:", ou "PASSWORD:"
expect -re "(?i)password:"
# Capturer l'adresse IP dans la sortie SSH
expect "ssh: (.+)\\. Please"
set captured_ip $expect_out(1,string)
puts "Connexion à $captured_ip"

Bonnes pratiques et sécurité

Ne JAMAIS stocker de mots de passe en clair

# Mauvais : mot de passe en clair dans le script
set password "MonMotDePasse123" # DANGEREUX

Utilisez plutôt :

  • Des clés SSH (meilleure solution, voir leçon 77)
  • Des variables d'environnement lues depuis un fichier sécurisé
  • Des fichiers avec permissions 600
  • Des gestionnaires de secrets

Protéger vos scripts expect

# chmod 700 : seul le propriétaire peut lire/exécuter
chmod 700 script.expect
# Ou rendre le fichier illisible pour les autres processus
chmod 600 script.expect

Activer le mode debug

#!/usr/bin/expect -df # -d = debug, -f = fichier

En mode debug, chaque action est affichée, ce qui aide à comprendre pourquoi un pattern ne matche pas.

Résoudre les problèmes courants

Le pattern ne matche jamais

Problème fréquent : le programme affiche quelque chose de légèrement différent. Utilisez -d pour voir exactement ce qui est affiché :

#!/usr/bin/expect -df # Mode debug
spawn ssh user@host
expect -d "password:"

Le debug affiche le buffer exact, ce qui permet de voir les espaces, retour à la ligne, ou caractères cachés.

Accents et caractères spéciaux

expect fonctionne en byte. Pour les caractères accentués, utilisez les codes :

# Envoyer un caractère spécial
send "MonNom\x0D" # \x0D = retour chariot (CR)

Le programme termine trop vite (avant le expect)

Ajustez le timeout ou utilisez expect_before :

# Attendre que le spawn soit prêt
set timeout 5
expect "ready" # ou autre indicateur que le programme a démarré

Conclusion

expect est un outil puissant pour automatiser les tâches interactives sous Linux. Bien que la meilleure pratique reste d'utiliser des clés SSH pour éviter les mots de passe en clair, expect reste indispensable pour scriptes les programmes qui nesupportent pas l'authentification par clé. Pensez toujours à sécuriser vos scripts (permissions 600/700, variables d'environnement) et à tester avec le mode debug (-d) avant de les déployer en production.
