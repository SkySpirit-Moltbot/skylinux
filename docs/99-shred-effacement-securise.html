Leçon 99 : shred — L'effacement sécurisé de fichiers

Quand vous supprimez un fichier avec rm, les données restent physiquement sur le disque. N'importe qui avec un outil de récupération peut les retrouver. La commande shred écrase le contenu du fichier plusieurs fois avant de le supprimer, rendant les données quasi irrattrapables.

Principe fondamental

shred fonctionne en écriture sur les données existantes du fichier. Il remplit le fichier avec des motifs de données aléatoires ou spécifiques, et répète cette opération plusieurs fois (par défaut 3 passes). C'est ce qu'on appelle le nettoyage sécurisé ou secure wiping.

Utilisation de base

Effacement simple

shred monfichier.txt

Cela effectue 3 passes d'écrasement puis supprime le fichier.

Spécifier le nombre de passes

shred -n 7 monfichier.txt

Ici, 7 passes d'écrasement sont effectuées. Plus il y a de passes, plus l'effacement est sécurisé — mais c'est aussi plus long.

Voir la progression

shred -v monfichier.txt

L'option -v (verbose) affiche chaque passe effectuée.

Effacer et supprimer

shred -u monfichier.txt

L'option -u efface le fichier puis le supprime. C'est l'utilisation la plus courante.

Combiner les options les plus utiles

shred -n 25 -vu monfichier.txt

25 passes, mode verbeux, puis suppression.

Options principales

OptionDescription
-n NNombre de passes (défaut : 3)
-uSupprime le fichier après l'effacement
-vMode verbeux (affiche la progression)
-zAjoute une passe finale avec des zéros (pour masquer l'effacement)
-fForce l'effacement même si le fichier est en lecture seule
-s NLimite la taille à N octets (utile pour les fichiers spéciaux)

Exemples pratiques

Effacer un document sensible

shred -n 10 -vu ~/.ssh/id_rsa

Effacer plusieurs fichiers d'un coup

shred -n 5 -vu fichier1.txt fichier2.txt fichier3.txt

Effacer un disque ou une partition (DANGEREUX)

shred -n 3 -v /dev/sdb1

⚠ Attention : Effacer une partition ou un disque est irréversible. Vérifiez thrice la cible avant d'exécuter cette commande !

Masquer l'effacement avec des zéros

shred -n 7 -z -u fichier_confidentiel.txt

La dernière passe avec des zéros rend l'effacement moins visible — comme si le fichier contenait des données normales.

Limites et pièges

Les systèmes de fichiers modernes

ℹ À savoir : Sur les systèmes avec journalisation (ext4, btrfs, XFS), les métadonnées peuvent créer des copies des données. shred ne peut pas garantir un effacement complet sur ces systèmes.

SSD et TRIM

Les SSD utilisent une technique appelée wear leveling qui déplace les données physiquement. shred ne peut pas garantir l'effacement de toutes les cellules mémoire sur un SSD. Pour un effacement sécurisé sur SSD, utilisez plutôt les outils fournis par le fabricant (comme hdparm ou le secure erase du firmware).

Les fichiers copiés

Si vous avez copié un fichier avec cp, shred ne pourra pas effacer l'original à travers la copie. Effacez chaque copie séparément.

Les snapshots et backups

Si votre système fait des snapshots (comme avec LVM ou Btrfs), les données peuvent persister dans ces snapshots même après l'effacement.

Alternative : shred dans un tube

Vous pouvez aussi utiliser shred avec des données venues d'un tube :

cat /dev/urandom | shred -n 5 -s 1M - > fichier_blindee.txt && shred -u fichier_blindee.txt

Récapitulatif

CommandeEffet
shred fichier3 passes, fichier non supprimé
shred -u fichier3 passes + suppression
shred -n 25 -zu fichier25 passes + zéros + suppression
shred -vf fichier3 passes, verbeux, forcé (fichiers protégés)

Bonnes pratiques

  • Utilisez toujours -u si vous voulez que le fichier soit supprimé à la fin
  • Pour les fichiers vraiment sensibles, utilisez au moins 7 passes
  • Sur SSD, préférez les outils de secure erase du firmware
  • Attention aux systèmes de fichiers journalisés — shred ne garantit pas un effacement à 100% dans tous les cas
  • Sur un disque dur mécanique classique, 3 à 7 passes suffisent pour la plupart des usages

shred est un outil puissant pour protéger vos données sensibles avant suppression. Mais souvenez-vous : sur les systèmes modernes avec SSD et journalisation, ses garanties sont limitées. Pour un effacement vraiment sécurisé, des solutions matérielles ou de chiffrement complet du disque restent les options les plus fiables.
