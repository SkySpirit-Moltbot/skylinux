ssh-keygen et ssh-agent — Clés SSH et agent d'authentification

Introduction

Vous en avez assez de taper votre mot de passe à chaque connexion SSH ? Les clés SSH offrent une alternative plus sécurisée et plus pratique. ssh-keygen crée des paires de clés (publique/privée), et ssh-agent garde vos clés déchiffrées en mémoire pour éviter de retaper votre phrase secrète à chaque connexion.

Dans cette leçon, vous apprendrez à générer des clés SSH robustes, à les déployer sur des serveurs distants, et à utiliser ssh-agent pour une expérience sans friction.

Générer une paire de clés SSH

Commande de base

La commande ssh-keygen crée une paire de clés RSA, ED25519 ou ECDSA. ED25519 est recommandé car plus sécurisé et plus rapide :

ssh-keygen -t ed25519 -C "mon_email@exemple.com"

Explications des options :

  • -t ed25519 : type de clé (ED25519, RSA, ECDSA)
  • -C "commentaire" : un label pour identifier la clé (souvent un email)

Spécifier un emplacement personnalisé

Par défaut, la clé est enregistrée dans ~/.ssh/. Pour changer l'emplacement :

ssh-keygen -t ed25519 -f ~/.ssh/cle_serveur -C "serveur-maison"

Protéger la clé par une phrase secrète

Lors de la génération, un message vous demande une phrase secrète (passphrase). Utilisez-en une forte :

Generating public/private ed25519 key pair. Enter file in which to save the key (/home/user/.ssh/id_ed25519): Enter passphrase (empty for no passphrase): Enter same passphrase again: Your identification has been saved in /home/user/.ssh/cle_serveur Your public key has been saved in /home/user/.ssh/cle_serveur.pub

Comprendre la différence entre clé publique et clé privée

Clé privée (cle_serveur)

C'est votre secret. Ne la partagez jamais. Elle reste sur votre machine locale et vous devez la protéger (chmod 600) :

chmod 600 ~/.ssh/cle_serveur

Clé publique (cle_serveur.pub)

C'est la partie que vous envoyez sur les serveurs distants. Elle peut être partagée librement. Son contenu ressemble à :

ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAILb6tLQx8tGjW4gP5kHx7nYV/3xQmK9dN2pQrX8B4x6Z serveur-maison

Déployer la clé publique sur un serveur distant

Méthode 1 : ssh-copy-id

L'outil le plus simple pour copier votre clé publique sur un serveur :

ssh-copy-id -i ~/.ssh/cle_serveur.pub user@adresse-serveur

Il vous demandera le mot de passe du serveur une dernière fois, puis ajoutera automatiquement votre clé publique dans ~/.ssh/authorized_keys du serveur.

Méthode 2 : copie manuelle

Si ssh-copy-id n'est pas disponible, faites-le manuellement :

# Afficher votre clé publique cat ~/.ssh/cle_serveur.pub

Connectez-vous au serveur et ajoutez le contenu dans ~/.ssh/authorized_keys :

mkdir -p ~/.ssh chmod 700 ~/.ssh echo "ssh-ed25519 AAAAC3Nza..." >> ~/.ssh/authorized_keys chmod 600 ~/.ssh/authorized_keys

Se connecter avec une clé SSH spécifique

Si vous avez plusieurs clés (une pour le travail, une pour GitHub, une pour votre serveur perso), spécifiez laquelle utiliser :

ssh -i ~/.ssh/cle_serveur user@adresse-serveur

Configuration SSH pour éviter de retaper les options

Le fichier ~/.ssh/config permet de stocker vos préférences par hôte :

nano ~/.ssh/config

Exemple de configuration :

Host serveur-maison HostName 192.168.1.100 User david IdentityFile ~/.ssh/cle_serveur Port 22 Host github.com HostName github.com User git IdentityFile ~/.ssh/cle_github Host * AddKeysToAgent yes UseKeychain yes

Après cela, connectez-vous simplement avec :

ssh serveur-maison

ssh-agent — Ne plus retaper sa phrase secrète

Démarrer ssh-agent

ssh-agent est un processus qui stocke vos clés déchiffrées en mémoire. Pour le démarrer :

eval "$(ssh-agent -s)"

Cela configure les variables d'environnement SSH_AUTH_SOCK et SSH_AGENT_PID.

Ajouter une clé à l'agent

Pour qu ssh-agent connaisse votre clé :

ssh-add ~/.ssh/cle_serveur

Il vous demandera la phrase secrète (une seule fois). L'agent la gardera en mémoire.

Lister les clés chargées

ssh-add -l

Ou voir les détails complets avec :

ssh-add -l

Supprimer une clé de l'agent

ssh-add -d ~/.ssh/cle_serveur

Pour supprimer toutes les clés :

ssh-add -D

Configurer le déverrouillage automatique sur macOS et Linux

macOS : utiliser le Keychain

Sur macOS, vous pouvez intégrer ssh-agent au Keychain pour ne jamais retaper votre phrase secrète :

ssh-add --apple-use-keychain ~/.ssh/cle_serveur

Ajoutez ceci à votre ~/.ssh/config pour macOS :

Host * AddKeysToAgent yes UseKeychain yes IdentityFile ~/.ssh/cle_serveur

Linux : agent avec persistence via keychain

Sur Ubuntu/Debian, installez keychain :

sudo apt install keychain

Ajoutez ceci à votre ~/.bashrc ou ~/.zshrc :

/usr/bin/keychain ~/.ssh/cle_serveur source ~/.keychain/$HOSTNAME-sh

Ainsi, l'agent persiste entre les sessions de terminal.

Bonnes pratiques de sécurité

Protéger le répertoire .ssh

chmod 700 ~/.ssh chmod 600 ~/.ssh/id_ed25519 chmod 644 ~/.ssh/id_ed25519.pub

Utiliser des clés différentes pour chaque usage

Créez des clés séparées pour :

  • Votre serveur personnel
  • GitHub / GitLab
  • Serveurs de travail

Ne jamais stocker de clés privées sur des serveurs distants

Utilisez toujours une clé locale et copiez la clé publique sur le serveur.

Définir une phrase secrete forte

Votre clé privée est aussi sécurisée que votre phrase secrète. Utilisez au moins 20 caractères avec des mots aléatoires ou générés.

Mettre une expiration sur vos clés (optionnel)

Pour les clés temporaires sur un serveur, vous pouvez ajouter une date d'expiration :

ssh-keygen -t ed25519 -V +90d -C "acces-temporaire"

Cette clé sera inutilisable après 90 jours.

Vérifier et débugger une connexion SSH

Mode verbose

Pour voir exactement ce qui se passe lors de la connexion :

ssh -vvv user@serveur

Triple v pour le niveau maximum de debug.

Vérifier que la clé est bien chargée

# Vérifier que l'agent tourne echo $SSH_AUTH_SOCK # Lister les clés chargées ssh-add -l # Voir quelle clé est utilisée (avec debug) ssh -v user@serveur 2>&1 | grep "Offering public key"

Exercice pratique

  1. Générez une clé ED25519 : lancez ssh-keygen -t ed25519 -f ~/.ssh/cle_test -C "test-cle", sans phrase secrète pour cet exercice (en usage réel, utilisez-en une).
  2. Protégez le répertoire SSH : faites chmod 700 ~/.ssh && chmod 600 ~/.ssh/cle_test.
  3. Affichez votre clé publique : cat ~/.ssh/cle_test.pub et notez son contenu.
  4. Démarrez ssh-agent : eval "$(ssh-agent -s)", puis ssh-add ~/.ssh/cle_test.
  5. Vérifiez que la clé est chargée : ssh-add -l.
  6. Créez un fichier ~/.ssh/config avec un Host personnalisé utilisant votre clé.
  7. Connectez-vous (si vous avez accès à un serveur de test) en utilisant cette configuration.

Conclusion

Les clés SSH avec ssh-agent transforment votre workflow quotidien : plus besoin de retaper des mots de passe, vos connexions sont plus sécurisées, et vous pouvez gérer plusieurs clés pour différents contextes. ssh-keygen crée la paire de clés, ssh-copy-id déploie la clé publique, ssh-agent garde vos clés déchiffrées en mémoire, et ~/.ssh/config simplifie les connexions futures. Une fois configuré, SSH devient transparent et fiable.
