Leçon 125: ss — Socket Statistics, l'outil moderne pour analyser le réseau

Dans cette leçon, vous allez découvrir ss, la commande moderne pour inspecter les sockets réseau sous Linux. Elle remplace avantageusement netstat et offre des performances bien meilleures sur les systèmes avec de nombreuses connexions.

1. Qu'est-ce que ss ?

ss signifie Socket Statistics. C'est un outil en ligne de commande qui permet d'afficher des informations détaillées sur les sockets réseau actif sur votre système Linux.

Pourquoi utiliser ss plutôt que netstat ?

  • Plus rapide sur les systèmes avec beaucoup de connexions
  • Fait partie du paquet iproute2 (déjà installé partout)
  • Affiche plus d'informations pertinentes par défaut
  • Support natif des filtres avancés

2. Installation

ss est généralement préinstallé sur les distributions Linux modernes. Il fait partie du paquet iproute2.

# Vérifier que ss est installé
which ss
# Si besoin, installer iproute2
# Ubuntu/Debian:
sudo apt install iproute2
# Fedora/RHEL:
sudo dnf install iproute
# Arch Linux:
sudo pacman -S iproute2

3. Utilisation basique

Afficher toutes les connexions

# Lister toutes les connexions (TCP, UDP, Unix)
ss
# Équivalent court
ss -a

Filtrer par protocole

# Afficher uniquement les connexions TCP
ss -t
# Afficher uniquement les connexions UDP
ss -u
# Afficher uniquement les sockets Unix (communication locale)
ss -x
# Combiner les options
ss -tu # TCP et UDP
ss -lt # TCP en écoute (listening)
ss -lu # UDP en écoute

4. Options utiles

OptionDescription
-lAfficher uniquement les sockets en écoute
-pAfficher les processus utilisant les sockets
-nNe pas résoudre les noms (afficher les ports numériques)
-rRésoudre les noms (hostname, service)
-aToutes les sockets (écoute + établies)
-eInformations étendues
-mAfficher l'utilisation mémoire du socket
-iInformations internes TCP
-oAfficher les timers (chrono)

5. Exemples pratiques

Voir tous les services en écoute

# Ports TCP en écoute
ss -ltn
# Résultat typique:
State Recv-Q Send-Q Local Address:Port Peer Address:Port
LISTEN 0 128 0.0.0.0:22 0.0.0.0:*
LISTEN 0 128 0.0.0.0:80 0.0.0.0:*
LISTEN 0 128 0.0.0.0:443 0.0.0.0:*
LISTEN 0 128 [::]:22 [::]:*

Voir les connexions établies avec les processus

# Connexions TCP établies avec nom du processus
ss -tlnp
# Exemple de sortie:
State Recv-Q Send-Q Local Address:Port Peer Address:Port Process
LISTEN 0 128 0.0.0.0:22 0.0.0.0:* users:(("sshd",pid=1234,fd=3))
LISTEN 0 128 0.0.0.0:80 0.0.0.0:* users:(("nginx",pid=5678,fd=4))

Connexions SSH actives

# Voir qui est connecté en SSH
ss | grep ssh
# Ou plus précis:
ss -tp | grep ssh

Connections par adresse IP

# Filtrer par IP source ou destination
ss dst 192.168.1.100
# Filtrer par port
ss sport = :443
ss dport = :80

Statistiques globales

# Résumé des connexions par état
ss -s
# Exemple de sortie:
Total: 156 (kernel 168)
TCP: 12 (estab 5, closed 2, orphaned 0, synrecv 0, timewait 2/0)
Transport Total IP IPv6
* 168 - -
RAW 0 0 0
UDP 4 3 1
TCP 10 8 2
INET 14 11 3
FRAG 0 0 0

6. Filtres avancés avec ss

ss permet des filtres très puissants pour analyser des situations spécifiques.

États des connexions TCP

# Connexions établies
ss state established
# Connexions en attente (synrecv)
ss state syn-recv
# TIME_WAIT (connexion fermée mais en attente)
ss state time-wait
# États possibles: established, syn-sent, syn-recv, fin-wait-1, fin-wait-2,
# time-wait, close, close-wait, last-ack, listening, closing

Combiner filtres et états

# Connexions HTTP/HTTPS établies
ss state established '( dport = :80 or dport = :443 )'
# Connexions SSH établies
ss state established '( dport = :22 )'

Filtrer par numéro de port

# Port source ou destination égal à 22
ss sport = :22
# Multiple ports (SSH ou HTTPS)
ss -tn 'dport = :22 or dport = :443'
# Plage de ports (5000 à 6000)
ss sport gt :5000 sport lt :6000

7. Cas d'utilisation réels

Diagnostiquer un serveur web lent

# Voir toutes les connexions HTTP/HTTPS
ss -ti 'dport = :80 or dport = :443'
# L'option -i affiche les infos TCP internes:
# - struct tcp_info: congestion, RTT, fenêtre receive/send

Vérifier les connexions suspectes

# Voir toutes les connexions non-locales établies
ss -tnp | grep -v 127.0.0.1 | grep ESTAB
# Chercher des connexions depuis l'extérieur sur des ports inhabituels
ss -tnp | grep ESTAB | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn

Surveiller les connexions MySQL/PostgreSQL

# Connexions MySQL (port 3306)
ss -tnp 'dport = :3306'
# Connexions PostgreSQL (port 5432)
ss -tnp 'dport = :5432'

8. Timer et monitoring continu

Pour un monitoring en temps réel, combinez avec watch :

# Surveillance continue des connexions
watch -n 1 'ss -tn'
# Surveillance des nouvelles connexions avec timer
watch -n 1 'ss -tno'

9. Comparaison avec netstat

CommandePerformanceInformationsDisponibilité
netstat -tulnLent sur beaucoup de connexionsBasiqueDeprecated
ss -tulnTrès rapideDétailléModerne, recommandé
# L'ancien netstat
netstat -tuln
# Équivalent moderne avec ss
ss -tuln

10. Bonnes pratiques

  • Utilisez toujours ss plutôt que netstat sur les systèmes modernes
  • Combinez -n avec les filtres pour éviter les lenteurs de résolution DNS
  • Pour le debugging réseau, ss -ti offre des infos TCP très utiles
  • Combinez avec grep pour filtrer rapidement : ss -tnp | grep :80
  • Pour un monitoring continu, utilisez watch : watch -n 1 'ss -s'

Résumé

La commande ss est l'outil indispensable pour quiconque administre un serveur Linux. Elle permet de diagnostiquer rapidement les problèmes de réseau, identifier les connexions actives, et surveiller l'état des services réseau.
