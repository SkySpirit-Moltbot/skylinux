188. df et du — Gérer l'espace disque

Votre disque est plein et vous ne savez pas pourquoi ? Les commandes df (disk free) et du (disk usage) sont vos premiers outils pour diagnostiquer l'espace disque sous Linux. L'une montre l'espace disponible sur les partitions, l'autre montre ce qui consomme de la place dans vos répertoires.

df — Espace disponible sur les partitions

df affiche l'espace disque libre et utilisé pour chaque système de fichiers monté.

Utilisation de base

df

Résultat typique :

Sys. de fichiers blocs de 1K Utilisé Disponible Uti% Monté sur /dev/sda1 20480000 15340000 5140000 75% / tmpfs 1024000 48 1023952 1% /dev/shm /dev/sda2 51200000 32000000 19200000 63% /home tmpfs 512000 1200 510800 1% /run

Affichage lisible par l'homme (-h)

df -h

Résultat avec des tailles lisibles (Ko, Mo, Go) :

Sys. de fichiers Taille Utilisé Dispo Uti% Monté sur /dev/sda1 20G 15G 5G 75% / /dev/sda2 49G 31G 18G 63% /home tmpfs 1000M 48K 1000M 1% /dev/shm

Afficher uniquement le système de fichiers local (-l)

df -lh

Voir un répertoire ou fichier précis

df -h /home df -h /var/log

Affiche les statistiques du système de fichiers contenant ce chemin.

Afficher les inodes (-i)

Les inodes stockent les métadonnées des fichiers. Un disque peut être plein d'inodes même avec de l'espace libre :

df -i df -i /

Afficher le type de système de fichiers (-T)

df -hT df -hT /home

Affiche une colonne supplémentaire avec le type (ext4, xfs, nfs, tmpfs…).

Options utiles de df

OptionDescription
-hTailles lisibles (Ko, Mo, Go)
-HComme -h mais avec 1000 au lieu de 1024
-TAfficher le type de système de fichiers
-iAfficher les inodes (pas les blocs)
-lN'afficher que les systèmes de fichiers locaux
-aInclure les systèmes de fichiers avec 0 blocs
--syncSynchroniser les systèmes de fichiers avant l'affichage

du — Espace utilisé par les fichiers et répertoires

du estime l'espace disque utilisé par les fichiers et répertoires.

Utilisation de base

du /home

Cela affiche la taille de chaque sous-répertoire dans /home.

Affichage lisible par l'homme (-h)

du -h /home

Voir uniquement le total pour un répertoire (-s)

du -sh /home du -sh /var/log du -sh /

Retourne uniquement la taille totale, sans le détail des sous-répertoires.

Trier par taille (--max-depth)

Pour trouver les répertoires qui consomment le plus d'espace :

du -h --max-depth=1 /home | sort -h

--max-depth=1 limite l'affichage à un niveau de profondeur, et sort -h trie par taille lisible.

Exclure un type de fichier (--exclude)

# Exclure les fichiers .log du -sh --exclude="*.log" /var # Exclure les fichiers d'un type précis du -sh --exclude="*.tmp" /tmp

Utiliser un fichier comme référence (--apparent-size)

du -sh --apparent-size fichier.tar.gz

Affiche la taille apparente (contenu) plutôt que l'espace disque réellement utilisé.

Options utiles de du

OptionDescription
-hTailles lisibles (Ko, Mo, Go)
-sAfficher uniquement le total (pas les sous-répertoires)
-aAfficher aussi les fichiers (pas seulement les répertoires)
--max-depth=NLimiter la profondeur d'affichage
--exclude=PATTERNExclure les fichiers correspondant au motif
-cAjouter une ligne de total à la fin
-LSuivre les liens symboliques
--apparent-sizeAfficher la taille apparente (pas l'allocation disque)
-mAfficher en mégaoctets

Atelier pratique : diagnostiquer un disque plein

Étape 1 — Vérifier l'état général des partitions

df -h

Repérez les partitions à plus de 80-90% d'utilisation. Ce sont vos priorités.

Étape 2 — Trouver les répertoires les plus volumineux

# Racine : afficher les répertoires de premier niveau du -h --max-depth=1 / 2>/dev/null | sort -rh | head -10

Cette commande affiche les 10 plus grands répertoires à la racine.

Étape 3 — Explorer le répertoire le plus gros

# Si /home est le plus gros du -h --max-depth=1 /home | sort -rh | head -10 # Puis drill-down dans le sous-répertoire suspect du -h --max-depth=1 /home/user/téléchargements | sort -rh | head -10

Étape 4 — Trouver les fichiers volumineux

# Trouver les fichiers de plus de 100 Mo dans /home find /home -type f -size +100M -exec ls -lh {} \;

Étape 5 — Vérifier les logs

# Taille totale des logs du -sh /var/log # Les fichiers de log les plus volumineux find /var/log -type f -name "*.log" -exec ls -lh {} \; | sort -k5 -rh | head -10

Étape 6 — Nettoyer les fichiers temporaires

# Voir la taille du cache apt du -sh /var/cache/apt/archives # Vider le cache apt (libère de l'espace sans risque) sudo apt clean # Voir la taille des thumbnails du -sh ~/.cache/thumbnails

Atelier pratique : surveillance automatique

Créer un script de surveillance de l'espace disque

#!/bin/bash # surveillance-disque.sh SEUIL=80 df -h | grep -E '^/dev/' | while read ligne; do utilisation=$(echo "$ligne" | awk '{print $5}' | sed 's/%//') partition=$(echo "$ligne" | awk '{print $1}') po=$(echo "$ligne" | awk '{print $4}') if [ "$utilisation" -ge "$SEUIL" ]; then echo "ALERTE: $partition à ${utilisation}% (il reste $po)" fi done

Rendre le script exécutable

chmod +x surveillance-disque.sh ./surveillance-disque.sh

Automatiser avec cron

# Ajouter une tâche cron pour vérifier chaque jour à 8h (crontab -l 2>/dev/null; echo "0 8 * * * /home/user/surveillance-disque.sh") | crontab -

Comprendre la différence entre taille et espace utilisé

Un fichier de 1 octet occupe au minimum un bloc sur le disque (souvent 4 Ko). C'est pourquoi du et la taille réelle d'un fichier peuvent différer.

# Créer un tout petit fichier echo "test" > /tmp/petit.txt # Taille réelle du fichier ls -l /tmp/petit.txt # Espace disque utilisé (différent !) du -h /tmp/petit.txt

Pour voir la taille apparente (le contenu réel), utilisez --apparent-size avec du ou stat :

stat /tmp/petit.txt # Size: 5 octets (contenu) # Blocks: 8 (espace disque utilisé, 8 blocs de 512 octets = 4 Ko)

Cas d'usage réels

Vérifier avant une grande installation

df -h # Si / a moins de 2 Go libre, réfléchissez avant d'installer de gros logiciels

Nettoyer un serveur web

# Trouver les logs nginx/apache volumineux du -sh /var/log/nginx/ du -sh /var/log/apache2/ # Tronquer les vieux logs (conserver le fichier, vider le contenu) sudo truncate -s 0 /var/log/nginx/access.log.old

Monitorer un serveur de fichiers

# Vérifier rapidement l'espace libre sur le serveur de fichiers df -h /mnt/partage # Trouver les 10 plus gros dossiers partagés du -h --max-depth=2 /mnt/partage 2>/dev/null | sort -rh | head -10

Préparer une sauvegarde

# Vérifier l'espace nécessaire pour /home du -sh /home # Vérifier l'espace disponible sur la partition de sauvegarde df -h /backup # Comparer avant de lancer rsync ou tar du -sh /home && df -h /backup

Résumé

CommandeDescription
df -hEspace libre sur toutes les partitions (tailles lisibles)
df -h /cheminEspace de la partition contenant /chemin
df -iAfficher les inodes (métadonnées) par partition
du -sh /repertoireEspace total utilisé par un répertoire
du -h --max-depth=1Espace de chaque sous-répertoire (1 niveau)
du -h | sort -rhTrier les répertoires par taille décroissante
find -type f -size +100MTrouver les fichiers de plus de 100 Mo

Bonnes pratiques

  • Vérifiez régulièrement l'espace disque avec df -h, surtout sur les serveurs
  • Configurez des alertes quand une partition dépasse 80-90% d'utilisation
  • Utilisez du -h --max-depth=1 pour identifier rapidement les répertoires qui consomment le plus
  • Ne confondez pas taille de fichier (contenu) et espace disque (allocation) — pour ça, stat est votre ami
  • Nettoyez régulièrement les fichiers temporaires et les vieux logs
  • Surveillez aussi les inodes avec df -i — un disque peut être plein d'inodes même avec de l'espace libre
  • Avant une opération volumineuse (compilation, téléchargement), vérifiez toujours l'espace disponible
