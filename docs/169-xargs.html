xargs — Construire et exécuter des commandes à partir de résultats

La commande xargs est un outil fondamental sous Linux. Elle permet de construire et exécuter des commandes à partir de données reçues en entrée (stdin). En d'autres termes, elle transforme le résultat d'une commande en arguments pour une autre commande. C'est le pont parfait entre deux commandes qui ne savent pas communiquer autrement.

Le principe fondamental

xargs lit des données depuis l'entrée standard (stdin) et les transforme en arguments pour une commande que vous spécifiez. Le schéma classique est :

commande_source | xargs commande_destination

Sans xargs, beaucoup de commandes ne savent pas lire depuis un pipe. Par exemple, rm ne peut pas recevoir des noms de fichiers via un pipe — xargs comble ce vide.

L'exemple le plus simple

Supposons que vous vouliez supprimer tous les fichiers dont le nom contient "temp" — vous ne pouvez pas faire ls | rm, mais vous pouvez faire :

ls | grep temp | xargs rm

xargs prend chaque ligne résultat de grep temp et la passe comme argument à rm.

Les options fondamentales

-n : nombre d'arguments par commande

Par défaut, xargs passe tous les arguments d'un coup à la commande. L'option -n 1 force l'appel de la commande une fois par argument :

# Supprimer chaque fichier UN PAR UN (plus sûr)
ls | grep temp | xargs -n 1 rm
# Créer un fichier par nom trouvé
ls *.txt | xargs -n 1 touch

-n 1 est très utile pour le débogage ou quand une commande ne supporte pas plusieurs arguments.

-I : remplacer une chaîne dans la commande

L'option -I (ou --replace) permet d'utiliser les arguments entrants à n'importe quelle position dans la commande, pas seulement en fin :

# Copier chaque fichier vers un répertoire de sauvegarde
ls *.log | xargs -I {} cp {} /backup/{}.bak
# Créer une archive par fichier
ls *.txt | xargs -I {} tar -czf {}.tar.gz {}
# Afficher avec un préfixe
echo -e "fichier1.txt\nfichier2.txt" | xargs -I {} echo "Traitement de : {}"

{} est le placeholder par défaut qui sera remplacé par chaque argument. Vous pouvez utiliser un autre marqueur avec -I AUTRE.

-d : delimiter personnalisé

Par défaut, xargs utilise l'espace et le retour à la ligne comme séparateurs. L'option -d permet de définir un autre délimiteur :

# Traiter une chaîne séparée par des virgules
echo "fichier1,fichier2,fichier3" | xargs -d ',' rm
# Traiter une chaîne séparée par des deux-points
echo "serveur1:srv2:srv3" | xargs -d ':' -n 1 ping -c 1

find + xargs : le duo classique

La combinaison la plus puissante sous Linux. find cherche les fichiers, xargs les traite :

# Supprimer tous les fichiers .tmp
find /tmp -name "*.tmp" | xargs rm
# Modifier les permissions de tous les fichiers trouvés
find . -name "*.sh" | xargs chmod 755
# Rechercher une chaîne dans tous les fichiers .c
find /src -name "*.c" | xargs grep "main("

Important : sur certains systèmes, les noms de fichiers peuvent contenir des espaces ou des caractères spéciaux. Utilisez alors -print0 avec xargs -0 pour une traitement sûr :

# Version sécurisée avec caractères spéciaux dans les noms
find /tmp -name "*.tmp" -print0 | xargs -0 rm

-p et -t : mode interactif et verbose

-p : demander confirmation avant chaque exécution

# Demander confirmation avant chaque suppression
ls | grep temp | xargs -p rm

Sortie attendue :

rm temp1.txt ?...y
rm temp2.txt ?...n

-t : afficher la commande avant de l'exécuter

# Voir exactement quelles commandes seront exécutées
ls *.txt | xargs -t rm

Très utile pour comprendre et vérifier avant de lancer un traitement destructeur.

-0 : gérer les noms de fichiers avec espaces

Associé à find -print0, -0 est la solution pour les noms de fichiers qui contiennent des espaces, guillemets ou retours à la ligne :

# Supprimer en toute sécurité (noms avec espaces)
find /photos -name "*.jpg" -print0 | xargs -0 rm
# Déplacer tous les fichiers avec des noms spéciaux
find /uploads -name "*.pdf" -print0 | xargs -0 -I {} mv {} /archives/

-P : exécuter en parallèle

L'option -P permet de parallèleiser les executions. Au lieu d'appeler la commande séquentiellement, xargs peut en lancer plusieurs simultanément :

# Compresser 4 fichiers en parallèle
ls *.txt | xargs -P 4 gzip
# Créer 8 threads pour le traitement
find /photos -name "*.jpg" | xargs -P 8 -I {} convert {} -resize 800x600 {}.small.jpg
# Paralléliser avec le nombre de CPUs disponibles
ls *.log | xargs -P $(nproc) gzip

Combiner avec d'autres outils

Avec grep

# Trouver les fichiers qui contiennent un motif
grep -rl "TODO" | xargs sed -i 's/TODO/FINI/g'
# Lister les fichiers modifiés récemment et afficher leur contenu
find . -mtime -7 | xargs grep -l "error"

Avec tar

# Créer une archive de chaque fichier individuellement
ls *.log | xargs -I {} tar -czf {}.tar.gz {}
# Archiver les résultats d'une recherche
find /var/log -name "*.log" | xargs tar -czf logs-sauvegarde.tar.gz

Avec git

# Supprimer tous les fichiers non-suivis
git status --porcelain | grep '^?' | awk '{print $2}' | xargs rm
# Ajouter les fichiers modifiés au staging
git status -s | awk '{print $2}' | xargs git add

Avec docker

# Supprimer plusieurs containers par leur ID
docker ps -aq | xargs docker rm -f
# Supprimer toutes les images dangling
docker images -f dangling=true -q | xargs docker rmi

xargs vs substitution de commande

xargs n'est pas toujours nécessaire — la substitution de commande $(...) fait parfois le même travail de manière plus lisible :

# Avec xargs
ls *.txt | xargs rm
# Avec substitution de commande (bash)
rm $(ls *.txt)

Mais xargs est supérieur quand :

  • Le nombre de résultats est très grand (la substitution peut dépasser la limite du shell)
  • Vous avez besoin de parallélisation (-P)
  • Vous voulez un comportement interactif (-p)
  • Les noms de fichiers contiennent des caractères spéciaux

Exemples pratiques complets

Nettoyage organisé

# Déplacer tous les fichiers .bak vers un dossier
find . -name "*.bak" -print0 | xargs -0 -I {} mv {} ./backup/
# Lister et créer un rapport des fichiers modifiés
find . -mtime -30 | xargs ls -lh | tee rapport.txt

Traitement d'images (ImageMagick)

# Redimensionner toutes les photos en parallèle (4 threads)
ls *.jpg | xargs -P 4 -I {} convert {} -resize 800x600 vignettes/{}
# Ajouter un filigrane à toutes les images
ls *.png | xargs -I {} composite -dissolve 30% watermark.png {} {}.watermarked.png

Automatisation système

# Redémarrer tous les services listés dans un fichier
cat services.txt | xargs -t systemctl restart
# Envoyer un ping à plusieurs serveurs
cat servers.txt | xargs -P 10 -I {} sh -c 'ping -c 1 {} && echo "{} OK" || echo "{} ECHEC"'

Génération de code

# Créer plusieurs fichiers depuis une liste
echo -e "module1\nmodule2\nmodule3" | xargs -I {} touch {}.py
# Générer des fichiers de test
seq 1 100 | xargs -I {} touch test_{}.txt

Erreurs courantes

Argument list too long

Si vous avez des milliers de fichiers, xargs peut quand même dépasser la limite. -n et -s помогают :

# Limiter à 100 fichiers par appel
find . -name "*.txt" | xargs -n 100 rm

xargs avec une entrée vide ne fait rien

Par défaut xargs exécute quand même la commande même si l'entrée est vide (avec des arguments inexistants). Utilisez -r pour éviter cela :

# Ne rien faire si grep ne trouve rien
ls | grep "invisible" | xargs -r rm

Conclusion

xargs est l'un des outils les plus polyvalents de la boîte à outils Linux. Il transforme les tuyaux (pipes) en véritable langage de script en permettant à n'importe quelle commande de consommer le résultat d'une autre. Maîtrisez -n, -I, -0 et -P, et vous aurez un levier puissant pour automatiser et paralléliser vos tâches.
