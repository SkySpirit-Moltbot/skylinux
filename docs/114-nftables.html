Leçon 114 : nftables — Le pare-feu nouvelle génération

Si vous avez suivi la leçon sur iptables, vous connaissez déjà le pare-feu historique de Linux. Mais iptables a pris de l'âge. nftables est son remplaçant officiel, conçu pour corriger ses limitations et unifier la gestion des règles de pare-feu, de NAT et même du QoS dans une seule interface cohérente.

Pourquoi passer à nftables ?

iptables souffre de plusieurs problèmes hérités de son histoire : une syntaxe différente selon le protocole (iptables pour IPv4, ip6tables pour IPv6, ebtables pour Ethernet…), un système de tables et chaînes rigide, et des performances limitées sur les systèmes à nombreuses règles. nftables résout tout ça avec une syntaxe unifiée et un noyau unifié.

Installation

nftables est généralement préinstallé sur les distributions modernes. Vérifions sa présence :

which nft

Sur Ubuntu/Debian, installez-le si nécessaire :

sudo apt install nftables

Activer et gérer le service

nftables fonctionne avec systemd comme les autres services :

sudo systemctl enable nftables sudo systemctl start nftables sudo systemctl status nftables

La syntaxe de base

Contrairement à iptables où tout est morcelé (tables, chaînes, règles), nftables organise tout dans une structure logique lisible.

Listing des règles existantes

sudo nft list ruleset

Si c'est vide, tant mieux — c'est le reglas par défaut d'un système ouvert.

Créer une table

Une table contient des chaînes. Le type de table définit ce qu'elle filtre : filter pour le pare-feu, nat pour la translation d'adresses, route pour le routage.

sudo nft add table inet firewall

inet signifie que la table gère à la fois IPv4 et IPv6 avec la même syntaxe. Fini de manipuler iptables ET ip6tables séparément !

Créer des chaînes

Une chaîne définit un point d' interception :

  • input : trafic entrant
  • forward : trafic routé
  • output : trafic sortant
sudo nft add chain inet firewall input { type filter hook input priority 0 \; policy drop \; }

Cette chaîne input intercepte tout le trafic entrant, avec une politique par défaut de drop (tout refuser par défaut). Le priority 0 définit l'ordre d'évaluation.

Ajouter des règles

Autoriser le loopback

sudo nft add rule inet firewall input iif lo accept

iif lo = interface d'entrée loopback. Tout le trafic loopback est légitime.

Autoriser les connexions établies

sudo nft add rule inet firewall input ct state established,related accept

ct state established,related accepte les paquets qui appartiennent à une connexion déjà établie ou liée. Indispensable pour que les réponses aux connexions sortantes reviennent.

Autoriser SSH (port 22)

sudo nft add rule inet firewall input tcp dport 22 accept

Autoriser HTTP/HTTPS (ports 80 et 443)

sudo nft add rule inet firewall input tcp dport { 80, 443 } accept

Notez la syntaxe avec accolades pour plusieurs ports — bien plus lisible que les multiples règles iptables.

Autoriser ICMP (ping)

sudo nft add rule inet firewall input icmp type echo-request accept

Supprimer des règles

Chaque règle a un numéro de handle. Pour le trouver :

sudo nft -a list ruleset

L'option -a affiche les handles. Ensuite, supprimez par handle :

sudo nft delete rule inet firewall input handle 5

Voir et effacer tout

# Voir les règles sudo nft list ruleset # Effacer tout et recommencer sudo nft flush ruleset # Supprimer une table complète sudo nft delete table inet firewall

Exemple complet : pare-feu de base

Voici un script complet qui configure un pare-feu nftables standard pour un serveur :

#!/usr/sbin/nft -f # Flush existing rules flush ruleset # Table unique pour IPv4 + IPv6 table inet firewall { # Chaîne entrante — politique par défaut : drop chain input { type filter hook input priority 0; policy drop; # Loopback — toujours accepter iif lo accept # Connexions établies/liées ct state established,related accept # ICMP (ping) ip protocol icmp accept icmpv6 type { echo-request, echo-reply, destination-unreachable } accept # SSH — adaptez le port si nécessaire tcp dport 22 accept # HTTP/HTTPS tcp dport { 80, 443 } accept # Impossible ici : rejection propre (optionnel) # tcp reset # icmpv6 type port-unreachable } }

Sauvegardez ce script dans /etc/nftables.conf et activez-le au démarrage. Activez aussi la persistance :

sudo systemctl enable nftables

nftables et la persistance

nftables ne sauvegarde pas automatiquement les règles à chaque modification. Deux approches :

  • Script dans /etc/nftables.conf : nftables charge ce fichier au démarrage. Modifiez, puis sudo nft -f /etc/nftables.conf pour recharger.
  • Commandes interactives : utilisez sudo nft list ruleset > /etc/nftables.conf pour sauvegarder l'état courant.

Bonnes pratiques

  • Définissez toujours une politique par défaut stricte (drop ou accept selon vos besoins).
  • Placez les règles les plus fréquentes en premier pour optimiser les performances.
  • Testez vos règles dans un screen ou tmux pour ne pas vous enfermer dehors.
  • Conservez toujours un accès SSH depuis un autre réseau avant d'appliquer un pare-feu restrictif.
  • Utilisez inet pour gérer IPv4 et IPv6 dans la même table.

Vérifier le pare-feu actif

# Voir les règles avec handles sudo nft -a list ruleset # Vérifier les compteurs de paquets sudo nft -s list ruleset # Monitorer en temps réel sudo nft monitor

Conclusion

nftables est l'avenir du pare-feu Linux. Sa syntaxe unifiée, ses performances améliorées et ses fonctionnalités avancées (sets, maps, support natif IPv4+IPv6) en font le choix naturel pour tout nouveau serveur. Si vous administrez des machines en production, prenez le temps de migrer vos scripts iptables vers nftables — vous y gagnerez en maintenabilité et en clarté.
