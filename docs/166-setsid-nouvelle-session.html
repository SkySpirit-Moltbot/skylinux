setsid — Lancer un programme dans une nouvelle session

La commande setsid permet de démarrer un programme dans une nouvelle session Linux, complètement détaché du terminal qui l'a lancé. Contrairement à nohup qui protège uniquement contre les signaux de déconnexion, setsid crée une nouvelle session avec son propre groupe de processus, isolant le programme du terminal parent.

Comprendre les sessions sous Linux

Sous Linux, chaque terminal appartient à une session. Chaque session contient un ou plusieurs groupes de processus (process groups), eux-mêmes composés de processus individuels.

  • SID (Session ID) : l'identifiant de la session
  • PGID (Process Group ID) : l'identifiant du groupe de processus
  • PID (Process ID) : l'identifiant du processus lui-même

Quand vous lancez un programme depuis un terminal, il appartient à la même session que ce terminal. Si vous fermez le terminal, le signal SIGHUP est envoyé à tous les processus de la session, ce qui les arrête généralement.

Syntaxe de base

setsid commande [arguments]

Pour запустить un programme en arrière-plan dans une nouvelle session :

setsid monscript.sh
setsid firefox
setsid python3 mon programme.py

Exemples pratiques

Lancer un script en arrière-plan complet

# Lancer un script qui tourne indépendamment du terminal
setsid ./backup.sh
echo "Le script s'exécute même si vous fermez ce terminal"

Rediriger les sorties

Par défaut, setsid rattache stdin/stdout/stderr au terminal parent. Pour完全ement détacher :

setsid sh -c 'exec monscript.sh > /var/log/monscript.log 2>&1 &'

Lancer une application graphique

# Lancer Firefox dans une nouvelle session
setsid firefox
# Firefox ne se fermera pas si vous fermez le terminal

Combiner avec cd pour changer de répertoire

setsid sh -c 'cd /home/user/projets && ./serveur &'

Vérifier la session d'un processus

Pour voir le SID (Session ID) d'un processus :

ps -o pid,sid,cmd
# ou pour un processus spécifique
ps -o pid,sid,cmd -C firefox

Un processus détaché aura un SID différent de celui du terminal (visible avec ps ou tty).

Cas d'utilisation courants

  • Scripts de démarrage : lancer des services au démarrage du système
  • Applications graphiques : éviter qu'une application GUI ne se ferme quand le terminal meurt
  • Server daemon : créer des serveurs qui survivent à la déconnexion
  • Automatisation : scripts qui doivent tourner même si la session SSH se coupe

Exemple concret : serveur persistant

# Créer un serveur qui survit à la déconnexion
setsid python3 -m http.server 8080 > /var/log/serveur.log 2>&1 &
echo "Serveur démarré avec PID: $!"
disown

Conclusion

setsid est l'outil idéal quand vous avez besoin de détacher complètement un processus du terminal. Il crée une nouvelle session, ce qui offre une isolation plus forte que nohup. Pour une protection maximale, combinez-le avec la redirection des sorties et disown.
