146. systemctl — Fichiers Unit personnalisés (Avancé)

Dans la leçon 74, nous avons vu les bases de systemd et systemctl. Ici, nous allons apprendre à créer nos propres fichiers unit pour transformer n'importe quel script ou commande en vrai service géré par systemd.

📋 Anatomie d'un fichier Unit

Un fichier unit est un fichier texte au format INI situé dans :

  • /etc/systemd/system/ — pour les services système (root)
  • ~/.config/systemd/user/ — pour les services utilisateur

Structure minimale

[Unit] Description=Mon service After=network.target [Service] Type=simple ExecStart=/opt/monscript.sh Restart=on-failure RestartSec=5 [Install] WantedBy=multi-user.target

🔧 Types de services (Type=)

TypeDescriptionQuand l'utiliser
simpleLe processus principal est ExecStartCas par défaut, le plus courant
forkingLe processus père en spawn d'autres puis se termineDaemon classique style SysV
oneshotLe service s'exécute puis s'arrêteTâches de configuration ponctuelles
execSimilar à simple mais plus récent et propreRemplacement recommandé de simple
notifyLe service envoie un signal READY à systemdServices qui implémentent sd_notify
dbusLe service prend un nom sur D-BusServices D-Bus typiques

📝 Section [Unit] — Métadonnées

[Unit] Description=Backup automatique quotidien # Description lisible Documentation=https://mondomaine.com/docs # Doc optionnelle After=network-online.target mysql.service # Démarre APRÈS ces services Before=montage.service # Démarre AVANT ce service Wants=network-online.target # Veut ce service (sans obligation) Requires=network.target # Dépendance forte (échoue si absent)

⚙️ Section [Service] — Configuration d'exécution

Commandes de cycle de vie

[Service] ExecStart=/usr/bin/monservice start # Commande de démarrage ExecStop=/usr/bin/monservice stop # Commande d'arrêt (optionnel) ExecReload=/bin/kill -HUP $MAINPID # Commande de reload RestartForceExitStatus=100 # Redémarre sur ce code de sortie TimeoutStartSec=300 # Timeout démarrage (5 min) TimeoutStopSec=30 # Timeout arrêt

Variables d'environnement

[Service] Environment="PORT=8080" Environment="HOST=localhost" EnvironmentFile=/etc/monservice/env # Charger depuis fichier

Utilisateur et groupe

[Service] User=backupuser Group=backupgroup SupplementaryGroups=disk # Groupes additionnels WorkingDirectory=/home/backupuser

Gestion du redémarrage

ValeurComportement
noNe redémarre jamais (défaut)
on-successRedémarre si sortie normale (code 0)
on-failureRedémarre si sortie anormale
on-abnormalRedémarre sur signal ou timeout
alwaysRedémarre toujours

Limites système (ULimit)

[Service] LimitNOFILE=65536 # Nombre max de fichiers ouverts LimitNPROC=4096 # Nombre max de processus LimitCORE=infinity # Taille max core dump MemoryMax=512M # Limite mémoire CPUQuota=50% #Quota CPU

Accès réseau et sécurité

[Service] PrivateTmp=yes # /tmp isolé ProtectSystem=strict # Protection /usr /boot /etc ProtectHome=yes # Cache /home ReadOnlyPaths=/ # Rendre le FS lecture seule NoNewPrivileges=yes # Empêcher privilege escalation ProtectKernelTunables=yes # Protéger paramètres kernel ProtectKernelModules=yes # Protéger chargement modules ProtectControlGroups=yes # Protéger cgroups RestrictNamespaces=yes # Restreindre namespaces LockPersonality=yes # Bloquer changement architecture RestrictRealtime=yes # Pas de scheduling RT RestrictAddressFamilies=af_inet af_inet6 # IPv4/IPv6 seulement

🎯 Section [Install] — Activation

[Install] WantedBy=multi-user.target # Active au boot en mode texte # WantedBy=graphical.target # Active au boot en mode graphique # WantedBy=default.target # Active par défaut pour session utilisateur Alias=monservice # Nom alternatif Also=autreservice.service # Active/désactive aussi ces services

📦 Exemple complet : Service de backup

[Unit] Description=Backup automatique quotidien vers NAS Documentation=man:rsync(1) After=network-online.target Wants=network-online.target [Service] Type=oneshot User=backup Group=backup WorkingDirectory=/home/backup Environment=BACKUP_DEST=/mnt/nas/backup EnvironmentFile=/etc/backup/env ExecStart=/usr/local/bin/backup.sh ExecStartPost=/usr/bin/logger "Backup terminé avec succès" ExecStartPost=/usr/bin/notify-send "Backup" "Sauvegarde terminée" ExecStopPost=/usr/bin/logger "Backup interrompu" Restart=on-failure RestartSec=60 TimeoutStartSec=3600 TimeoutStopSec=300 # Sécurité NoNewPrivileges=yes ProtectSystem=strict ProtectHome=yes PrivateTmp=yes ReadOnlyPaths=/ ReadWritePaths=/home/backup /mnt/nas # Logging StandardOutput=journal StandardError=journal SyslogIdentifier=backup-service [Install] WantedBy=multi-user.target

🔄 Exemple : Service permanent (daemon)

[Unit] Description=Capteur de température IoT After=network.target [Service] Type=exec ExecStart=/usr/local/bin/temp-sensor --port 8888 Restart=always RestartSec=5 WatchdogSec=30 # Sécurité avancée NoNewPrivileges=yes ProtectSystem=strict ProtectHome=read-only PrivateTmp=yes PrivateDevices=yes ProtectKernelTunables=yes ProtectControlGroups=yes RestrictNamespaces=yes LockPersonality=yes MemoryDenyWriteExecute=no RestrictAddressFamilies=af_inet SystemCallFilter=@system-service SystemCallErrorNumber=EPERM # Ressources MemoryMax=100M CPUQuota=20% [Install] WantedBy=multi-user.target

⏰ Exemple : Service temporisé (timer-linked)

Créer d'abord le service (sans [Install]) puis un timer associé :

# /etc/systemd/system/nettoyage.service [Unit] Description=Nettoyage des fichiers temporaires After=local-fs.target [Service] Type=oneshot ExecStart=/usr/local/bin/cleanup-tmp.sh PrivateTmp=yes [Unit] Description=Nettoyage automatique tous les jours à 3h After=multi-user.target [Timer] OnCalendar=*-*-* 03:00:00 Persistent=true RandomizedDelaySec=3600 [Install] WantedBy=timers.target

🛠️ Commands essentielles pour gérer vos units

# Installer et activer sudo cp mon-service.service /etc/systemd/system/ sudo systemctl daemon-reload # Recharger après modification sudo systemctl enable --now mon-service # Activer + démarrer # Vérifications systemctl status mon-service systemctl cat mon-service # Voir le fichier unit systemctl edit mon-service # Éditer (crée override) systemctl show mon-service # Voir toute la config # Logs journalctl -u mon-service -f # Suivre les logs journalctl -u mon-service --since "1 hour ago" # Réinstaller après modification sudo systemctl daemon-reload sudo systemctl restart mon-service

🔒 Bonnes pratiques de sécurité

  • Principe du moindre privilège : créez un utilisateur dédié, pas root
  • ProtectSystem=strict : limitez l'accès au filesystem
  • NoNewPrivileges=yes : empêche l'élévation de privilèges
  • ReadOnlyPaths : rendez le système de fichiers lecture seule par défaut
  • SystemCallFilter : limitez les appels système autorisés
  • RestrictNamespaces : limitez l'utilisation des namespaces Linux
  • PrivateTmp : isoler /tmp et /var/tmp
  • WatchdogSec : redémarrer automatiquement si le service plante silencieusement

📊 Surveillance et debugging

# Voir les dépendances systemctl list-dependencies mon-service # Tester les limites systemd-run --scope -p MemoryMax=100M /chemin/commande # Mode "transient" (test sans fichier) systemd-run --scope /usr/bin/mon-daemon # Vérifier les erreurs de syntaxe systemd-analyze verify /etc/systemd/system/mon-service.service

🎓 Résumé

ConceptDescription
Type=simple, oneshot, forking, exec, notify, dbus
Restart=Stratégie de redémarrage automatique
WantedBy=Comment le service est activé
Environment=Variables d'environnement injectées
Protect*=yesOptions de sandboxing filesystem
SystemCallFilter=Limiter les appels système
WatchdogSec=Timeout de surveillance (health check)

Avec systemd, vous pouvez transformer n'importe quel script en service robuste, sécurisé et surveillé — bien plus professionnel qu'un simple nohup ou un screen.
