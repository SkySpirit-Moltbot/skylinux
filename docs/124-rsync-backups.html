Leçon 124 : rsync — Sauvegardes professionnelles

Dans la leçon 50, nous avons vu les bases de rsync. Ici, nous plongeons dans les stratégies de sauvegarde professionnelles, les scripts automatisés, et les techniques avancées pour protéger vos données.

Pourquoi rsync pour les sauvegardes ?

  • Incrémental par défaut : ne transfère que les fichiers modifiés
  • Compression à la volée : réduit la bande passante
  • Preserve les permissions : conserve propriétaires, timestamps et attributs étendus
  • Supporte SSH : chiffré de bout en bout
  • rapide et léger : idéal pour les sauvegardes fréquentes

Stratégies de sauvegarde

1. Sauvegarde locale complète

rsync -avh --progress /home/david/documents/ /media/backup/documents/
  • -a : mode archivage (preserve permissions, ownership, timestamps, symlinks)
  • -v : mode verbeux
  • -h : affichage lisible (human readable)
  • --progress : affiche la progression

2. Sauvegarde avec lien dur (stratégie 3-2-1)

La stratégie 3-2-1 : 3 copies, 2 supports différents, 1 copie hors site.

# Première sauvegarde complète rsync -av /home/david/documents/ /backup/jour1/documents/ # Sauvegarde du lendemain (ne transfère que les changements) rsync -av --delete /home/david/documents/ /backup/jour2/documents/ # Utiliser --link-dest pour créer des copies efficientes rsync -av --link-dest=/backup/jour1/documents/ \ /home/david/documents/ \ /backup/jour2/documents/

L'option --link-dest crée des liens durs vers les fichiers inchangés du répertoire de référence, économisant énormément d'espace disque tout en permettant d'accéder à chaque instant comme s'il s'agissait d'une sauvegarde complète.

3. Sauvegarde distante via SSH

# Syntaxe SSH rsync -avz -e ssh /home/david/documents/ user@serveur:/backup/documents/ # Avec port SSH personnalisé rsync -avz -e "ssh -p 2222" /home/david/documents/ user@serveur:/backup/ # Spécifier une clé SSH rsync -avz -e "ssh -i ~/.ssh/backup_key" /home/david/documents/ user@serveur:/backup/

4. Sauvegarde en mode daemon (rsyncd)

Configuration du serveur rsyncd sur /etc/rsyncd.conf :

[backup] comment = Module de sauvegarde path = /backup read only = no auth users = backupuser secrets file = /etc/rsyncd.secrets
# Lancement du daemon sudo systemctl enable rsync sudo systemctl start rsync # Connexion depuis le client rsync -av /home/david/documents/ rsync://backupuser@monserveur/backup/

Exclusions et filtres

# Exclure des patterns rsync -av --exclude='*.tmp' --exclude='.cache/' /home/david/ /backup/ # Exclure depuis un fichier rsync -av --exclude-from='/home/david/exclusions.txt' /home/david/ /backup/ # Inclure uniquement certains fichiers rsync -av --include='*.pdf' --include='*.docx' --exclude='*' /home/david/ /backup/ # Utiliser un fichier de filter rsync -avF /home/david/ /backup/

Contenu typique de exclusions.txt :

- .cache/ - .thumbnails/ - *.tmp - Downloads/ - node_modules/

Script de sauvegarde automatisé

#!/bin/bash # === Configuration === SRC="/home/david/documents" DEST="/media/backup/documents" LOG="/var/log/backup.log" RETENTION=7 # === Fonctions === log() { echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" | tee -a "$LOG" } # === Vérifications === [ ! -d "$SRC" ] && { log "ERREUR: Source $SRC introuvable"; exit 1; } [ ! -d "$DEST" ] && { log "ERREUR: Destination $DEST introuvable"; exit 1; } # === Sauvegarde avec lien dur === log "Début de la sauvegarde de $SRC vers $DEST" rsync -avh \ --delete \ --link-dest=/backup/precedent \ --exclude='.cache' \ --exclude='*.tmp' \ --log-file="$LOG" \ "$SRC/" "$DEST/current/" 2>&1 if [ $? -eq 0 ]; then log "Sauvegarde terminée avec succès" # Rotation : déplacer current vers precedent rm -rf /backup/precedent mv /backup/actuel /backup/precedent ln -s "$DEST/current" /backup/actuel # Nettoyage des anciennes sauvegardes (> $RETENTION jours) find /backup -maxdepth 1 -type d -mtime +$RETENTION -exec rm -rf {} \; log "Rotation terminée" else log "ERREUR: La sauvegarde a échoué" exit 1 fi

Options avancées utiles

OptionDescription
--dry-run / -nSimulation sans modification (indispensable pour tester)
--deleteSupprime les fichiers dans dest s'ils n'existent plus dans src
--partialConserve les fichiers partiellement transférés (reprise)
--bwlimit=5000Limite la bande passante à 5 Mo/s
--checksumCompare par checksum (plus lent, plus sûr)
--backupBackup des fichiers modifiés/supprimés
--updateNe transfère que si la source est plus récente
-zCompresse pendant le transfert

Reprise après interruption

# Reprendre un transfert interrompu rsync -avP --partial \ -e ssh \ /home/david/large_file.tar.gz \ user@serveur:/backup/ # -P = --partial --progress (raccourci courant)

Sauvegarde système complète

# Exclure les fichiers volatiles et les systèmes de fichiers virtuels rsync -aAXv \ --exclude={"/dev/*","/proc/*","/sys/*","/tmp/*","/run/*","/mnt/*","/media/*","/lost+found"} \ / \ /backup/system/
  • -A : préserve les ACL
  • -X : préserve les attributs étendus (SELinux context)

Bonnes pratiques

  • Toujours tester avec --dry-run avant d'exécuter
  • Vérifier les logs après chaque sauvegarde
  • Tester la restauration régulièrement
  • Utiliser SSH pour les sauvegardes distantes (chiffrement)
  • Planifier avec cron : 0 2 * * * /home/david/scripts/backup.sh
  • Monitorer l'espace disque剩余空间

À retenir : rsync est l'outil de référence pour les sauvegardes Linux grâce à son efficacité incrémentale. Combinez-le avec SSH pour des sauvegardes sécurisées et avec --link-dest pour des instantanés (snapshots) économes en espace.
