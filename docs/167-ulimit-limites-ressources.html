ulimit — Gérer les limites des ressources système

La commande ulimit permet de consulter et de modifier les limites des ressources disponibles pour le shell courant et ses processus fils. C'est un outil essentiel pour contrôler la consommation mémoire, le nombre de fichiers ouverts, ou la taille des fichiers créés par un utilisateur ou un script.

Pourquoi limiter les ressources ?

Sans limites, un processus mal configuré ou bogué pourrait :

  • Ouvrir un nombre infini de fichiers (fd leaks)
  • Consommer toute la mémoire RAM disponible
  • Créer des fichiers immenses qui saturent le disque
  • Générer des fourches infinies (fork bombs)

ulimit permet de prévenir ces problèmes en imposant des quotas par shell ou par utilisateur.

Syntaxe de base

ulimit [options] [limite]

Consulter les limites actuelles

# Voir toutes les limites douces (soft limits)
ulimit -a
# Exemple de sortie :
core file size (blocks, -c) 0
data seg size (kbytes, -d) unlimited
max nice (egid, -g) 0
file size (blocks, -f) unlimited
open files (-n) 1024
pipe size (512 bytes, -p) 8
max locked memory (kbytes, -l) 65536
max memory size (kbytes, -m) unlimited
processes (-u) 4096
stack size (kbytes, -s) 8192
cpu time (seconds, -t) unlimited
max user processes (-x) 4096
virtual memory (kbytes, -v) unlimited

Exemples pratiques

Limiter le nombre de fichiers ouverts

C'est l'une des limites les plus utilisées, notamment pour les serveurs web :

# Voir la limite actuelle
ulimit -n
# 1024
# Augmenter temporairement pour ce shell
ulimit -n 4096
# Vérifier
ulimit -n
# 4096

Limiter la taille des fichiers créés

# Limiter à 10 Mo (20 blocs de 512 Ko)
ulimit -f 20480
# Tester
dd if=/dev/zero of=test.bin bs=1M count=15
# File size limit exceeded

Limiter la mémoire d'un script

# Limiter la mémoire virtuelle à 512 Mo
ulimit -v 524288
# Lancer le script
python3 mon_script_lourd.py

Limiter le nombre de processus

# Empêcher les fork bombs
ulimit -u 100
# Si un script tente de créer trop de processus
# bash: fork: Resource temporarily unavailable

Soft limits vs Hard limits

Linux distingue deux types de limites :

  • Soft limit : la limite par défaut, que l'utilisateur peut modifier librement (dans la plage autorisée)
  • Hard limit : le maximum absolu, que seul root peut modifier
# Voir les limites souples et dures
ulimit -Sn # Soft limit pour fichiers ouverts
ulimit -Hn # Hard limit pour fichiers ouverts
# Définir les deux en même temps
ulimit -Hn 8192 # Hard limit = 8192
ulimit -Sn 4096 # Soft limit = 4096

Limites permanentes avec /etc/security/limits.conf

Les modifications avec ulimit ne sont valables que pour le shell courant. Pour des limites permanentes, on configure /etc/security/limits.conf :

# Syntaxe :
#
# Exemples :
# Limiter l'utilisateur 'www-data' à 2048 fichiers ouverts
www-data soft nofile 2048
www-data hard nofile 4096
# Limiter tous les utilisateurs à 100 processus max
* soft nproc 100
* hard nproc 200
# Ajouter un message pour les forks bombs
@students hard nproc 50

Voir les limites système pour un processus

Pour connaître les limites d'un processus déjà lancé :

# Via le système de fichiers
cat /proc/PID/limits
# Exemple pour nginx
ps aux | grep nginx
# root 1234 ... nginx: master process
cat /proc/1234/limits

Exemple : protéger contre une fork bomb

# 1. Configurer une limite permanente pour l'utilisateur
sudo nano /etc/security/limits.conf
# Ajouter :
# monuser soft nproc 100
# monuser hard nproc 200
# 2. Redémarrer la session ou se reconnecter
# 3. Vérifier
ulimit -u
# 100

Conclusion

ulimit est un outil puissant pour protéger le système contre les processus malveillants ou défectueux. Les limites temporaires avec ulimit sont pratiques pour les tests, tandis que /etc/security/limits.conf est recommandé pour une configuration permanente et robuste.
