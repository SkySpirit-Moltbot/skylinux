taskset — Gérer l'affinité CPU des processus

Sous Linux, chaque processus peut être lié à un ou plusieurs cœurs CPU. Par défaut, un processus peut s'exécuter sur n'importe quel cœur disponible. La commande taskset permet de contrôler finement cette affinité, ce qui est particulièrement utile pour optimiser les performances ou isoler des charges de travail.

Afficher le nombre de CPU disponibles

Avant de jouer avec l'affinité, connaissez votre matériel :

nproc

Ou encore :

ls /sys/devices/system/cpu/

Cela liste les CPUs disponibles (cpu0, cpu1, cpu2…). Sur un système 4 cœurs, vous aurez cpu0 à cpu3.

Voir l'affinité actuelle d'un processus

Chaque processus possède un masque de bits (bitmask) indiquant sur quels CPU il peut s'exécuter. Pour le voir :

taskset -p PID

Exemple concret :

taskset -p 1234

Résultat possible :

pid 1234's current affinity mask: ff

Le masque ff (en hexadécimal) signifie que le processus peut tourner sur les 8 premiers CPU (ff en hexa = 11111111 en binaire = 8 bits = 8 CPU).

Démarrer un processus avec une affinité précise

Avec un masque binaire

Le format le plus courant utilise un masque hexadécimal. Chaque bit correspond à un CPU :

MasqueCPU autorisésDescription
01CPU 0 uniquement1 CPU
02CPU 1 uniquement1 CPU
03CPU 0 et 12 CPUs
07CPU 0, 1 et 23 CPUs
0fCPU 0 à 34 CPUs
ffCPU 0 à 78 CPUs
ffffffffTous les CPU 0-3132 CPUs

Pour lancer un processus sur le CPU 0 uniquement :

taskset -c 01 -- gnome-calculator

Ou en utilisant le format classique (non compact) :

taskset 01 -- mon_script.sh

Avec la liste CPU (format compact)

Utilisez le flag -c pour une syntaxe plus lisible :

taskset -c 0,2,3 -- mon_processus

Cela lance le processus sur les CPU 0, 2 et 3 uniquement.

taskset -c 0-3 -- mon_processus

Cela lance le processus sur les CPU 0 à 3 (notation par plage).

Modifier l'affinité d'un processus en cours

Vous pouvez changer l'affinité d'un processus déjà démarré :

taskset -p 03 PID

Cela restreint le processus PID aux CPU 0 et 1.

Ou avec le format compact :

taskset -cp 0,1 PID

Exemples pratiques

1. Lancer un script bash sur un cœur dédié

taskset -c 3 ./mon_script_lourd.sh

Le script s'exécutera uniquement sur le CPU 3, isolant les autres cœurs pour le système.

2. Vérifier et modifier l'affinité avec top

Dans top, appuyez sur f puis ajoutez la colonne Last used CPU. Vous verrez sur quel CPU chaque processus s'exécute. Combinez avec taskset pour affiner.

3. Scripts de performance

Pour un benchmark ou un calcul intensif qu'on veut contrôler :

# Lancer 4 instances d'un worker, chacune sur un CPU différent taskset -c 0 ./worker.sh & taskset -c 1 ./worker.sh & taskset -c 2 ./worker.sh & taskset -c 3 ./worker.sh &

4. Affinité CPU dans un script Python

#!/usr/bin/env python3 import os # Obtenir le masque CPU actuel mask = os.sched_getaffinity(0) print(f"CPU disponibles: {mask}") # Restreindre aux CPU 0 et 1 os.sched_setaffinity(0, {0, 1}) print("Affinité modifiée: CPU 0 et 1 uniquement")

Cas d'utilisation courants

  • Optimisation de performance : Certaines applications sensibles à la latence (trading haute fréquence, audio temps réel) bénéficient d'un CPU dédié pour éviter les migrations entre cœurs.
  • Isolation de charge : Isoler un processus lourd sur des CPU spécifiques pour préserver la réactivité du système sur les autres cœurs.
  • Conteneurs et virtualisation : Pinner des conteneurs Docker ou des VMs sur des CPU dédiés.
  • Tests et benchmarks : Mesurer les performances sur un nombre limité de cœurs pour des comparaisons précises.

Combiner avec d'autres outils

Avec nice et ionice

Ces outils contrôlent différents aspects de l'ordonnancement. Ensemble, ils offrent un contrôle complet :

nice -n 10 ionice -c 2 -n 7 taskset -c 2 ./processus_lourd.sh

Cela exécute le processus avec une priorité réduite (nice), une classe d'I/O différée (ionice), et uniquement sur le CPU 2.

Attention aux systèmes NUMA

Sur les serveurs avec plusieurs nœuds NUMA (plusieurs sockets CPU), méfiez-vous de l'allocation mémoire. Un processus épinglé sur un CPU d'un nœud NUMA peut ressentir une latence accrue si sa mémoire est sur un autre nœud. Vérifiez avec numactl --hardware.

numactl --cpunodebind=0 --membind=0 ./mon_programme

Résumé des options principales

OptionDescription
taskset -p PIDAfficher l'affinité actuelle d'un processus
taskset -p MASQUE PIDModifier l'affinité d'un processus existant
taskset -c MASQUE CMDLancer une commande avec une affinité donnée (format compact)
taskset -c 0-3 CMDFormat par plage de CPUs
taskset -c 0,2,4 CMDFormat liste de CPUs

taskset est un outil puissant pour optimiser et contrôler l'exécution des processus sous Linux. Bien utilisé, il permet d'améliorer significativement les performances et la prévisibilité des charges de travail.
