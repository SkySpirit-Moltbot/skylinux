Leçon 117 : script — Enregistrer une session terminal

Vous avez déjà été dans cette situation : vous effectuez une série de commandes complexes, et vous auriez bien voulu garder une trace de tout ce que vous avez tapé et affiché. C'est exactement ce que fait la commande script. Elle enregistre tout ce qui s'affiche dans votre terminal dans un fichier, que vous pouvez ensuite relire, partager ou archiver.

1. L'enregistrement de base

La syntaxe est très simple :

script ma_session.txt

Dès cet instant, tout ce que vous tapez et tout ce qui s'affiche est enregistré dans ma_session.txt. Pour arrêter l'enregistrement, tapez exit ou appuyez sur Ctrl+D.

$ script session.log
Script started, file is session.log
$ ls -la /var/log
$ df -h
$ uptime
$ exit
Script done, file is session.log

2. Lire le fichier d'enregistrement

Le fichier généré contient à la fois les commandes tapées et leur sortie. Vous pouvez le consulter directement avec cat :

cat session.log

Le fichier inclut des caractères de contrôle (backspaces, retours chariot). Si vous voulez un fichier texte propre, utilisez l'option -c (ou --log-close) combinée avec scriptreplay.

3. Enregistrement avec horodatage

Pour garder une trace du moment où chaque commande a été exécutée, utilisez l'option --timing :

script --timing=timing.txt session.log

Cette commande crée deux fichiers :

  • session.log : le contenu de la session
  • timing.txt : les délais entre chaque action

Vous pouvez ensuite rejouer la session avec scriptreplay :

scriptreplay --timing=timing.txt --log-out=session.log

La session est rejouée exactement comme vous l'avez vécue, avec les mêmes délais.

4. Enregistrement silencieux

Par défaut, script affiche aussi dans le terminal tout en enregistrant. Si vous voulez un enregistrement transparent (sans double affichage), utilisez l'option -q (quiet) :

script -q session.log

5. Mode append (ajouter au fichier)

Vous pouvez ajouter une nouvelle session à un fichier existant avec l'option -a :

script -a session.log

C'est utile pour documenter des sessions de maintenance sur plusieurs jours.

6. Enregistrement dans un format brut

L'option -t (timing) est l'équivalent historique de --timing. Combinez-la avec scriptreplay pour rejouer :

script -t 2>timing.txt session.log

Cette syntaxe redirige les informations de timing vers timing.txt et le contenu vers session.log.

7. Cas d'utilisation pratiques

Documenter une installation complexe

script install_serveur.log
# Tapez vos commandes d'installation...
exit

Vous avez maintenant une trace complète de votre installation, horodatée, que vous pouvez conserver ou partager.

Capturer une session de debug

script debug_reseau.log
$ ip addr show
$ ping -c 4 8.8.8.8
$ traceroute google.com
$ exit

Formation et tutoriels

Enregistrez une session pour montrer à un collègue ou un étudiant les étapes exactes d'une procédure. Rejouez-la avec scriptreplay pour une démonstration en direct.

8. Récapitulatif des options

OptionDescription
script fichier.logEnregistrer dans fichier.log
-aAjouter au fichier existant
-qMode silencieux (pas d'affichage)
--timing=fichier.txtEnregistrer les délais
-c COMMANDEExécuter une commande sans shell interactif
scriptreplayRejouer une session enregistrée

9. Exécuter une commande sans shell interactif

Si vous voulez juste capturer la sortie d'une commande sans ouvrir un shell complet, utilisez -c :

script -c "make && make install" install.log

C'est pratique pour capturer une compilation sans que l'utilisateur interagisse.

Exercice

Essayez ces manipulations pour vous familiariser avec script :

  • Démarrez un enregistrement avec script test.log
  • Tapez quelques commandes (ls, date, whoami)
  • Quittez avec exit
  • Affichez le contenu de test.log avec cat
  • Recommencez avec l'option -a pour ajouter au même fichier
  • Utilisez script --timing=timing.txt sortie.log puis scriptreplay

La commande script est un outil simple mais puissant pour garder une trace de votre travail. Que ce soit pour de la documentation, du dépannage, de la formation ou simplement pour ne rien oublier de ce que vous avez fait, elle trouve sa place dans la boîte à outils de tout administrateur Linux.
