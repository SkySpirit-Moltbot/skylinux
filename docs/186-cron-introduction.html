186. Cron — Automatiser des tâches sous Linux

Vous voulez qu'une commande s'exécute automatiquement tous les jours à 3h du matin, ou chaque lundi à midi ? cron est l'outil de planification de tâches le plus utilisé sous Linux. Il permet d'automatiser presque tout : sauvegardes, nettoyage, monitoring, rapports...

Comment fonctionne cron ?

cron est un daemon (service en arrière-plan) qui vérifie toutes les minutes s'il doit exécuter des tâches planifiées. Chaque utilisateur dispose de son propre fichier de tâches appelé crontab (cron table).

Les principaux composants :

  • cron daemon (crond) — le service qui tourne en arrière-plan
  • crontab — le fichier contenant les tâches planifiées d'un utilisateur
  • crontab -e — la commande pour éditer sa crontab
  • /etc/cron.*/ — répertoires contenant des scripts exécutés automatiquement

Le format d'une ligne cron

Chaque ligne de crontab contient 5 champs de temps suivis de la commande :

┌───────────── minute (0 - 59) │ ┌───────────── heure (0 - 23) │ │ ┌───────────── jour (1 - 31) │ │ │ ┌───────────── mois (1 - 12) │ │ │ │ ┌───────────── jour de semaine (0 - 7, 0 et 7 = dimanche) │ │ │ │ │ * * * * * commande

Exemples de planification

ExpressionSignification
* * * * *Chaque minute
0 * * * *Chaque heure (à la minute 0)
0 0 * * *Chaque jour à minuit
0 3 * * *Chaque jour à 3h du matin
0 9 * * 1Chaque lundi à 9h
30 14 1 * *Le 1er du mois à 14h30
0 8 * * 1-5Chaque jour de semaine à 8h
*/5 * * * *Toutes les 5 minutes
0 */2 * * *Toutes les 2 heures
0 0 1,15 * *Les 1er et 15 de chaque mois à minuit

Modifier sa crontab

Ouvrir l'éditeur

crontab -e

La première fois, cron vous demande de choisir un éditeur.，推荐 nano pour les débutants.

Ajouter une tâche

Dans l'éditeur, ajoutez une ligne comme celle-ci :

# Exemple : sauvegarde quotidienne à 3h du matin 0 3 * * * rsync -a /home/ /backup/home-$(date +\%Y\%m\%d)/

Important : le signe % a une signification spéciale dans crontab. Utilisez \% pour obtenir un vrai signe pourcent dans la commande.

Lister ses tâches

crontab -l

Supprimer toute sa crontab

crontab -r

L'option -i demande une confirmation : crontab -ri

Les répertoires cron prédéfinis

Si vous ne voulez pas apprendre le format cron complet, des scripts dans ces répertoires sont exécutés automatiquement :

RépertoireFréquence d'exécution
/etc/cron.hourly/Toutes les heures
/etc/cron.daily/Une fois par jour
/etc/cron.weekly/Une fois par semaine
/etc/cron.monthly/Une fois par mois

Pour ajouter une tâche quotidienne, placez-y un script exécutable :

# Rendre le script exécutable sudo cp mon-script.sh /etc/cron.daily/ sudo chmod +x /etc/cron.daily/mon-script.sh

Atelier pratique : automatiser une sauvegarde

Étape 1 — Créer le script de sauvegarde

mkdir -p ~/bin cat > ~/bin/backup.sh << 'EOF' #!/bin/bash # Sauvegarde du répertoire personnel vers /backup SOURCE=/home/$USER DEST=/backup DATE=$(date +%Y%m%d) mkdir -p "$DEST" rsync -a --delete "$SOURCE/" "$DEST/backup-$DATE/" echo "Sauvegarde terminée : $DATE" | tee "$DEST/log.txt" EOF chmod +x ~/bin/backup.sh

Étape 2 — Planifier avec cron

crontab -e

Ajoutez cette ligne :

# Sauvegarde chaque jour à 3h du matin 0 3 * * * /home/votre-user/bin/backup.sh >> /home/votre-user/backup.log 2>&1

>> /home/votre-user/backup.log 2>&1 redirige la sortie standard et les erreurs vers un fichier de log.

Étape 3 — Vérifier

# Vérifier que cron fonctionne sudo systemctl status cron # Voir les exécutions dans les logs grep CRON /var/log/syslog

Atelier pratique : nettoyer les fichiers temporaires

Supprimer automatiquement les fichiers de /tmp plus anciens que 7 jours :

# Éditer la crontab crontab -e
# Chaque dimanche à 2h du matin 0 2 * * 0 find /tmp -type f -atime +7 -delete 2>/dev/null

Atelier pratique : surveiller l'espace disque

Recevoir un e-mail si l'espace disque est bas (nécessite un serveur mail configuré) :

# Vérifier l'espace tous les jours à 8h 0 8 * * * df -h | awk 'NR>1 {print $5 " " $6}' | while read usage point; do pct=${usage%\%} if [ "$pct" -gt 85 ]; then echo "Attention : $point à $usage" | mail -s "Alerte disque" admin@example.com fi done

Utiliser des variables d'environnement dans la crontab

Vous pouvez définir des variables au début de votre crontab :

# Définir le PATH PATH=/usr/local/bin:/usr/bin:/bin # Définir l'éditeur EDITOR=nano # Définir des variables personnalisées MES_BACKUPS=/backup # Maintenant les commandes utilisent ces variables 0 3 * * * $MES_BACKUPS/script.sh

Spécifier l'utilisateur

Dans /etc/crontab et les fichiers de /etc/cron.d/, le format inclut un champ utilisateur :

# Format /etc/crontab : # minute heure jour mois jour_semaine utilisateur commande 0 3 * * * root rsync -a /home/ /backup/

Le répertoire /etc/cron.d/

Pour les tâches système, placez un fichier dans /etc/cron.d/ :

sudo nano /etc/cron.d/nettoyage
# Nettoyer les logs chaque semaine SHELL=/bin/bash PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin 0 4 * * 0 root find /var/log -name "*.log" -mtime +30 -delete

Protéger sa crontab

Empêcher un utilisateur de'utiliser cron

# Interdire cron à un utilisateur sudo echo "toto" >> /etc/cron.deny # Vérifier crontab -u toto -l # Affiche : crontab: you (toto) are not allowed to use this program

N'autoriser que certains utilisateurs

# Supprimer /etc/cron.deny s'il existe # Créer /etc/cron.allow avec les utilisateurs autorisés sudo echo "admin" | sudo tee /etc/cron.allow sudo chmod 644 /etc/cron.allow

Journaliser les exécutions

Par défaut, cron enregistre les exécutions dans /var/log/syslog (sur Debian/Ubuntu) :

grep CRON /var/log/syslog | tail -20

Pour un log dédié à cron, modifiez /etc/rsyslog.conf :

cron.* /var/log/cron.log
sudo systemctl restart rsyslog

Erreurs courantes

La commande ne trouve pas le programme

Utilisez le chemin absolu des commandes :

# Incorrect (peut échouer) * * * * * rsync -a /home/ /backup/ # Correct * * * * * /usr/bin/rsync -a /home/ /backup/

Ou définissez le PATH en haut de la crontab :

PATH=/usr/local/bin:/usr/bin:/bin:/usr/local/sbin:/usr/sbin:/sbin

Les variables d'environnement ne sont pas chargées

cron exécute les commandes dans un environnement minimal. Si votre script utilise ~ ou des variables comme $HOME, spécifiez-les explicitement :

HOME=/home/votre-user 0 3 * * * $HOME/bin/backup.sh

Caractères spéciaux non échappés

Le signe % dans une commande cron est interpreté comme un retour à la ligne. Échappez-le :

# Incorrect : le % sera interprété 0 3 * * * echo $(date) > /tmp/log.txt # Correct : le % est échappé 0 3 * * * echo $(date +\%Y-\%m-\%d) > /tmp/log.txt

Bonnes pratiques

  • Utilisez toujours des chemins absolus dans les commandes cron
  • Redirigez la sortie vers un fichier de log (>> fichier.log 2>&1)
  • Définissez le PATH en haut de votre crontab pour éviter les erreurs "command not found"
  • Pour les tâches système, préférez les fichiers dans /etc/cron.d/ plutôt que modifier /etc/crontab
  • Testez votre commande manuellement avant de la mettre dans cron
  • Surveillez les logs régulièrement pour détecter les échecs
  • Préférez les scripts dans /etc/cron.hourly/, cron.daily/, etc. pour les tâches simples
