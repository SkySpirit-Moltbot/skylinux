Leçon 72 : chmod et chown — Permissions avancées

1. Introduction

Après avoir vu les bases des permissions dans la leçon 3, explorons maintenant les aspects avancés : la notation octale détaillée, les permissions spéciales (SUID, SGID, Sticky Bit), et l'utilisation approfondie de chown et chgrp.

Un mauvais chmod peut rendre un fichier inexploitable ou, pire, ouvrir des failles de sécurité. Toujours vérifier avant d'appliquer sur des fichiers critiques.

2. Rappels : notation symbolique vs octale

Chaque fichier possède trois triplets de permissions :

TripletSignification
u (user)Propriétaire du fichier
g (group)Groupe propriétaire
o (other)Tous les autres utilisateurs
a (all)Tout le monde (u + g + o)

Notation symbolique

chmod u+x fichier # ajoute le droit execute au proprietaire chmod g-w fichier # retire le droit ecriture au groupe chmod o=r fichier # met lecture seule pour les autres chmod a+rw fichier # lecture + ecriture pour tout le monde chmod u+rx,g+rx,o+r fichier

Notation octale

Chaque permission a une valeur numérique :

PermissionValeur
r (lecture)4
w (ecriture)2
x (execution)1
- (aucun)0

On additionne les valeurs pour chaque triplet :

OctalSymboliqueDescription
7rwxLecture + ecriture + execution
6rw-Lecture + ecriture
5r-xLecture + execution
4r--Lecture seule
0---Aucune permission
# Exemples pratiques chmod 755 fichier # rwxr-xr-x (proprietaire: tout, groupe: rx, autres: rx) chmod 644 fichier # rw-r--r-- (proprietaire: rw, groupe: r, autres: r) chmod 700 fichier # rwx------ (proprietaire: tout, groupe: rien, autres: rien) chmod 775 fichier # rwxrwxr-x (tout le monde lit/execute, seuls others n'ecrivent pas) chmod 600 fichier # rw------- (seul le proprietaire lit et ecrit)

3. Permissions speciales

Il existe trois permissions speciales qui s'ajoutent devant le triplet :

BitOctalSur fichierSur repertoire
SUID4Execute avec les droits du proprietaire-
SGID2Execute avec les droits du groupeLes fichiers heritent du groupe
Sticky Bit1-Seul le proprietaire peut supprimer

SUID (Set User ID)

Quand un fichier a le SUID positionne, il s'execute avec l'UID de son proprietaire, pas celui de l'utilisateur qui le lance. L'exemple classique est /usr/bin/passwd :

ls -l /usr/bin/passwd # -rwsr-xr-x 1 root root ... /usr/bin/passwd # ^ le 's' au lieu de 'x' signifie SUID actif
# Activer le SUID sur un script chmod 4755 /chemin/vers/script # 4 = SUID # ou en notation symbolique chmod u+s /chemin/vers/script # Retirer le SUID chmod u-s /chemin/vers/script

Le SUID est un risque de securite si tu l'appliques a un shell ou un script qui permet l'acces a root. Ne l'utilise que sur des programmes西亚 specifiques et bloques.

SGID (Set Group ID)

Sur un fichier, il fonctionne comme le SUID mais pour le groupe. Sur un repertoire, tous les fichiers crees heritent automatiquement du groupe du repertoire :

# Activer SGID sur un repertoire (partage de groupe) chmod 2775 /var/projet # Les fichiers crees ici appartiendront automatiquement au groupe du repertoire # Notation symbolique chmod g+s /var/projet # Verifier ls -ld /var/projet # drwxrwsr-x ... /var/projet # ^ le 's' au lieu de 'x' pour le groupe = SGID actif

Sticky Bit

Sur un repertoire, seul le proprietaire d'un fichier peut le supprimer (meme si les autres ont les droits d'ecriture sur le repertoire). L'exemple classique est /tmp :

ls -ld /tmp # drwxrwxrwt ... /tmp # ^ le 't' = sticky bit actif # Activer le sticky bit sur un repertoire chmod 1777 /var/shared # ou chmod +t /var/shared # Notation symbolique pour retirer chmod -t /var/shared

5. chown — Changer le proprietaire

Syntaxe de base

sudo chown [options] proprietaire[:groupe] fichier

Exemples

# Changer le proprietaire sudo chown alice fichier.txt # Changer proprietaire ET groupe sudo chown alice:developpeurs fichier.txt # Changer uniquement le groupe (deux facons equivalentes) sudo chown :developpeurs fichier.txt sudo chgrp developpeurs fichier.txt # Changer le groupe sans toucher au proprietaire sudo chgrp nouveau_groupe fichier.txt # Appliquer recursivement a un repertoire sudo chown -R alice:developpeurs /home/alice/projet # Ne changer que le proprietaire d'un lien symbolique (pas la cible) sudo chown -h alice lien_symbolique # Verifier apres modification ls -l fichier.txt

6. Copier et transferer les permissions

Copier les permissions d'un fichier vers un autre

# Copier les permissions de fichierA vers fichierB chmod --reference=fichierA fichierB # Appliquer a tout un repertoire chmod --reference=fichierA -R repertoire/

Copier proprietaire et groupe d'un fichier vers un autre

# Copier le proprietaire:groupe de fichierA vers fichierB sudo chown --reference=fichierA fichierB # Appliquer recursivement sur un repertoire sudo chown -R --reference=fichierA repertoire/

7. Masques de permissions (umask)

Le umask definit quelles permissions sont retirees par defaut lors de la creation d'un fichier ou repertoire. C'est un masque : les bits a 1 sont supprimes.

# Voir le umask actuel umask # En notation symbolique umask -S # u=rwx,g=rwx,o=rx # Definir un umask pour la session umask 022 # Retire 022 -> 755 par defaut pour les repertoires umask 077 # Retire 077 -> 700 par defaut (tres restrictif)

Pour rendre le umask permanent, ajoute-le dans ~/.bashrc ou /etc/profile.

8. Cas pratiques

Securiser un script pour qu'il s'execute avec les droits root

# 1. Creer le script sudo nano /usr/local/bin/mon-script.sh # 2. Rendre executable et activer SUID root sudo chmod 750 /usr/local/bin/mon-script.sh sudo chown root:root /usr/local/bin/mon-script.sh sudo chmod u+s /usr/local/bin/mon-script.sh # Verifier ls -l /usr/local/bin/mon-script.sh # -rwsr-x--- 1 root root ... /usr/local/bin/mon-script.sh

Creer un repertoire partage entre plusieurs utilisateurs

# 1. Creer le groupe sudo groupadd projet_equipe # 2. Ajouter les utilisateurs sudo usermod -aG projet_equipe alice sudo usermod -aG projet_equipe bob # 3. Creer le repertoire et appliquer les droits sudo mkdir /var/projet sudo chown root:projet_equipe /var/projet sudo chmod 2775 /var/projet # Resultat : # - SGID = tous les fichiers heritent du groupe projet_equipe # - Sticky bit = chacun peut ecrire mais ne peut pas supprimer les fichiers des autres

9. Visualiser rapidement les permissions

# Voir les permissions detaillees stat fichier.txt # File: fichier.txt # Access: (0644/-rw-r--r--) Uid: (1000/alice) Gid: (1000/alice) # Notation numerique uniquement stat -c "%a %n" fichier.txt # 644 fichier.txt # Notation symbolique stat -c "%A %n" fichier.txt # rw-r--r-- fichier.txt # Tous les fichiers d'un repertoire avec permissions ls -la /var/projet

10. Exercices pratiques

1. **Notation** — Quelle est la signification de `chmod 2755 fichier` ? Explique chaque chiffre.

2. **SUID** — Trouve les fichiers avec SUID active sur ton systeme avec find / -perm /4000 2>/dev/null.

3. **Repertoire partage** — Cree un groupe equipe_test, ajoute ton utilisateur, puis cree un repertoire /tmp/test_partage avec SGID et sticky bit.

4. **umask** — Quelle sera la permission par defaut d'un nouveau repertoire si le umask est `027` ? Calcule et verifie avec umask 027 && mkdir test_umask && ls -ld test_umask.

5. **Securite** — Explique pourquoi chmod 777 / serait catastrophique. Cite au moins trois raisons.
