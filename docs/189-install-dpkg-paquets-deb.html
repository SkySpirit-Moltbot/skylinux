189. dpkg, apt et install — Installer des logiciels hors ligne

Vous êtes sur un système sans internet ou avez téléchargé un paquet Debian (.deb) manuellement ? La commande dpkg est l'outil de base pour installer, supprimer et gérer des paquets sous Debian et ses dérivées (Ubuntu, Linux Mint…). Dans cette leçon, vous apprendrez à installer des logiciels depuis des fichiers .deb, à résoudre les dépendances manquantes, et à nettoyer votre système.

Comprendre le format .deb

Un fichier .deb est un paquet Debian. Il contient le logiciel à installer ainsi que des métadonnées (nom, version, dépendances, scripts de pré/post-installation).

Deux outils principaux coexistent :

  • dpkg — l'outil bas niveau. Il installe directement un fichier .deb, mais ne télécharge pas les dépendances.
  • apt — l'outil haut niveau. Il utilise dpkg en interne, mais gère automatiquement les dépendances depuis les dépôts.

dpkg — Installation directe d'un fichier .deb

Installer un paquet (.deb)

sudo dpkg -i paquet.deb

Exemple concret :

sudo dpkg -i code_1.75.0-1678414834_amd64.deb

-i (ou --install) installe le paquet depuis le fichier .deb donné.

Vérifier si un paquet est installé

dpkg -l | grep nom_du_paquet dpkg -l firefox

Résultat typique :

ii firefox 121.0+build2-0ubuntu0.22.04.1 amd64 Maroon FireFox web browser

La première colonne indique l'état :

ÉtatSignification
iiCorrectement installé
rcFichiers de configuration seuls restants (paquet supprimé)
unPaquet connu mais non installé
pnPaquet installé puis supprimé
iuInstallé mais dans un état incohérent (dépendances manquantes)

Lister tous les paquets installés

dpkg -l

Ou filtrer avec grep :

dpkg -l | grep "^ii" | less

Voir les fichiers d'un paquet installé

dpkg -L firefox

Affiche tous les fichiers installés par le paquet Firefox.

Identifier le paquet qui a installé un fichier

dpkg -S /usr/bin/firefox firefox: /usr/bin/firefox

Très utile quand vous trouvez un exécutable et voulez savoir quel paquet l'a installé.

Supprimer un paquet (conserver les fichiers de configuration)

sudo dpkg -r nom_du_paquet sudo dpkg -r firefox

-r (ou --remove) supprime le paquet mais conserve les fichiers de configuration dans /etc.

Supprimer un paquet (avec fichiers de configuration)

sudo dpkg -P nom_du_paquet sudo dpkg -P firefox

-P (ou --purge) supprime complètement le paquet, y compris ses fichiers de configuration.

Résoudre les dépendances manquantes

Le point faible de dpkg -i : si un paquet a des dépendances non satisfaites, l'installation échoue. Exemple :

sudo dpkg -i virtualbox.deb Sélection du paquet virtualbox précédemment désélectionné. (Lecture de la base de données... 163120 fichiers et répertoires installés.) Préparation du dépaquetage de 'virtualbox.deb'... Dépaquetage de virtualbox (7.0.10-158379~Ubuntu~jammy) ... dpkg: des problèmes de dépendances empéchent la configuration de virtualbox : virtualbox dépend de libqt5opengl5 (>= 5.0.2) ; mais : Le paquet libqt5opengl5 n'est pas installé. virtualbox dépend de libpython3.10 (>= 3.10.0) ; mais : Le paquet libpython3.10 n'est pas installé.

La solution : dpkg --configure -a

Après avoir installé les dépendances manuellement, lancez :

sudo dpkg --configure -a

Cela reprend la configuration de tous les paquets laissés dans un état incohérent.

La solution complète : gdebi

L'outil gdebi télécharge et installe automatiquement les dépendances d'un fichier .deb :

# Installer gdebi (si pas déjà présent) sudo apt install gdebi # Installer un .deb avec ses dépendances sudo gdebi virtualbox.deb

Identifier les dépendances d'un paquet

# Voir les dépendances d'un paquet installé dpkg -s virtualbox | grep Depends

Ou sans l'installer, directement depuis un fichier .deb :

dpkg-deb -I virtualbox.deb Depends

dpkg-deb — Inspecter et manipuler les fichiers .deb

dpkg-deb est l'outil pour inspecter l'intérieur d'un fichier .deb sans l'installer.

Afficher les informations d'un paquet

dpkg-deb -I virtualbox.deb

Affiche le nom, version, architecture, taille installée, dépendances, description.

Lister le contenu d'un fichier .deb

dpkg-deb -c virtualbox.deb

Montre tous les fichiers qui seraient installés par ce paquet.

Extraire le contenu d'un .deb

# Créer un répertoire de travail mkdir extrait && cd extrait # Extraire le contenu du .deb dpkg-deb -x virtualbox.deb virtualbox-contenu # Explorer ls virtualbox-contenu/ # usr/ DEBIAN/

Extraire uniquement les fichiers de contrôle (métadonnées)

dpkg-deb -e virtualbox.deb DEBIAN-control

Crée un répertoire DEBIAN/ contenant les scripts de contrôle et métadonnées.

Atelier pratique : installer un logiciel hors ligne

Scénario : installer VS Code sur un PC sans internet

Vous avez téléchargé code_1.75.0-1678414834_amd64.deb depuis un autre ordinateur.

Étape 1 — Vérifier le fichier

# Vérifier que le fichier existe et est un .deb valide file code_1.75.0-1678414834_amd64.deb # code_1.75.0-1678414834_amd64.deb: Debian binary package (format 2.0) # Afficher les informations du paquet dpkg-deb -I code_1.75.0-1678414834_amd64.deb

Étape 2 — Lister les fichiers qui seront installés

dpkg-deb -c code_1.75.0-1678414834_amd64.deb | head -20

Étape 3 — Vérifier les dépendances

dpkg-deb -I code_1.75.0-1678414834_amd64.deb | grep Depends # Depends: gtk-3-0, libnotify4, libnss3, libxkbfile1, ...

Étape 4 — Vérifier si les dépendances sont satisfaites

# Essayer l'installation directe sudo dpkg -i code_1.75.0-1678414834_amd64.deb 2>&1 | head -30

Si des dépendances manquent, elles seront listées.

Étape 5 — Corriger les dépendances avec apt

Si votre système a accès à internet mais vous préférez installer le .deb :

# Forcer apt à corriger les dépendances après dpkg sudo apt install -f

apt install -f corrige les dépendances brisées en installant ce qui manque depuis les dépôts.

Étape 6 — Vérifier l'installation

# Confirmer que le paquet est installé dpkg -l | grep code # Vérifier que l'exécutable est accessible which code # /usr/bin/code

Atelier pratique : créer un mini dépôt local

Si vous devez installer le même logiciel sur plusieurs machines sans internet, créez un dépôt local.

Structurer le dépôt

# Créer la structure du dépôt mkdir -p /opt/mon-depot cp ~/Téléchargements/*.deb /opt/mon-depot/ # Entrer dans le répertoire cd /opt/mon-depot

Générer les index du dépôt (sans serveur web)

# Installer dpkg-dev pour créer les index sudo apt install dpkg-dev # Générer le fichier Packages.gz dpkg-scanpackages . /dev/null | gzip -9c > Packages.gz # Vérifier ls -lh Packages.gz

Utiliser le dépôt local

# Ajouter le dépôt local à apt # Sur chaque machine, créer un fichier de configuration : sudo nano /etc/apt/sources.list.d/local-depot.list

Contenu du fichier :

deb [trusted=yes] file:///opt/mon-depot/ ./
# Mettre à jour la liste des paquets sudo apt update # Installer un logiciel depuis le dépôt local sudo apt install code

Partager le dépôt via un serveur web ou clé USB

Si vous avez un serveur web accessible sur le réseau local :

# Copier le dépôt sur le serveur web scp -r /opt/mon-depot user@mon-serveur:/var/www/html/depot/ # Sur les machines clientes, utiliser l'URL http : # deb http://adresse-ip-serveur/depot/ ./

Atelier pratique : nettoyer les restes de paquets supprimés

Trouver les paquets dans un état incohérent

dpkg --audit

Ou lister les paquets dont l'état commence par iU ou ir :

dpkg -l | grep -E "^[iu][^n]"

Reconfigurer un paquet problématique

# Reconfigurer un paquet spécifique sudo dpkg --configure nom_du_paquet # Reconfigurer tous les paquets en attente sudo dpkg --configure -a

Supprimer les fichiers de configuration orphelins

# Lister les paquets avec uniquement des fichiers de config restants dpkg -l | grep "^rc" # Purger tous les restes de configuration dpkg -l | grep "^rc" | awk '{print $2}' | xargs sudo dpkg -P

Vérifier l'espace disque avant/après nettoyage

df -h /

Atelier pratique : extraire et réempaqueter un .deb

Utile pour modifier un paquet sans l'installer.

Extraire le contenu

# Créer un répertoire de travail mkdir ~/deb-travail && cd ~/deb-travail # Extraire le contenu dpkg-deb -x /chemin/vers/paquet.deb extraction # Extraire les métadonnées dpkg-deb -e /chemin/vers/paquet.deb extraction/DEBIAN

Modifier le contenu (exemple : changer un fichier de config)

# Modifier un fichier dans extraction/ nano ~/deb-travail/extraction/etc/ma-config.conf # Vérifier les modifications diff -u /chemin/vers/paquet.deb.extracted/etc/ma-config.conf ~/deb-travail/extraction/etc/ma-config.conf

Réempaqueter en .deb

# Réempaqueter dpkg-deb --build ~/deb-travail/extraction mv ~/deb-travail/extraction.deb ~/deb-travail/paquet-modifie.deb # Vérifier le nouveau paquet dpkg-deb -I ~/deb-travail/paquet-modifie.deb

Comprendre les scripts de contrôle d'un .deb

Un fichier .deb contient un répertoire DEBIAN/ avec des scripts qui s'exécutent à différentes étapes :

FichierQuandÀ quoi ça sert
preinstAvant l'installationArrêter un service, créer un utilisateur
postinstAprès l'installationConfigurer, redémarrer un service
prermAvant la suppressionArrêter le service proprement
postrmAprès la suppressionNettoyer les fichiers, supprimer des utilisateurs

Vous pouvez examiner ces scripts dans le répertoire DEBIAN/ d'un .deb extrait.

Bonnes pratiques

  • Toujours vérifier le contenu d'un .deb avec dpkg-deb -I avant de l'installer
  • Utiliser dpkg -l | grep nom pour vérifier si un logiciel est déjà installé avant d'installer un .deb
  • Si dpkg -i échoue à cause de dépendances, lancez ensuite sudo apt install -f pour corriger
  • Sur un système sans internet, installez d'abord les dépendances manuellement, puis le .deb
  • Utilisez gdebi pour une installation plus simple des fichiers .deb (il gère les dépendances)
  • Purgez régulièrement les restes de configuration avec dpkg -l | grep "^rc"
  • Ne supprimez jamais le répertoire /var/lib/dpkg — il contient la base de données de tous les paquets installés
  • Pour multiplier les installations sur plusieurs machines, créez un dépôt local avec dpkg-scanpackages
