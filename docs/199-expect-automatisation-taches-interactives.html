Leçon 199 : expect — Automatiser les tâches interactives

Quand vous devez automatiser des programmes qui posent des questions (mot de passe, confirmation, menu interactif), les scripts bash classiques ne suffisent pas. expect permet de dialoguer automatiquement avec n'importe quel programme interactif en simulant des frappes et en répondant aux invites.

Installation

expect n'est généralement pas installé par défaut :

# Debian/Ubuntu
sudo apt install expect
# Fedora/RHEL
sudo dnf install expect
# Arch Linux
sudo pacman -S expect

Principe de base

Un script expect fonctionne ainsi :

  1. On lance un programme (spawn)
  2. On attend une chaîne de caractères précise (expect)
  3. On envoie une réponse (send)
  4. On termine (interact ou exit)

Premier exemple : ssh sans taper le mot de passe

#!/usr/bin/expect -f
# Définir les variables
set USER "david"
set HOST "serveur.example.com"
set PASS "monmotdepasse"
# Lancer ssh
spawn ssh $USER@$HOST
# Attendre l'invite de mot de passe
expect "password:"
# Envoyer le mot de passe
send "$PASS\r"
# Passer la main à l'utilisateur
interact

Les commandes fondamentales

spawn — Lancer un programme

spawn démarre le processus que vous voulez automatiser :

spawn ssh dbserv03
spawn ftp serveurftp.com
spawn passwd # changer son mot de passe
spawn scp fichier.txt user@host:/chemin/

expect — Attendre une chaîne

expect met le script en pause jusqu'à ce que le programme affiche un texte précis :

expect "password:"
expect "Are you sure (yes/no)?"
expect "Login:"
expect "># " # invite de commande d'un équipement réseau

On peut enchaîner plusieurs expect pour gérer différentes réponses :

expect {
"yes/no" { send "yes\r"; exp_continue }
"password:" { send "$PASS\r" }
}

send — Envoyer du texte

send envoie les caractères comme si vous les tapiez au clavier. N'oubliez pas \r (retour chariot) pour valider :

send "monmotdepasse\r"
send "yes\r"
send "show running-config\r"
send "\r" # juste appuyer sur Entrée

send_user — Afficher pour l'humain

send_user affiche du texte dans le terminal (sans l'envoyer au programme) :

send_user "Connexion en cours à $HOST...\n"
send_user "Transfert terminé avec succès.\n"

interact vs expect_before / expect_after

  • interact : rend la main à l'utilisateur humain (il peut taper lui-même)
  • expect_before : intercepte automatiquement certaines chaînes avant les autres expect
  • expect_after : intercepte automatiquement après un expect

Exemple complet : automatiser un transfert FTP

#!/usr/bin/expect -f
set FTP_HOST "ftp.example.com"
set FTP_USER "admin"
set FTP_PASS "secretpass"
set LOCAL_FILE "rapport.pdf"
set REMOTE_DIR "/uploads"
send_user "Connexion FTP à $FTP_HOST...\n"
spawn ftp $FTP_HOST
expect {
"Name" { send "$FTP_USER\r" }
timeout { send_user "Timeout: FTP ne répond pas\n"; exit 1 }
}
expect "Password:"
send "$FTP_PASS\r"
expect "ftp>"
send "binary\r"
expect "ftp>"
send "cd $REMOTE_DIR\r"
expect "ftp>"
send "put $LOCAL_FILE\r"
expect "ftp>"
send "bye\r"
send_user "Transfert FTP terminé.\n"

Gestion des timeout

Par défaut, expect attend indéfiniment. Utilisez set timeout pour limiter :

set timeout 30 # timeout de 30 secondes
spawn ssh serveur
expect {
"password:" { send "$PASS\r" }
timeout { send_user "Trop long, abandon\n"; exit 1 }
}

Variables dans expect

Comme en Tcl (sur lequel repose expect), on accède aux variables avec $nom et on peut utiliser l'interpolation dans les chaînes entre guillemets :

set nom_utilisateur "alice"
set hote "serveur-linux"
spawn ssh $nom_utilisateur@$hote
expect "password:"
send "$PASS\r"
send_user "Connecté à $hote\n"

Combiner expect dans un script bash

On peut intégrer un bloc expect dans un script bash avec expect -c pour les cas simples :

#!/bin/bash
HOST="serveur.example.com"
USER="admin"
PASS="motdepasse123"
expect -c "
spawn ssh $USER@$HOST
expect {
\"yes/no\" { send \"yes\r\"; exp_continue }
\"password:\" { send \"$PASS\r\" }
}
expect eof
"

Exemple avec un équipement réseau (switch Cisco)

expect est très utilisé pour automatiser l'administration d'équipements réseau :

#!/usr/bin/expect -f
set IP "192.168.1.1"
set USER "admin"
set PASS "cisco123"
spawn telnet $IP
expect "Username:"
send "$USER\r"
expect "Password:"
send "$PASS\r"
expect ">"
send "enable\r"
expect "Password:"
send "enablepass\r"
expect "#"
send "show interfaces status\r"
expect "#"
send "exit\r"
interact

La commande expect_out (capturer la sortie)

Pour extraire du texte de la sortie d'un programme, on utilise expect_out :

spawn hostnamectl
expect "Static hostname:"
set hostname $expect_out(1,string)
send_user "Le hostname est : $hostname\n"

Bonnes pratiques

  • timeout approprié : réglez-le avant chaque bloc expect critique
  • exp_continue : permet de rester dans un expect après une correspondance pour attendre autre chose
  • send_user pour le feedback : n'envoyez jamais de mot de passe en clair dans un send_user visible
  • Protégez vos scripts : un script expect contient le mot de passe en clair — utilisez chmod 600 et envisagez l'authentification par clé SSH à la place
  • Testez avec spawn + expect + exit avant d'utiliser interact pour débugger

Conclusion

expect est l'outil idéal pour automatiser tout ce qui nécessite une interaction humaine : connexions SSH/FTP/Telnet, changement de mots de passe, dialogues de confirmation, administration d'équipements réseau. Combiné à un script bash, il permet de construire des procédures d'automatisation puissantes sans avoir besoin d'API ou de clés SSH.
