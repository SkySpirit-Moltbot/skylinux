190. which — Localiser une commande sur le système

Sous Linux, des centaines de commandes coexistent sur le système. Comment savoir si python pointe vers le Python 2 ou Python 3 ? Où se trouve réellement grep ? La commande which répond à ces questions en un clin d'œil.

Principe fondamental

which cherche une commande dans les répertoires listés dans la variable d'environnement PATH et retourne le premier chemin absolu qui serait exécuté si vous tapiez cette commande.

$ which python
/usr/bin/python3

Utilisation de base

Trouver une seule commande

$ which ls
/usr/bin/ls

Trouver plusieurs commandes d'un coup

$ which grep sed awk
/usr/bin/grep /usr/bin/sed /usr/bin/awk

Vérifier si une commande existe

Si la commande n'existe pas, which ne retourne rien (code de retour = 1) :

$ which vim /usr/bin/vim
$ which monprogramme # (rien — commande introuvable)
$ echo $? 1

Options utiles

OptionDescription
-aAffiche toutes les occurrences dans le PATH (pas seulement la première)
-sMode silencieux : pas de sortie, juste un code de retour (0 = trouvé, 1 = pas trouvé)
-iIgnore les alias et cherche le binaire réel

Trouver toutes les versions d'une commande

$ which -a python
/usr/bin/python3 ~/.local/bin/python

Vérifier sans rien afficher

Pratique dans un script pour tester la présence d'un outil :

if which curl > /dev/null 2>&1; then echo "curl est disponible" else echo "curl est absent" fi

Ignorer un alias

$ alias ll='ls -la' $ which ll /usr/bin/ll # (n'existe pas) $ which -i ll /bin/ls # le vrai binaire derrière l'alias

La variable PATH expliquée

which cherche uniquement dans les répertoires de $PATH. Pour voir votre PATH actuel :

$ echo $PATH /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

Les répertoires sont parcourus de gauche à droite. La première correspondance trouvée est celle qui sera exécutée.

Cas concrets

Débugger une commande qui "ne fonctionne pas"

# Pourquoi ma commande personnalisée n'est pas trouvée ? $ which monscript # (rien) # Vérifier si le répertoire est dans le PATH $ echo $PATH | tr ':' '\n' | grep -q /home/user/bin || echo "manquant" # Ajouter au PATH si nécessaire $ export PATH="/home/user/bin:$PATH"

Vérifier quel interpréteur est utilisé

$ which python python2 python3
/usr/bin/python3 # python2 n'existe peut-être pas sur votre système

Dans un script d'installation

# Vérifier les dépendances avant installation for cmd in gcc make git wget curl; do if ! which $cmd > /dev/null 2>&1; then echo "ERREUR: $cmd est requis mais non trouvé" exit 1 fi done echo "Toutes les dépendances sont présentes"

which vs whereis vs type

CommandeCe qu'elle faitExemple de sortie
whichCherche dans le PATH, retourne le premier exécutable/usr/bin/grep
whereisCherche binaire, source et page mangrep: /usr/bin/grep /usr/share/man/man1/grep.1.gz
typeDécrit le type (binaire, alias, fonction, builtin)grep is /usr/bin/grep
$ type ls ls is an alias for 'ls --color=auto' $ which ls /usr/bin/ls $ whereis ls ls: /usr/bin/ls /usr/share/man/man1/ls.1.gz

Exercices

  1. Trouvez le chemin complet de bash, ssh et tar.
  2. Utilisez which -a pour voir toutes les occurrences de python sur votre système.
  3. Créez un script qui vérifie la présence de git, docker et curl et affiche un message adapté pour chacun.
  4. Comparez les sorties de which, whereis et type pour une commande de votre choix.
  5. Ajoutez un répertoire temporaire à votre PATH et vérifiez avec which qu'une commande dans ce répertoire est优先 trouvée.
