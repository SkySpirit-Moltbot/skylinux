Leçon 200 : kill — Envoyer des signaux aux processus

Sous Linux, tout processus peut recevoir des signaux (signals) — des messages spéciaux qui demandent au processus de faire quelque chose : s'arrêter, redémarrer, se recharger, etc. La commande kill est l'outil principal pour envoyer ces signaux depuis le terminal.

Principe fondamental : les signaux

Un signal est un mécanisme de communication inter-processus. Quand vous envoyez un signal à un programme, le noyau interrompt ce que le programme est en train de faire et lui transmet le signal. Le programme peut alors :

  • Ignorer le signal (certain signaux ne peuvent pas être ignorés)
  • Intercepter le signal et exécuter une action personnalisée
  • Mourir silencieusement
  • Créer un fichier core dump avant de mourir

La commande kill — Envoyer un signal

Par défaut, kill envoie le signal SIGTERM (signal 15) au processus cible :

kill 1234 # envoyer SIGTERM au processus PID 1234
kill -15 1234 # équivalent explicite
kill -TERM 1234 # notation par nom

Si le processus ne s'arrête pas, on peut utiliser SIGKILL (signal 9), qui est impossible à ignorer :

kill -9 1234 # forcer l'arrêt immédiat (SIGKILL)
kill -KILL 1234 # notation par nom, equivalent

Trouver le bon PID

Avant d'envoyer un signal, il faut identifier le PID du processus. Plusieurs méthodes :

pgrep — Rechercher par nom

pgrep firefox # affiche le(s) PID de firefox
pgrep -f "python" # recherche dans la ligne de commande complete
pgrep -u david # processus appartenants a l'utilisateur david

pidof — PID d'un programme précis

pidof firefox # PID du processus firefox principal
pidof -s nginx # un seul PID (le plus ancien)

ps + grep

ps aux | grep nginx
ps -ef | grep "[c]hromium" # le crochet evite de capturer le grep lui-meme

Envoyer un signal à plusieurs processus

On peut cibler plusieurs processus avec kill et une commande qui renvoie plusieurs PID :

# Arrêter tous les processus python
kill $(pgrep python)
# Forcer l'arrêt de tous les chromium
kill -9 $(pidof chromium)
# Arrêter tous les processus d'un utilisateur
kill -15 -1 # -1 = tous les processus du processus courant (sauf init)

Signal et scripts : capturer un signal

Dans un script bash, on peut capturer un signal pour réagir proprement (par exemple, nettoyer des fichiers temporaires avant de s'arrêter) :

#!/bin/bash
TEMP_DIR="/tmp/mon_script_$$"
mkdir "$TEMP_DIR"
# Fonction de nettoyage
cleanup() {
echo "Nettoyage en cours..."
rm -rf "$TEMP_DIR"
exit 0
}
# Capturer SIGTERM et SIGINT
trap cleanup SIGTERM SIGINT
echo "Script en cours (PID: $$). Appuyez sur Ctrl+C ou envoyez SIGTERM pour arrêter."
# Boucle infinie pour garder le script actif
while true; do
sleep 1
done

SIGHUP : recharger la configuration

Quand un daemon (service en arrière-plan) reçoit SIGHUP, il relit généralement sa configuration sans redémarrer. C'est le comportement standard pour nginx, apache, bind, etc. :

# Relire la configuration de nginx sans redémarrer
kill -HUP $(pidof nginx)
# Équivalent avec systemctl
systemctl reload nginx

Suspendre et reprendre (SIGSTOP / SIGCONT)

SIGSTOP met le processus en pause (comme Ctrl+Z) et SIGCONT le reprend :

# Suspendre un processus
kill -STOP 1234
# Le reprendre
kill -CONT 1234

Cela permet de mettre un processus de côté temporairement, par exemple pour libérer un terminal ou de la mémoire.

La famille kill : killall et pkill

killall — Par nom de programme

killall firefox # envoyer SIGTERM a tous les firefox
killall -9 chromium # forcer l'arret de tous les chromium
killall -u david # tuer tous les processus de l'utilisateur david
killall -i nginx # mode interactif (demande confirmation)

pkill — Recherche + kill

pkill firefox # arreter firefox par son nom
pkill -f "python script.py" # arreter un processus par sa ligne de commande
pkill -u david # tuer tous les processus de david
pkill -x nginx # tuer uniquement si le nom correspond exactement
pkill -o firefox # arreter uniquement le plus ancien
pkill -n firefox # arreter uniquement le plus recent

Vérifier que le signal a été reçu

Après l'envoi d'un signal, vérifiez que le processus est bien terminé :

kill -15 1234
sleep 2
ps -p 1234 && echo "Le processus existe encore" || echo "Processus arrete"
# Si le processus persiste malgré SIGTERM
kill -9 1234

Signaux et numéros — La liste complète

Pour voir tous les signaux disponibles sur votre système :

kill -l # liste tous les signaux (nom et numéro)
kill -l 9 # afficher le nom du signal numero 9 (KILL)
kill -l SIGTERM # afficher le numero du signal SIGTERM (15)

Bonnes pratiques

  • Toujours essayer SIGTERM d'abord : c'est propre, le processus peut nettoyer ses fichiers et fermer proprement ses connexions
  • Utiliser SIGKILL (-9) uniquement en dernier recours : le processus n'a aucune chance de nettoyer, vous risquez de perdre des données
  • Utilisez trap dans vos scripts pour capturer les signaux et nettoyer proprement
  • kill -1 (SIGHUP) est le standard pour demander à un daemon de relire sa configuration — pas besoin de le redémarrer
  • Attention avec kill -9 sur un processus qui écrit sur le disque : corruption possible de fichiers
  • killall et pkill sont pratiques mais utilisez-les avec prudence — vérifiez bien le nom avant d'exécuter

Conclusion

kill est bien plus qu'un simple "tueur" de processus. C'est un outil de communication avec les programmes : leur demander de s'arrêter proprement, forcer leur arrêt, leur demander de relire leur configuration, ou même les suspendre temporairement. Connaître les signaux et leur utilisation est indispensable pour administrer efficacement un système Linux.
