Leçon 111 : iptables — Le pare-feu Linux en ligne de commande

Quand vous avez besoin de contrôler précisément le trafic réseau de votre machine Linux, iptables est l'outil de référence. Si vous avez suivi la leçon sur UFW, sachez que UFW est en réalité un frontal qui utilise iptables en coulisses. Comprendre iptables vous donne un contrôle bien plus fin sur votre pare-feu. Dans cette leçon, vous apprendrez à manipuler directement les règles de pare-feu sous Linux.

Qu'est-ce que iptables ?

iptables est le logiciel de pare-feu intégré au noyau Linux. Il fonctionne avec le concept de chaînes (chains) et de règles (rules). Chaque règle définit quelle action prendre quand un paquet réseau correspond à certains critères.

La structure de base est :

table → chaîne → règle → action

Les tables principales

iptables organise ses règles dans des tables selon le type de traitement :

TableUtilisation
filterLa plus utilisée. Contrôle l'autorisation ou le blocage des paquets.
natTraduction d'adresses réseau (PAT, redirection de ports).
mangleModification avancée des paquets (QoS, marquage).
rawTraçabilité des connexions, désactiver le suivi d'état.

Les chaînes intégrées

Chaque table contient des chaînes (chains), qui sont des points de contrôle dans le parcours des paquets :

ChaîneContexte
INPUTPaquets destinés à la machine locale
OUTPUTPaquets émis par la machine locale
FORWARDPaquets routés à travers la machine (mode routeur)
PREROUTINGAvant le routage, NAT entrant
POSTROUTINGAprès le routage, NAT sortant

Pour un ordinateur classique, les chaînes les plus utilisées sont INPUT et OUTPUT.

Les actions (targets)

Quand un paquet correspond à une règle, une action est appliquée :

ActionEffet
ACCEPTAutoriser le paquet
DROPIgnorer le paquet (sans réponse, plus discret)
REJECTRefuser le paquet (avec réponse ICMP d'erreur)
LOGJournaliser le paquet sans le bloquer
MASQUERADENAT sortant (remplace l'IP source par celle de l'interface)
DNATNAT entrant (redirection de port)

Syntaxe de base

Afficher les règles

# Afficher les règles de la table filter (défaut)
sudo iptables -L -n -v
# Explication des options :
# -L : Lister les règles
# -n : Afficher les IPs/numéros de ports (pas de résolution DNS)
# -v : Mode détaillé (bytes, packets, interfaces...)
# Afficher avec numéros de ligne (pour suppression)
sudo iptables -L -n --line-numbers
# Afficher une chaîne spécifique
sudo iptables -L INPUT -n -v

Autoriser le trafic

# Autoriser le trafic SSH (port 22) en entrée
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
# Explication :
# -A INPUT : Ajouter (-A) à la chaîne INPUT
# -p tcp : Protocole TCP
# --dport 22 : Port destination 22
# -j ACCEPT : Sauter (-j) vers ACCEPT (action)
# Autoriser HTTP (port 80) et HTTPS (port 443)
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

Bloquer le trafic

# Refuser tout le trafic SSH depuis une IP spécifique
sudo iptables -A INPUT -p tcp -s 192.168.1.100 --dport 22 -j DROP
# Bloquer une IP entière (整个 réseau 10.0.0.0/8)
sudo iptables -A INPUT -s 10.0.0.0/8 -j DROP

Supprimer une règle

# Supprimer une règle par son numéro de ligne
sudo iptables -D INPUT 5
# Supprimer par critères (ici : bloquer SSH depuis 192.168.1.100)
sudo iptables -D INPUT -p tcp -s 192.168.1.100 --dport 22 -j DROP

Politiques par défaut

Chaque chaîne a une politique par défaut (policy) qui s'applique quand aucune règle ne correspond :

# Définir la politique par défaut de INPUT sur DROP (sécurisé)
sudo iptables -P INPUT DROP
# Garder OUTPUT ouvert par défaut
sudo iptables -P OUTPUT ACCEPT

Attention : si vous êtes connecté en SSH et que vous réglez INPUT DROP sans avoir autorisé SSH avant, vous perdrez votre connexion ! L'ordre des règles compte.

Le suivi de connexion (stateful firewall)

Un des points forts d'iptables est le suivi d'état des connexions. Vous pouvez autoriser les réponses aux connexions sortantes :

# Autoriser les paquets liés à une connexion déjà établie
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
# Autoriser les nouvelles connexions SSH uniquement
sudo iptables -A INPUT -p tcp --dport 22 -m state --state NEW -j ACCEPT

États possibles :

ÉtatDescription
NEWNouvelle connexion
ESTABLISHEDConnexion déjà établie
RELATEDConnexion liée (ex:数据传输 FTP)
INVALIDPaquet invalide ou inconnu

Exemples pratiques complets

Configuration SSH sécurisée

# 1. Autoriser les connexions SSH existantes
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
# 2. Autoriser SSH (nouvelles connexions)
sudo iptables -A INPUT -p tcp --dport 22 -m state --state NEW -j ACCEPT
# 3. Tout le reste en entrée : DROP
sudo iptables -P INPUT DROP

Serveur web basique

# Trafic établi
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
# HTTP et HTTPS
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
# SSH
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

Bloquer les ping (ICMP)

# Bloquer les ping entrants (ne répond plus au ping)
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j DROP
# Autoriser les ping entrants (répond au ping)
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT

Redirection de ports (NAT)

Activation du routage

# Activer le routage IP (requis pour NAT)
sudo sysctl -w net.ipv4.ip_forward=1
# Rendre permanent (éditer /etc/sysctl.conf) :
echo "net.ipv4.ip_forward = 1" | sudo tee -a /etc/sysctl.conf

Redirection de port (DNAT)

# Rediriger le port 8080 vers un serveur interne 192.168.1.50:80
sudo iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.50:80
# Explanation :
# -t nat : Table NAT
# PREROUTING : Chaîne PREROUTING (avant routage)

Masquaderade (partage de connexion)

# Masquerade : les clients du réseau local sortent avec l'IP du routeur
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

Journalisation avec LOG

# Logger les paquets bloqués avant de les drop
sudo iptables -A INPUT -j LOG --log-prefix "IPTables-DROP: " --log-level 4
# Voir les logs iptables
sudo tail -f /var/log/kern.log | grep "IPTables"

Sauvegarder et restaurer les règles

Sauvegarder

# Debian/Ubuntu : sauvegarder dans un fichier
sudo iptables-save > /etc/iptables/rules.v4
# Format de sauvegarde (compatible avec iptables-restore)
sudo iptables-save

Restaurer

# Restaurer depuis le fichier
sudo iptables-restore < /etc/iptables/rules.v4

Réinitialiser toutes les règles

# Effacer toutes les règles de la table filter
sudo iptables -F
# Réinitialiser les compteurs
sudo iptables -Z
# Remettre la politique par défaut à ACCEPT
sudo iptables -P INPUT ACCEPT
sudo iptables -P FORWARD ACCEPT
sudo iptables -P OUTPUT ACCEPT

Commandes utiles pour débugger

# Vérifier si une règle existe
sudo iptables -C INPUT -p tcp --dport 22 -j ACCEPT
# Lister avec compteurs (看清楚 les hits)
sudo iptables -L -n -v --line-numbers
# Voir les règles NAT
sudo iptables -t nat -L -n -v

Résumé des commandes principales

CommandeDescription
iptables -L -n -vAfficher les règles avec détails
iptables -A INPUT -p tcp --dport X -j ACCEPTAutoriser un port TCP
iptables -A INPUT -s IP -j DROPBloquer une IP
iptables -D INPUT NUMSupprimer une règle par numéro
iptables -P INPUT DROPPolitique par défaut : tout bloquer
iptables -FEffacer toutes les règles
iptables-save > fichierSauvegarder les règles
iptables-restore < fichierRestaurer les règles

Conclusion

iptables est l'outil de référence pour contrôler le trafic réseau sous Linux. Bien que UFW offre une interface plus simple (voir leçon 37), iptables reste indispensable pour comprendre le fonctionnement réel du pare-feu et effectuer des configurations avancées comme le NAT, la redirection de ports, ou le filtrage très précis. Prenez le temps de tester dans un environnement sécurisé — une erreur de pare-feu peut vous bloquer l'accès à votre propre machine.
