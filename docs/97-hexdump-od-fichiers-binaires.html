97. hexdump et od — Affichez n'importe quel fichier en hexadécimal

Quand vous ouvrez un fichier binaire avec un éditeur de texte classique, vous ne voyez qu'un tas de caractères incompréhensibles. hexdump et od (octal dump) vous montrent exactement ce qu'il y a réellement dans le fichier — octet par octet. Indispensable pour comprendre les formats de fichiers, débugger, ou simplement curieux de voir ce qui se cache dans un fichier.

1. hexdump — Le visualiseur hexadécimal

Installation

hexdump fait partie du paquet bsdmainutils (souvent déjà installé). Sur certaines distributions, il s'appelle hexdump ou hd.

# Vérifier qu'il est disponible which hexdump # ou utiliser hd (alias de hexdump sur certain systèmes) which hd

Affichage basique

# Afficher un fichier entier en hexadécimal hexdump -C monfichier.bin

L'option -C est la plus lisible : elle montre l'adresse (offset) en hexadécimal, le contenu en hexadécimal (16 octets par ligne), et la représentation ASCII à droite.

# Exemple avec un fichier texte echo "Bonjour le monde !" > test.txt hexdump -C test.txt

Résultat :

00000000 42 6f 6e 6a 6f 75 72 20 6c 65 20 6d 6f 6e 64 65 |Bonjour le monde| 00000010 20 21 0a | !.|

Vous voyez : chaque caractère a son code hexadécimal. 42 = B, 6f = o, 0a = newline (saut de ligne).

Options utiles

OptionDescription
-CFormat canonique : offset + hex + ASCII (le plus courant)
-xAfficher en mots de 2 octets (hexadécimal)
-bAfficher en octal (un octet par champ)
-cAfficher en caractères ASCII (avec interprétation)
-n NLimiter l'affichage aux N premiers octets
-s NCommencer l'affichage à l'offset N
-vAfficher toutes les lignes (sans remplacer les lignes identiques par *)

Exemples pratiques

# Voir les 32 premiers octets d'un fichier PNG (en-tête) hexdump -C image.png | head -5

Un fichier PNG commence toujours par 89 50 4e 47 (soit \x89PNG en ASCII) — pratique pour identifier un type de fichier.

# Sauter les 16 premiers octets et afficher la suite hexdump -C -s 16 monfichier.bin | head -10
# Afficher seulement les 64 premiers octets hexdump -C -n 64 monfichier.bin
# Format caractère seul (comme strings mais avec codes) hexdump -C -n 100 /dev/urandom

2. od — Octal Dump (format original Unix)

od est l'outil historique Unix pour visualiser des fichiers. Son nom signifie octal dump, mais il supporte aussi l'hexadécimal et d'autres formats.

# Format par défaut : octal (base 8) od test.txt

Résultat :

0000000 042111 06f156 075543 020152 066555 040040 066145 040412 0000020 021012

Options principales

OptionDescription
-A xAdresse en hexadécimal (au lieu de octal par défaut)
-t x1Type : hexadécimal, 1 octet
-t x2Type : hexadécimal, mots de 2 octets
-t cCaractères ASCII avec séquences d'échappement
-t d1Décimal, 1 octet par valeur
-N NLimiter aux N premiers octets
-j NSauter les N premiers octets

Exemples pratiques

# Format hexadécimal avec adresse hexadécimale (le plus lisible) od -A x -t x1z -v monfichier.bin

-A x = adresse en hexa, -t x1z = hexadécimal 1 octet + ASCII, -v = tout afficher.

# Voir les codes ASCII de caractères spéciaux echo -e "Tab:\tNouvelle ligne:\n" | od -A x -t x1z -c

Résultat :

00000000 54 61 62 3a 09 4e 6f 75 76 65 6c 6c 65 3a 0a |Tab:.Nouvelle ligne:.|

Ici 09 est la tabulation et 0a est le newline.

# Combiner od avec un pipe pour analyser des données cat /proc/cpuinfo | od -A x -t x1z | head -10

3. Comparaison hexdump vs od

Critèrehexdumpod
PortabilitéBSD/Linux (paquet bsdmainutils)Tous les Unix (standard POSIX)
Format par défauthexadécimal (avec -C)octal
LisibilitéPlus lisible par défautPlus cryptique par défaut
Option canonique-C (offset + hex + ASCII)-A x -t x1z (à mémoriser)
Caractères affichésASCII uniquementASCII + séquences d'échappement

Recommandation : Utilisez hexdump -C pour une lecture rapide et lisible. Utilisez od quand vous avez besoin de formats spécifiques ou quand vous êtes sur un système sans hexdump.

4. Cas d'utilisation concrets

Identifier un type de fichier

# Vérifier les "magic bytes" d'un fichier hexdump -C monfichier | head -1

Quelques signatures magiques courantes :

FichierSignature (hex)ASCII
PNG89 50 4e 47\x89PNG
JPEGff d8 ff\xff\xd8\xff
PDF25 50 44 46%PDF
ZIP50 4b 03 04PK\x03\x04
ELF (Linux)7f 45 4c 46\x7fELF

Analyser un fichier binaire inconnu

# Première ligne : en-tête hexdump -C -n 16 fichier.bin
# Derniers octets : pied de page ou checksum hexdump -C -s -16 fichier.bin

L'option -s -16 signifie : partir de 16 octets avant la fin du fichier.

Comparer deux fichiers binaires

# Extraire les différences entre deux fichiers diff <(hexdump -C fichier1.bin) <(hexdump -C fichier2.bin)

Vérifier l'intégrité d'un fichier après transfert

# Comparer les premiers et derniers octets d'un fichier copié hexdump -C -n 16 fichier_copie.bin hexdump -C -s -16 fichier_copie.bin

5. Exercices pratiques

Exercice 1 — Identifier un fichier mystery

Créez un fichier avec différents contenus et identifiez son type avec hexdump :

# Créer un fichier qui ressemble à un PNG printf '\x89PNG\r\n\x1a\n' > mystery.bin hexdump -C mystery.bin

Exercice 2 — Lire les premiers octets d'un exécutable

# Voir l'en-tête ELF d'un programme hexdump -C -n 64 /bin/ls

Exercice 3 — Analyser une image disque

# Voir le secteur de boot d'une clé USB (si vous avez les droits) # ATTENTION : ne faites pas ça sur un disque système ! sudo hexdump -C -n 512 /dev/sdb | head -10

Exercice 4 — Comparer hexdump et od

# Mêmes données, formats différents echo "Test 123" > demo.txt hexdump -C demo.txt od -A x -t x1z demo.txt

6. Astuces avancées

Combiner avec grep pour rechercher des motifs

# Rechercher une séquence hexadécimale dans un fichier # Par exemple, chercher "PDF" (50 44 46) hexdump -C fichier.bin | grep -i "50 44 46"

Extraire une portion précise

# Extraire les octets 256 à 512 d'un fichier dd if=fichier.bin bs=1 skip=256 count=256 | hexdump -C

Créer un alias pratique

# Ajouter dans ~/.bashrc pour un affichage par défaut plus lisible alias hdump='hexdump -C -v'

Résumé

CommandeUsage principal
hexdump -C fichierAffichage hexadécimal canonique le plus courant
hexdump -C -n 64 fichierLimiter aux 64 premiers octets
hexdump -C -s N fichierCommencer à l'offset N
od -A x -t x1z fichierFormat hex + ASCII avec od
hexdump -C fichier | headVoir seulement le début
hexdump -C -s -N fichierVoir les N derniers octets

hexdump et od sont vos yeux sur les fichiers binaires. Quand un fichier refuse de s'ouvrir ou que vous voulez comprendre pourquoi un programme lit mal des données, ces outils révèlent la vérité : ce qui est vraiment écrit sur le disque, octet par octet.
