ln — Liens symboliques et liens durs

Introduction

Vous avez probablement déjà rencontré ces petits raccourcis avec une flèche sur Linux sans vraiment comprendre ce que c'était. Les liens sous Linux permettent de créer des références vers des fichiers ou dossiers, un peu comme les raccourcis sous Windows, mais en bien plus puissant.

Il existe deux types de liens : les liens durs (hard links) et les liens symboliques (symbolic links ou symlinks). Chaque type a ses propres usages et particularités. Dans cette leçon, vous allez comprendre la différence et savoir quand utiliser chacun.

Comprendre le système de fichiers Linux

Chaque fichier a un inode

Pour comprendre les liens, il faut d'abord savoir comment Linux stocke les fichiers. Chaque fichier sur le disque possède un numéro unique appelé inode. L'inode contient les métadonnées du fichier (permissions, dates, emplacement des données) mais pas le nom du fichier.

# Voir le numéro d'inode d'un fichier ls -li fichier.txt

La première colonne affiche le numéro d'inode.

Un nom de fichier pointe vers un inode

Quand vous créez un fichier, vous créez en réalité un nom qui pointe vers un inode. Le nom est stocké dans un répertoire, qui est lui-même une liste de noms pointant vers des inodes.

# Créer un fichier echo "Bonjour" > fichier.txt # Vérifier son inode ls -li fichier.txt

Les liens duros (Hard Links)

Qu'est-ce qu'un lien dur ?

Un lien dur est un nom supplémentaire qui pointe vers le même inode qu'un fichier existant. Les deux noms sont parfaitement égaux — supprimer l'un ne supprime pas l'autre tant qu'il reste au moins un lien.

Créer un lien dur

ln fichier.txt lien_dur.txt

Après cette commande, fichier.txt et lien_dur.txt pointent vers le même contenu.

Vérifier que ça fonctionne

# Voir les deux fichiers avec leurs inodes ls -li

Vous remarquerez que les deux noms ont le même numéro d'inode. Le compteur de liens (deuxième colonne) passe à 2.

Modifier un lien dur

# Modifier via un lien echo "Nouveau contenu" > lien_dur.txt # Lire via l'autre lien cat fichier.txt

Les deux noms voient le même contenu car ils pointent vers le même inode.

Supprimer un lien dur

# Supprimer le lien dur rm lien_dur.txt # Le fichier original existe toujours cat fichier.txt

Limitations des liens duros

  • Même système de fichiers : un lien dur ne peut pointer que vers un fichier du même système de fichiers (même partition).
  • Pas de liens vers des répertoires : vous ne pouvez pas créer de lien dur vers un répertoire.
  • Pas de liens vers des fichiers specials (devices, sockets).

Les liens symboliques (Symbolic Links)

Qu'est-ce qu'un lien symbolique ?

Un lien symbolique est un fichier spécial qui contient le chemin vers un autre fichier ou répertoire. C'est comme un raccourci : le lien symbolique pointe vers la cible, et quand vous ouvrez le lien, Linux vous redirige vers le fichier réel.

Créer un lien symbolique

# Syntaxe : ln -s fichier_original lien_symbolique ln -s fichier.txt lien_sym.txt

Identifier un lien symbolique

# Les liens symboliques sont reconnaissables par la flèche -> ls -la

La sortie montre quelque chose comme :

lrwxrwxrwx 1 user user 12 jun 2 lien_sym.txt -> fichier.txt

Le l au début indique que c'est un lien (pas un fichier ordinaire -).

Suivre un lien symbolique

# Lire le contenu via le lien cat lien_sym.txt # Le lien symbolique pointe vers le fichier original # Si le fichier original est supprimé, le lien devient "orphelin"

Créer un lien vers un répertoire

# Les liens symboliques peuvent pointer vers des répertoires ln -s /var/log logs

Liens symboliques vers des chemins absolus ou relatifs

# Absolu (recommandé) : fonctionne où que soit le lien ln -s /home/user/documents/docs mes_docs # Relatif : fonctionne seulement si le lien est dans le bon contexte ln -s ../autre_dossier/file.txt lien.txt

Liens symboliques cassés

# Un lien symbolique vers un fichier inexistant ls -la lien_casse # Affiche : lien_casse -> fichier_inexistant (clignotant en rouge sur certains terminaux)

Pour vérifier si un lien symbolique est valide :

test -e lien_sym && echo "Valide" || echo "Cassé"

Cas d'usage courants des liens symboliques

Créer des raccourcis pour des chemins longs

# Raccourcir un chemin fréquemment utilisé ln -s /var/log/apache2 logs-apache # Utiliser le raccourci cd logs-apache ls /var/log/apache2 # équivalent

Versions multiples d'un logiciel

# Gérer plusieurs versions d'un logiciel ln -s /opt/python-3.9.7 python ln -s /opt/python-3.11.2 python3 #切换 de version en changeant le lien rm python ln -s /opt/python-3.10.4 python

Configuration centralisée

# Pointer vers un fichier de config dans un autre emplacement ln -s /mnt/config/git/config ~/.gitconfig

Répertoires de données partagés

# Partager un dossier entre plusieurs utilisateurs ln -s /srv/donnees_partagees /home/user/documents/data

Gérer les liens symboliques

Voir tous les liens vers un inode

Pour trouver tous les noms pointant vers un même inode :

# Trouver tous les liens duros (via l'inode) find /chemin -samefile fichier.txt

Trouver tous les liens symboliques dans un répertoire

# Trouver les liens symboliques find /chemin -type l # Trouver les liens symboliques cassés find /chemin -type l ! -e

Modifier un lien symbolique

Pour changer la cible d'un lien symbolique, supprimez-le et recréez-le :

# Supprimer et recréer rm ancien_lien ln -s /nouveau/chemin ancien_lien

Connaître la cible d'un lien

# Lire le lien (résolution) readlink lien_sym # Résoudre complètement le chemin readlink -f lien_sym

Dépanner les liens symboliques

Le lien ne fonctionne plus

Si un lien symbolique est cassé, vérifiez d'abord que la cible existe :

# Vérifier la cible ls -l lien_sym # Lister le contenu du répertoire parent ls -la /chemin/parent/

Lien relatif vs absolu

Si vous déplacez un lien symbolique qui utilise un chemin relatif, il peut se casser. Préférez les chemins absolus pour les liens permanents :

# Bon : chemin absolu ln -s /home/user/projets/mon_projet projet # Risqué : chemin relatif (cassé si déplacé) ln -s ../../projets/mon_projet projet

Permissions des liens symboliques

Les liens symboliques ont toujours les permissions lrwxrwxrwx — ces permissions n'ont pas de sens car le lien suit toujours les permissions du fichier cible.

Exercice pratique

  1. Créer un fichier texte : écrivez du texte dans fichier_test.txt.
  2. Vérifier son inode : faites ls -li fichier_test.txt et notez le numéro d'inode.
  3. Créer un lien dur : ln fichier_test.txt lien_dur_test.txt.
  4. Vérifier : ls -li montre que les deux ont le même inode.
  5. Créer un lien symbolique : ln -s fichier_test.txt lien_sym_test.txt.
  6. Vérifier : ls -la montre la flèche vers la cible.
  7. Modifier via le lien dur : echo "modifié" > lien_dur_test.txt, puis cat fichier_test.txt.
  8. Modifier via le lien symbolique : echo "via sym" > lien_sym_test.txt, puis cat fichier_test.txt.
  9. Supprimer le fichier original : rm fichier_test.txt.
  10. Vérifier le lien dur : cat lien_dur_test.txt — il fonctionne encore !
  11. Vérifier le lien symbolique : cat lien_sym_test.txt — message d'erreur (lien cassé).
  12. Créer un lien vers /var/log : ln -s /var/log mes_logs et explorez-le.
  13. Nettoyer : rm lien_dur_test.txt lien_sym_test.txt fichier_test.txt mes_logs (si créé).

Conclusion

Les liens Linux sont un outil puissant pour organiser vos fichiers et créer des raccourcis intelligents. Utilisez les liens duros quand vous avez besoin de partager un même fichier sous plusieurs noms sur la même partition — par exemple pour des sauvegardes rapides. Utilisez les liens symboliques pour créer des raccourcis vers des chemins longs, gérer plusieurs versions d'un logiciel, ou pointer vers des fichiers sur d'autres partitions. La commande ln crée des liens durs, et ln -s crée des liens symboliques. Avec l'habitude, vous utiliserez ces deux outils quotidiennement pour garder votre système organisé.
