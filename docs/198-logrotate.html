Leçon 198 — logrotate : Gérer automatiquement la rotation des logs

Sous Linux, les fichiers logs ne cessent de grandir. Si vous ne les maîtrisez pas, votre disque finit par se remplir et les services plantent. C'est là qu'intervient logrotate — l'outil qui rotate, compresse, supprime et envoie automatiquement vos logs pour éviter les sorpresas.

1. Comment ça marche ?

logrotate est lancé quotidiennement par cron (via /etc/cron.daily/logrotate). Il lit ses fichiers de configuration et applique les règles définies pour chaque fichier ou groupe de fichiers.

Le principe est simple : quand un log atteint une certaine taille ou un certain âge, logrotate le renomme (en y ajoutant un numéro), le compresse, et crée un nouveau fichier vide à la place. Les anciens fichiers sont supprimés après un certain nombre de rotations.

2. Le fichier de configuration principal

La configuration principale se trouve dans /etc/logrotate.conf. C'est le point de départ, mais en pratique on crée des fichiers individuels par service dans /etc/logrotate.d/.

Contenu typique de /etc/logrotate.conf :

# Rotation hebdomadaire (weekly = par défaut)
weekly
# Garder les 4 dernières versions
rotate 4
# Compresser les fichiers rotatés
compress
# Créer un nouveau fichier log après rotation avec les droits specified
create 0640 root adm
# Inclure les configs individuelles
include /etc/logrotate.d

3. Créer une configuration pour un service

Dans /etc/logrotate.d/, chaque service a son propre fichier. Par exemple, pour une application personnalisée :

/var/log/monapp/*.log {
weekly # Rotation chaque semaine
rotate 8 # Garder 8 fichiers (8 semaines)
missingok # Ne pas erreur si le fichier n'existe pas
notifempty # Ne pas tourner si le fichier est vide
compress # Compresser les anciennes versions
delaycompress # Compresser à la deuxième rotation (pas immédiatement)
create 0640 www-data www-data # Nouveau fichier avec ces droits
sharedscripts # Exécuter le script post-rotation une seule fois
postrotate
systemctl reload monapp > /dev/null 2>&1 || true
endscript
}

4. Les directives les plus utiles

5. Exemple concret : configurer les logs Nginx

Voyons à quoi ressemble la config de Nginx livrée par défaut :

/var/log/nginx/*.log {
daily # Rotation quotidienne
missingok # Pas d'erreur si pas de log
rotate 14 # Garder 14 jours
compress # Compresser
delaycompress # Garder la dernière non compressée
notifempty # Ignorer les fichiers vides
create 0640 www-data adm # Droits du nouveau fichier
sharedscripts # Script exécuté une seule fois
postrotate
invoke-rc.d nginx rotate >/dev/null 2>&1
endscript
}

6. Tester sa configuration

Avant de déployer, toujours tester :

# Tester sans rien modifier (mode debug)
sudo logrotate -d /etc/logrotate.conf
# Forcer une rotation maintenant (pour tester)
sudo logrotate -f /etc/logrotate.d/monapp

L'option -d montre ce qui se passerait sans rien faire. Très utile pour débugger avant de apply.

7. Rotation par taille plutôt que par temps

Si vos logs grossissent très vite, privilégiez une rotation par taille :

/var/log/monapp/access.log {
size 50M # Rotation quand le fichier dépasse 50 Mo
rotate 5 # Garder 5 fichiers
compress
missingok
notifempty
create 0640 www-data www-data
}

Notez que size prime sur weekly/daily : si les deux sont spécifiés, la rotation se fait à la première condition remplie.

8. Le piège du copytruncate

Certains processus (comme SysV init ou certains services legacy) gardent le fichier log ouvert en permanence. Dans ce cas, vous ne pouvez pas renommer le fichier. Utilisez copytruncate :

/var/log/ancien-service.log {
daily
rotate 7
copytruncate # Copie le contenu puis vide le fichier original
compress
missingok
notifempty
}

copytruncate a un léger overhead (copie du contenu) mais c'est la seule solution pour les processus qui ne supportent pas le signal de réouverture des logs.

9. Surveillance et logs

logrotate écrit son activité dans /var/lib/logrotate/status (fichier binaire) et peut aussi logger dans /var/log/syslog selon la configuration. Pour voir les dernières rotations :

# Voir quand chaque log a été rotaté
cat /var/lib/logrotate/status
# Filtrer les entrées logrotate dans syslog
grep logrotate /var/log/syslog | tail -20

10. Exercice pratique

Créez une configuration pour une application fictive :

# 1. Créer un répertoire et des fichiers de test
sudo mkdir -p /var/log/testapp
sudo sh -c 'for i in $(seq 1 20); do echo "Ligne $i de log $(date)" >> /var/log/testapp/app.log; done'
# 2. Créer la config
sudo nano /etc/logrotate.d/testapp
# Y écrire :
# /var/log/testapp/*.log {
# weekly
# rotate 4
# compress
# missingok
# notifempty
# create 0640 root root
# }
# 3. Forcer une rotation pour tester
sudo logrotate -f /etc/logrotate.d/testapp
# 4. Vérifier le résultat
ls -la /var/log/testapp/
# Vous devriez voir app.log.1.gz (compressé) et un nouveau app.log

Résumé

logrotate est un outil essentiel pour tout administrateur Linux. Il permet de gérer automatiquement la croissance des fichiers logs avec des règles simples et flexibles. Les points clés à retenir :

  • /etc/logrotate.conf = configuration globale, /etc/logrotate.d/ = configs par service
  • weekly, daily, monthly ou size contrôlent la fréquence
  • rotate N définit combien de versions garder
  • compress et delaycompress pour gérer l'espace
  • copytruncate pour les processus qui gardent le log ouvert
  • Testez toujours avec logrotate -d avant d'appliquer
