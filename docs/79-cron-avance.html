Cron — Planification avancée et bonnes pratiques

Introduction

Si la leçon 13 vous a donné les bases de cron, cette leçon vous pousse plus loin. Vous allez maîtriser la syntaxe cron avancée, comprendre les pièges courants, organiser vos tâches avec les répertoires spécialisés, et sécuriser vos scripts planifiés. Quand vous aurez terminé, cron n'aura plus aucun secret pour vous.

Syntaxe cron détaillée

Les 5 champs

Chaque ligne cron contient 5 champs séparés par des espaces :

┌───────────── minute (0-59) │ ┌───────────── heure (0-23) │ │ ┌───────────── jour du mois (1-31) │ │ │ ┌───────────── mois (1-12) │ │ │ │ ┌───────────── jour de la semaine (0-6, 0 = dimanche) │ │ │ │ │ * * * * * commande

Symboles spéciaux

SymboleSignificationExemple
*Chaque valeur* * * * * = chaque minute
,Liste de valeurs0,30 * * * * = à chaque heure pile et demi
-Plage de valeurs9-17 * * * * = chaque minute entre 9h et 17h
/Intervalle / pas*/5 * * * * = toutes les 5 minutes
LDernier jour (jour/mois)0 0 L * * = dernier jour du mois à minuit
WJour ouvré le plus proche0 9 15W * * = 15 du mois ou jour ouvré le + proche
#N-ième du jour/semaine0 0 * * 2#3 = 3e mardi du mois

Exemples avancés

# Toutes les 5 minutes */5 * * * * # Chaque 15 minutes (notation alternative) 0,15,30,45 * * * * # Heures impairs (1, 3, 5, ...) 0 1-23/2 * * * # Du lundi au vendredi à 8h30 30 8 * * 1-5 # Tous les 2 heures pendant les heures ouvrées 0 9-17/2 * * 1-5 # 3e lundi du mois à 10h 0 10 * * 1#3 # Dernier vendredi du mois à 14h 0 14 * * 5L # Minutes 10 à 20 toutes les 5 minutes 10-20/5 * * * *

Répertoires cron spécialisées

Cron recherche automatiquement des scripts dans quatre répertoires. Plus besoin de syntaxe compliquée — mettez juste un script exécutable au bon endroit.

/etc/cron.d/ # Scripts système (format complet avec utilisateur) # Exemple de fichier : # PATH=/usr/local/bin:/usr/bin:/bin # 0 3 * * * root /opt/scripts/sauvegarde.sh /etc/cron.hourly/ # Exécuté chaque heure /etc/cron.daily/ # Exécuté chaque jour à 6h25 /etc/cron.weekly/ # Exécuté chaque semaine le dimanche à 6h47 /etc/cron.monthly/ # Exécuté le 1er du mois à 6h52

Pour ajouter une tâche dans un répertoire horaire, copiez simplement votre script :

# Rendre le script exécutable sudo chmod +x /opt/scripts/nettoyage_logs.sh # Copier dans le répertoire quotidien sudo cp /opt/scripts/nettoyage_logs.sh /etc/cron.daily/ # Vérifier que le nom ne contient pas de point (sinon ignoré) sudo mv netcost.sh netcost # pas .sh sinon ignoré

Ordre d'exécution

Les répertoires cron.hourly, cron.daily, etc. sont exécutés par run-parts qui les lance dans l'ordre alphabétique. L'heure précise est définie dans /etc/crontab.

# Voir les heures d'exécution (fichier système) /etc/crontab

Environment et sécurité

Le problème de l'environnement

Cron exécute les scripts avec un environnement très limité — variables PATH minimales, aucun terminal. Un script qui fonctionne en interactif peut échouer dans cron.

# Debug : voir l'environnement cron crontab -e # Ajouter cette ligne temporaire pour tester : # * * * * * env > /tmp/cron_env.txt # Puis vérifier le contenu cat /tmp/cron_env.txt

Solutions pour l'environnement

Dans votre crontab, rechargez votre profil bash :

# Charger le profil bash avant chaque commande SHELL=/bin/bash BASH_ENV=/home/user/.bashrc PATH=/usr/local/bin:/usr/bin:/bin MAILTO=user@example.com # Ou lancez via bash -l : * * * * * /bin/bash -l /home/user/script.sh

Redirection des sorties

Par défaut, cron envoie la sortie par email. Si vous ne voulez pas d'email, redirigez stdout et stderr :

# Ignorer toute sortie (recommande) * * * * * /opt/scripts/backup.sh > /dev/null 2>&1 # Logger dans un fichier (avec rotation) 0 3 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1 # Logger stdout et stderr séparément 0 3 * * * /opt/scripts/backup.sh > /var/log/backup.log 2>/var/log/backup.err # Conserver seulement les erreurs 0 3 * * * /opt/scripts/backup.sh 2>&1 > /dev/null || /opt/scripts/backup.sh > /dev/null

Utilisateurs et permissions

Cron par utilisateur

# Éditer sa propre crontab crontab -e # Lister ses tâches crontab -l # Supprimer toute la crontab crontab -r # Lister les crontabs d'un autre utilisateur (root) sudo crontab -l -u david # Éditer la crontab d'un autre utilisateur (root) sudo crontab -e -u david

Fichier /etc/cron.d/ pour les utilisateurs

# Format complet : utilisateur + commande # /etc/cron.d/script-quotidien SHELL=/bin/bash PATH=/usr/local/bin:/usr/bin:/bin 0 2 * * * david /home/david/scripts/sauvegarde.sh

Restreindre l'accès à cron

# Interdire cron pour un utilisateur echo "alice" | sudo tee /etc/cron.deny # Autoriser seulement certains utilisateurs echo "alice" | sudo tee /etc/cron.allow # Si cron.allow existe, seuls les utilisateurs listés peuvent l'utiliser # Si seul cron.deny existe, les utilisateurs listés sont interdits

Systemd timers — Alternative moderne

systemd timers sont une alternative à cron recommandée sur les systèmes modernes. Ils offrent plus de contrôle et sont plus faciles à débugger.

Créer un timer

# Unit service : /etc/systemd/system/nettoyage.service [Unit] Description=Nettoyage des logs [Service] Type=oneshot ExecStart=/opt/scripts/nettoyage.sh # Unit timer : /etc/systemd/system/nettoyage.timer [Unit] Description=Nettoyage quotidien [Timer] OnCalendar=daily Persistent=true [Install] WantedBy=timers.target
# Activer et démarrer sudo systemctl enable --now nettoyage.timer # Lister les timers actifs systemctl list-timers # Statut du timer systemctl status nettoyage.timer # Statut du service systemctl status nettoyage.service

Timer avec condition

# Exécuter seulement si le réseau est accessible [Timer] OnCalendar=daily Persistent=true [Install] WantedBy=timers.target # Ajouter dans le service : [Unit] ConditionPathExists=/run/systemd/network/ # Ou attendre le réseau After=network-online.target Wants=network-online.target

Techniques de debugging

Tester avant de déployer

Avant de mettre dans cron, testez manuellement avec le même environnement :

# Simuler l'environnement cron /usr/bin/env -i HOME=/home/user PATH=/usr/local/bin:/usr/bin:/bin /bin/bash -l -c '/opt/scripts/monscript.sh' # Vérifier les codes de sortie /opt/scripts/monscript.sh echo "Code de retour: $?"

Logger dans le script

Ajoutez du logging dans vos scripts pour Faciliter le dépannage :

#!/bin/bash LOGFILE="/var/log/monscript.log" log() { echo "[$(date '+%Y-%m-%d %H:%M:%S')] $*" | tee -a "$LOGFILE" } log "Démarrage du script" log "Utilisateur: $USER" log "HOME: $HOME" # Vos commandes ici log "Traitement terminé"

Commandes de debug cron

# Vérifier que cron tourne systemctl status cron # Debian/Ubuntu systemctl status crond # RHEL/CentOS # Voir les logs cron journalctl -u cron -f grep CRON /var/log/syslog # Debian # Lister les tâches système cat /etc/crontab ls -la /etc/cron.d/ ls -la /etc/cron.hourly/ /etc/cron.daily/ /etc/cron.weekly/ /etc/cron.monthly/

Planifier une exécution immédiate pour tester

# Ajouter une tâche qui s'exécute dans 1 minute pour tester crontab -e # Tapez : * * * * * /opt/scripts/test.sh > /tmp/test_cron.log 2>&1 # Attendre 1 minute sleep 60 # Vérifier le résultat cat /tmp/test_cron.log # Supprimer la ligne de test quand validé

Bonnes pratiques

Organisation des scripts

# Structure recommandée /opt/ ├── scripts/ │ ├── daily/ # scripts quotidiens │ ├── hourly/ # scripts horaires │ ├── weekly/ # scripts hebdomadaires │ └── common/ # fonctions partagées └── logs/ # logs des scripts cron # Exemple de script bien structuré #!/bin/bash # /opt/scripts/daily/backup.sh set -euo pipefail SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)" source "${SCRIPT_DIR}/common/functions.sh" log "Démarrage backup" # ... reste du script log "Backup terminé"

Règles de sécurité

  • Ne jamais mettre de mots de passe en clair dans les scripts cron — utilisez des variables d'environnement ou des fichiers .env avec permissions restrictives.
  • Vérifier les permissions : chmod 700 /opt/scripts/sensibles.sh
  • Utiliser des chemins absolus dans les scripts (cron n'a pas de répertoire de travail).
  • Préférer sudo -u pour les tâches devant tourner sous un autre utilisateur.
  • Logger tout — les scripts cron silencieux sont difficiles à débugger.
  • Vérifier l'espace disque avant d'écrire des logs volumineux.

Rotation des logs

Configurez logrotate pour vos logs cron :

# /etc/logrotate.d/mes-scripts /var/log/monscript.log { daily rotate 7 compress missingok notifempty create 0640 root root sharedscripts }

Cas d'usage courants

Nettoyage des fichiers temporaires

# /etc/cron.daily/cleanup-temp # Nettoyer /tmp tous les jours à 3h 0 3 * * * root find /tmp -type f -atime +7 -delete 2>/dev/null # Nettoyer les logs de plus de 30 jours 0 4 * * * root find /var/log -name "*.log" -mtime +30 -compress

Sauvegardes automatiques

# /etc/cron.daily/backup-db 0 2 * * * root /opt/scripts/backup-db.sh >> /var/log/backup-db.log 2>&1 # Backup avec rétention (garder 7 jours) #!/bin/bash BACKUP_DIR="/backup" DATE=$(date +%Y%m%d_%H%M%S) mysqldump -u backup_user -p"$MYSQL_PASSWORD" all_databases | gzip > "$BACKUP_DIR/db_$DATE.sql.gz" # Supprimer les backups de plus de 7 jours find "$BACKUP_DIR" -name "db_*.sql.gz" -mtime +7 -delete

Monitoring et alertes

# Vérifier l'espace disque chaque heure etalerert si < 10% 0 * * * * root df -h / | awk 'NR==2 {if($5+0<10) print "Disque bas: "$5}' | wall # Vérifier les services critiques */5 * * * * root systemctl is-active --quiet apache2 || systemctl restart apache2

Erreurs courantes

ErreurSolution
Script ne fonctionne que manuellementVérifier les chemins absolus et l'environnement. Utiliser -l avec bash.
Pas de sortie / pas de logRediriger stdout/stderr vers un fichier. Ajouter du logging.
Exécution trop fréquenteUtiliser un fichier lock pour éviter les doublons (flock).
Tâche ignorée silencieusementVérifier le nom du fichier dans /etc/cron.d/ (pas de point).
Fuseau horaire non respectéVérifier que le système est dans le bon fuseau : timedatectl.
Dépassement de tempsUtiliser timeout ou un script wrapper avec set -m.

Éviter les doublons avec flock

# Empêcher l'exécution si une instance tourne déjà 0 * * * * flock -n /var/lock/monscript.lock /opt/scripts/monscript.sh

Exercice pratique

  1. Configurer un script de monitoring : créez un script ~/scripts/check_disk.sh qui affiche l'espace disque et enregistre la sortie dans /var/log/disk_check.log. Rendez-le exécutable.
  2. Planifier l'exécution : avec crontab -e, exécutez ce script toutes les heures. Ajoutez la redirection vers un fichier de log.
  3. Tester immédiatement : exécutez le script manuellement et vérifiez le log.
  4. Ajouter une tâche système : copiez votre script dans /etc/cron.hourly/ (sans extension) et vérifiez qu'il s'exécute.
  5. Créer un timer systemd : au lieu de cron, créez un service et timer systemd pour exécuter votre script quotidiennement à 9h.
  6. Ajouter une protection contre les doublons : utilisez flock dans votre crontab pour éviter que le script ne s'exécute plusieurs fois simultanément.
  7. Vérifier le bon fonctionnement : consultez systemctl list-timers ou grep CRON /var/log/syslog pour confirmer l'exécution.
  8. Nettoyer : supprimez vos entrées de test de crontab et les fichiers de test.

Conclusion

Cron est un outil puissant, mais ses pièges sont nombreux. Avec cette leçon, vous savez maintenant maîtriser la syntaxe avancée, utiliser les répertoires spécialisés, sécuriser vos scripts, et débugger efficacement. Les timers systemd offrent une alternative moderne mérite d'être envisagée sur les systèmes récents — ils sont plus facile à监控 et offrent plus de fonctionnalités. Quel que soit votre choix, n'oubliez jamais les bases : chemins absolus, logging, et tests avant déploiement. Un script cron mal testé peut causer des problèmes silencieux que vous ne remarquerez qu'au moment où vous en aurez le plus besoin.
