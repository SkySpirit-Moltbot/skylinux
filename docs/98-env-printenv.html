env et printenv — Explorer et manipuler les variables d'environnement

Linux utilise des variables d'environnement pour configurer le comportement du système et des applications. Les commandes env et printenv permettent de les afficher, tandis que export permet de les définir. Ce chapitre vous montre comment tirer pleinement parti de ces outils essentiels.

Afficher toutes les variables avec printenv

La commande printenv affiche toutes les variables d'environnement définies dans votre session courante.

printenv | sort

Sans argument, printenv affiche l'ensemble de l'environnement. Le tri alphabétique rend la lecture plus confortable.

Afficher une variable précise

Pour visualiser une seule variable, précisez son nom en argument :

printenv HOME
printenv USER
printenv PATH

Si la variable n'existe pas, aucune sortie n'est générée (pas d'erreur visible).

La commande env — Exécuter dans un environnement modifié

La commande env sans argument affiche également toutes les variables, mais elle brille surtout par sa capacité à lancer une commande dans un environnement personnalisé.

Afficher l'environnement complet

env | sort

Lancer une commande avec un environnement vide

Utilisez env -i pour partir d'un environnement minimal (quasi vide) :

env -i /bin/bash -c 'echo "HOME=$HOME"'

Aucune variable n'est héritée — HOME est vide. Utile pour tester un programme dans un contexte propre.

Définir des variables pour une commande

Syntaxe : env VAR=valeur commande

env MA_VARIABLE="bonjour" printenv MA_VARIABLE
env PATH="/opt/monprogramme:$PATH" mon_script.sh

Définir des variables avec export

Pour créer ou modifier une variable d'environnement dans la session courante :

export MA_VARIABLE="valeur"
printenv MA_VARIABLE

Par défaut, les variables définies ainsi sont locales à la session shell et ne persistent pas après fermeture du terminal. Pour les rendre permanentes, ajoutez-les dans un fichier de configuration :

# Dans ~/.bashrc ou ~/.profile export PATH="/opt/monprogramme/bin:$PATH" export EDITOR="nano"

Exporter une variable existante

Si une variable est déjà définie (sans export), rendez-la accessible aux sous-processus :

MA_VAR="test" export MA_VAR # maintenant visible par les processus enfants

Supprimer une variable

Utilisez unset pour supprimer une variable d'environnement :

unset MA_VARIABLE printenv MA_VARIABLE # aucune sortie — la variable n'existe plus

Modifier PATH — Ajouter des répertoires

La variable PATH détermine où le shell cherche les commandes. Pour ajouter un répertoire temporairement :

# Ajouter au début (priorité haute) export PATH="/opt/programmes/bin:$PATH" # Ajouter à la fin (priorité basse) export PATH="$PATH:/opt/programmes/bin"

Pour une modification permanente, ajoutez la ligne dans ~/.bashrc (session interactive) ou ~/.profile (session de connexion).

Cas d'usage pratiques

1. Déboguer un script qui échoue silencieusement

# Vérifier que les variables attendues sont bien définies env | grep -E '^(HOME|PATH|USER)='

2. Exécuter un script avec un PATH limité

# Sécurité : limiter la recherche de commandes env -i PATH=/usr/bin:/bin HOME="$HOME" /home/david/mon_script.sh

3. Propager des variables à un service systemd

# Dans /etc/environment MA_BASE_URL="https://api.monsite.ch" API_KEY="secret123"

4. Lancer un processus avec des credentials temporaires

env AWS_ACCESS_KEY_ID="..." AWS_SECRET_ACCESS_KEY="..." ./upload.sh

Bonnes pratiques

  • Ne stockez jamais de secrets sensibles (mots de passe, clés API) dans des fichiers .bashrc versionnés sur Git.
  • Utilisez des fichiers séparés ou des gestionnaires de secrets pour les credentials.
  • Préférez les variables en minuscules pour vos variables personnelles afin d'éviter les collisions avec les variables système en MAJUSCULES.
  • Testez toujours vos modifications dans un sous-shell avant de les rendre permanentes : bash -c 'source ~/.bashrc; echo $MA_VARIABLE'
