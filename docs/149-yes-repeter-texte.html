149 — yes — Répéter du texte en boucle

yes est une commande simple mais étonnamment utile. Elle affiche une ligne contenant une chaîne de texte (par défaut "y") indéfiniment, jusqu'à ce qu'on l'arrête ou qu'elle soit redirigée. Elle sert principalement à automatiser les réponses "oui" dans les scripts et à générer des flux de données texte.

1. Principe de base

Sans argument, yes affiche la lettre y suivie d'un retour à la ligne, en continu :

yes

Cela produit une suite infinie de lignes contenant "y". Pour arrêter, faites Ctrl+C.

Vous pouvez spécifier n'importe quel texte à répéter :

yes "oui"

Cela affiche "oui" en boucle.

2. Répondre automatiquement "oui" aux commandes

L'utilisation la plus courante de yes est d'automatiser les confirmations interactives. Many commands ask for confirmation (yes/no), and yes can feed them automatically.

Exemple avec rm (supprimer)

yes | rm -ri /tmp/test

Cela supprime récursivement et interactivement /tmp/test, en répondant automatiquement "y" à chaque confirmation.

Exemple avec apt-get

yes | apt-get install mon_paquet

Répond "y" à toutes les questions de confirmation d'apt-get. Notez que cela peut être dangereux pour certaines opérations.

Exemple avec cp (copier)

yes | cp -i fichier.txt destination/

L'option -i de cp demande une confirmation avant d'écraser. yes fournit automatiquement cette confirmation.

3. Répondre autre chose que "y"

On peut passer n'importe quelle chaîne de texte à yes :

yes "Je confirme"
yes "OK"
yes "oui" | commande_interactive

4. Limiter le nombre de répétitions

Bien que yes produise une sortie infinie par défaut, on peut la limiter avec une redirection ou head :

yes | head -n 10

Esto produces only 10 lines of "y".

yes "OK" | head -n 5

Produces 5 lines containing "OK".

5. Générer du contenu pour les tests

yes est très utile pour créer rapidement des fichiers de test ou générer des données volumineuses :

Créer un fichier avec des lignes répétées

yes "Ligne de test" | head -n 100 > test.txt

Crée un fichier test.txt contenant 100 lignes "Ligne de test".

Générer un fichier de données volumineux

yes "data" | head -c 1M > fichier_1Mo.dat

Génère un fichier de 1 Mo rempli de "data". Utile pour tester la gestion de gros fichiers.

Remplir un disque avec des zéros (ou presque)

yes | dd of=/dev/zero bs=1M count=100 2>/dev/null

Bien que /dev/zero soit plus approprié pour des zéros purs, yes fonctionne aussi pour des tests de remplissage.

6. Combiner avec xargs pour des opérations en masse

Approuver toutes les suppressions

find /tmp -name "*.tmp" -print0 | xargs -0 rm -i

Pour que cette commande soit automatique, combinez avec yes :

yes | find /tmp -name "*.tmp" -exec rm -i {} +

Valider toutes les demandes de confirmation

yes | xargs -I {} commande {}

7. Exemples concrets

Forcer la suppression de plusieurs fichiers

yes | rm -i *.log

Supprime tous les fichiers .log en répondant "y" à chaque demande.

Générer un fichier CSV de test

yes "id,name,email" | head -n 5 > test.csv

Créer un fichier avec des caractères répétés

yes "=" | head -n 40 | tr -d '\n' > line.txt

Creates a line of 40 equal signs without a trailing newline.

Test de performance d'écriture disque

yes "test" | head -c 100M > /tmp/test_perf.dat && rm /tmp/test_perf.dat

Alimentation d'un tube (pipe) en continu

yes "ping" | nc -l -p 1234

Envoie "ping" en boucle vers un serveur NetCat en écoute.

Script de déploiement automatisé

#!/bin/bash # Script de déploiement avec validations automatiques yes | ./deploy.sh

8. Options de yes

OptionDescription
yes [chaîne]Affiche la chaîne en boucle (défaut : "y")
--helpAffiche l'aide et quitte
--versionAffiche la version et quitte

9. yes vs autres approches

MéthodeUsageQuand l'utiliser
yes | cmdRépondre "y" à toutAutomatiser les confirmations
cmd <<< "y"Répondre une seule foisUne seule confirmation nécessaire
echo "y" | cmdRépondre "y" via pipeAlternative simple
cmd --assume-yesOption nativeSi la commande le supporte (apt, yum...)

10. Erreurs fréquentes

  • Utiliser yes sans limitation et saturer le disque — yes peut remplir un disque très rapidement si redirigé sans head. Toujours coupler avec une limite.
  • Oublier de rediriger la sortie — yes sans redirection remplit l'écran de "y". Utilisez yes | head -n N pour contrôler.
  • Confondre avec echo — echo affiche une fois, yes affiche en boucle infinie.
  • Utiliser sur des systèmes de fichiers en production — La génération de gros volumes de données peut saturer l'espace disque.
  • Ne pas vérifier le contenu généré — Assurez-vous que le texte répété correspond bien à ce que la commande attend.

11. Bonnes pratiques

  • Toujours coupler yes avec head -n quand vous redirigez vers un fichier pour éviter de saturer le disque.
  • Privilégiez les options natives comme --yes ou -y quand elles existent dans la commande (ex : apt-get install -y).
  • Dans un script de déploiement, préférez yes | ./script.sh plutôt que de modifier le script lui-même.
  • Pour les tests de performance, utilisez /dev/zero si vous avez besoin de zéros, c'est plus rapide et plus propre.
  • Créez des fichiers de test réalistes en combinant yes avec head et tr selon vos besoins.
  • Dans les pipelines, yes peut servir à alimenter une commande qui attend une entrée en continu.
