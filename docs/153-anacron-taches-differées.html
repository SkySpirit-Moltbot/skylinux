Anacron — Exécuter des tâches sur des systèmes non-permanents

Introduction

Si cron est parfait pour les serveurs qui tournent 24h/24, que se passe-t-il quand votre ordinateur ou serveur est éteint au moment où une tâche était programmée ? C'est là qu'intervient anacron (anachronistic cron).

Anacron garantit que vos tâches planifiées seront exécutées quand le système sera disponible, pas seulement à un moment précis. C'est l'outil idéal pour les ordinateurs portables, les postes de travail, ou tout système qui n'est pas allumé en continu.

Différence entre cron et anacron

Caractéristiquecronanacron
Exécution précise à l'heure✅ Oui❌ Non
Exécute si le système était éteint❌ Non✅ Oui
Utilisé surServeurs 24/7Postes de travail, laptops
Fréquence minimaleMinutesJours

Installation

Sur la plupart des systèmes, anacron est déjà installé. Vérifiez :

which anacron

Si absent, installez-le :

# Debian/Ubuntu sudo apt install anacron # Fedora/RHEL sudo dnf install anacron

Fichier de configuration principal

Le fichier de configuration d'anacron se trouve dans /etc/anacrontab. Seul root peut le modifier :

sudo nano /etc/anacrontab

Format des entrées

Chaque ligne suit ce format :

PÉRIODE DÉLAI IDENTIFIANT COMMANDE
  • PÉRIODE : Fréquence d'exécution en jours (1 = quotidien, 7 = hebdomadaire, @monthly = mensuel)
  • DÉLAI : Minutes à attendre après le démarrage avant d'exécuter (évite de surcharger au démarrage)
  • IDENTIFIANT : Nom unique pour cette tâche (pour les logs)
  • COMMANDE : La commande ou script à exécuter

Exemple de fichier /etc/anacrontab

# Format: PÉRIODE DÉLAI IDENTIFIANT COMMANDE # Nettoyage des logs tous les jours, 10 min après démarrage 1 10 cleanup-logs /home/david/scripts/nettoyer-logs.sh # Mise à jour de la base locate chaque semaine, 5 min après démarrage 7 5 updatedb /usr/bin/updatedb # Sauvegarde mensuelle, 15 min après démarrage @monthly 15 backup-home /home/david/scripts/backup.sh

Les délais (delay field)

Le champ délai est crucial pour éviter de surcharger le système au démarrage. Voici quelques exemples :

DélaiUsage typique
5-10 minutesTâches légères (nettoyage, mise à jour index)
15-30 minutesTâches moyennes (sauvegardes, sync)
60+ minutesTâches lourdes (compilation, gros backups)

Fichier de spool (suivi des exécutions)

Anacron conserve un historique des exécutions dans /var/spool/anacron/ :

ls -la /var/spool/anacron/
# Voir le contenu (date de dernière exécution) cat /var/spool/anacron/cleanup-logs

Ces fichiers contiennent uniquement la date de dernière exécution de chaque tâche. Anacron les compare avec la période pour décider s'il faut réexécuter.

Gestion du service anacron

Vérifier le statut

# systemd sudo systemctl status anacron # ou ps aux | grep anacron

Démarrer/Arrêter/Redémarrer

sudo systemctl start anacron sudo systemctl stop anacron sudo systemctl restart anacron

Désactiver anacron (si besoin)

# Désactiver au démarrage sudo systemctl disable anacron # Ou commenter les lignes dans /etc/anacrontab

Logs d'anacron

Les traces sont généralement dans /var/log/syslog ou /var/log/anacron selon la distribution :

# Voir les logs anacron grep anacron /var/log/syslog # Sur certaines distributions sudo cat /var/log/anacron

Créer un script pour anacron

Créez d'abord votre script, puis ajoutezz-le à anacron. Voici un exemple complet :

1. Créer le script

mkdir -p ~/scripts nano ~/scripts/nettoyer-logs.sh
#!/bin/bash # Nettoyer les anciens fichiers log de ~/logs/ LOGDIR="$HOME/logs" JOURS=7 if [ -d "$LOGDIR" ]; then find "$LOGDIR" -name "*.log" -mtime +$JOURS -delete echo "$(date): Nettoyage des logs de plus de $JOURS jours terminé" >> ~/logs/cleanup.log else echo "Répertoire $LOGDIR non trouvé" exit 1 fi
# Rendre exécutable chmod +x ~/scripts/nettoyer-logs.sh

2. L'ajouter à anacron

sudo nano /etc/anacrontab

Ajoutez cette ligne :

7 15 clean-logs /home/david/scripts/nettoyer-logs.sh

Tester anacron

Forcer l'exécution manuelle

# Exécuter une tâche spécifique (avec sudo) sudo anacron -f -n cleanup-logs # -f : forcer l'exécution (ignorer la date) # -n : exécuter maintenant (ignorer le délai)

Vérifier le fonctionnement

# Simuler sans exécuter sudo anacron -T # Mode verbeux (debug) sudo anacron -d -f -n

Bonnes pratiques

  • Gardez les délais courts : Anacron ne devrait pas gêner l'utilisation normale. 5-15 minutes suffisent généralement.
  • Scripts idempotents : Vos scripts doivent pouvoir être exécutés plusieurs fois sans effet néfaste.
  • Logs dans les scripts : Ajoutez des messages de log pour suivre ce qui se passe.
  • Chemins absolus : Utilisez toujours des chemins absolus dans vos scripts.
  • Droits appropriés : Les scripts lancés par anacron s'exécutent avec les droits de root (par défaut).

Configuration pour utilisateurs (anacron local)

Si vous êtes sur un système où vous n'avez pas accès root, vous pouvez créer votre propre configuration utilisateur. Certains systèmes supportent ~/.anacrontab :

# Créer un anacron utilisateur (si supporté) mkdir -p ~/.local/share/anacron echo "1 10 mon-tache ~/scripts/ma-tache.sh" > ~/.anacrontab # Lancer avec anacron -s -c ~/.anacrontab

Note : Cette fonctionnalité dépend de la distribution et des droits disponibles.

Résumé

  • Anacron exécute les tâches planifiées même si le système était éteint
  • Configuration dans /etc/anacrontab
  • Format : PÉRIODE DÉLAI IDENTIFIANT COMMANDE
  • Idéal pour les postes de travail et laptops
  • Historique des exécutions dans /var/spool/anacron/
  • Combinez avec cron pour une couverture complète (cron pour les tâches temps réel, anacron pour les tâches quotidiennes)
