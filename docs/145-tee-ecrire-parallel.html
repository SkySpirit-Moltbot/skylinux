Leçon 145 : tee — Écrire simultanément dans un fichier et vers une autre commande

tee est une commande qui lit depuis l'entrée standard et écrit simultanément dans la sortie standard et dans un ou plusieurs fichiers. Son nom vient de la forme en "T" du tuyau de plomberie : les données entrent d'un côté et sortent dans deux directions.

Pourquoi tee est essentiel

  • Logging : voir la sortie d'une commande ET la sauvegarder dans un fichier
  • Pipeline transparent : inspecter les données qui traversent un pipe
  • Debug : déboguer un pipeline sans le casser
  • Archivage : capturer la sortie de commandes longue sans知道她
  • Installation : visualiser ET enregistrer le résultat d'une installation

Syntaxe de base

commande | tee [OPTIONS] FICHIER...

Installation

tee fait partie du paquet coreutils et est installé par défaut sur toutes les distributions Linux. Aucune installation nécessaire.

Options principales

OptionDescription
-a, --appendAjouter à la fin du fichier au lieu de l'écraser
-i, --ignore-interruptsIgnorer les signaux d'interruption
-pDiagnostiquer les erreurs lors de l'écriture dans les pipes
--output-error[=MODE]Comportement en cas d'erreur d'écriture (warn, exit, etc.)

Exemples fondamentaux

Écrire dans un fichier ET afficher à l'écran

# Voir la sortie ET la sauvegarder
echo "Bonjour le monde" | tee salut.txt
# Affiche : Bonjour le monde
# Contenu de salut.txt : Bonjour le monde

Écraser un fichier

# Par défaut, tee écrase le fichier
ls -la / | tee liste.txt

Ajouter à un fichier (append)

# Ajouter au lieu d'écraser
echo "Première ligne" | tee log.txt
echo "Deuxième ligne" | tee -a log.txt
echo "Troisième ligne" | tee -a log.txt
cat log.txt
# Première ligne
# Deuxième ligne
# Troisième ligne

Écrire dans plusieurs fichiers

# Écrire dans plusieurs fichiers en une seule passe
echo "Données importantes" | tee fichier1.txt fichier2.txt fichier3.txt

Exemples pratiques

Logger une installation

# Enregistrer et visualiser une installation
sudo apt install nginx | tee install_nginx.log
# Vous voyez la sortie en temps réel
# ET le fichier install_nginx.log contient tout

Logger un script

#!/bin/bash
# Exécuter un script et logger la sortie
./mon_script.sh 2>&1 | tee sortie.log
# 2>&1 redirige stderr vers stdout pour tout capturer

Capturer la sortie de make

# Compiler et garder le log
make 2>&1 | tee build.log
# En cas d'erreur, le log contient tout pour le debug

Pipeline de debug

# Inspecter ce qui passe dans un pipeline
cat data.csv | tee /tmp/debug.txt | sort | uniq
# Vous voyez les données originales
# /tmp/debug.txt contient les données avant tri

Archivage de la sortie système

# Capturer la sortie de plusieurs commandes
{
echo "=== RAPPORT SYSTÈME ==="
echo "Date : $(date)"
echo ""
echo "=== MÉMOIRE ==="
free -h
echo ""
echo "=== DISQUE ==="
df -h
} | tee rapport_systeme.txt

Pipeline sudo

# Écrire dans un fichier protégé avec sudo
echo "configuration" | sudo tee /etc/mon_service/config.conf
# Alternative sans tee (moins élégant) :
echo "configuration" | sudo dd of=/etc/mon_service/config.conf

Ajouter sudo pour l'écriture

#tee ne peut pas lire sudo pour l'entrée,
#mais peut écrire la sortie avec sudo
# Écrire dans un fichier root-owned
commande | sudo tee /var/log/mon_log.log > /dev/null
# Le > /dev/null empêche l'affichage de la sortie

Combinaisons avancées

Avec xargs

# Créer plusieurs fichiers à partir d'une liste
echo -e "fichier1.txt\nfichier2.txt\nfichier3.txt" | xargs -I {} tee {} <<< "Contenu initial"

Avec des sous-shells

# Capturer plusieurs sorties groupées
(
echo "=== HEURE ===" ; date
echo "=== UTILISATEURS ===" ; who
echo "=== PROCESSUS ===" ; ps aux | head -5
) | tee -a journal_quotidien.txt

Avec grep pour filtrer ET存档

# Garder les lignes contenant "error" ET voir toute la sortie
commande | tee /tmp/sortie_complete.txt | grep "error"
# /tmp/sortie_complete.txt contient tout
# grep affiche uniquement les erreurs (sans vider le pipe)

Double tee (pipeline en T)

# Écrire à deux endroits différents
commande | tee fichier1.txt | tee fichier2.txt | wc -l
# Les deux fichiers reçoivent la même sortie

Archiver et envoyer vers un pipe

# Archiver ET continuer le traitement
curl http://api.exemple.com/donnees | tee /tmp/cache.json | jq '.resultats'

Cas d'utilisation réels

Script d'installation avec log

#!/bin/bash
# Script d'installation qui log tout
LOG="install_$(date +%Y%m%d_%H%M%S).log"
exec > >(tee -a "$LOG") 2>&1
echo "=================================="
echo "Installation начало $LOG"
echo "=================================="
# Toutes les sorties sont automatiquement loggées
apt update
apt install -y nginx postgresql
echo "Installation terminée !"

Sauvegarde avec tee

#!/bin/bash
# Créer une sauvegarde et garder un historique
SOURCE="/home/david/documents"
BACKUP="/media/backup/sauvegarde_$(date +%Y%m%d).tar.gz"
LISTE="/media/backup/liste_fichiers.txt"
# Lister les fichiers et archiver en parallèle
tar -czf "$BACKUP" "$SOURCE" 2>&1 | tee "$LISTE"
echo "Sauvegarde créée : $BACKUP"
echo "Liste enregistrée : $LISTE"

Surveillance en temps réel

#!/bin/bash
# Surveiller un log en temps réel et l'archiver
tail -f /var/log/syslog | tee /tmp/syslog_capture.txt
# Vous voyez les logs défiler ET ils sont sauvegardés

Pipeline de traitement de données

# Traiter des données, garder une trace, et continuer
cat data.csv | tee raw_data.csv | sort | uniq > cleaned_data.csv

Comparaison avec d'autres commandes

Bonnes pratiques

  • Utilisez 2>&1 | tee pour capturer stdout et stderr
  • Utilisez -a pour ajouter au lieu d'écraser lors des logs successifs
  • Redirigez vers /dev/null avec > /dev/null si vous ne voulez que le fichier
  • Combinez avec sudo tee pour écrire dans des fichiers protégés
  • Pour des logs automatiques, utilisez exec > >(tee -a logfile) 2>&1 au début d'un script
  • Vérifiez le code de retour du pipeline car tee peut échouer silencieusement

Résumé

tee est l'outil idéal pour dupliquer un flux de données : il affiche tout ce qui passe ET l'enregistre simultanément. Utilisez-le pour le logging, le debug de pipelines, l'archivage de sorties, ou simplement pour garder une trace de ce que fait une commande sans perdre la visibilité en temps réel.
