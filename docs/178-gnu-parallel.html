GNU parallel — Exécuter des commandes en parallèle

Introduction

Vous avez une liste de 100 fichiers à traiter, une commande à exécuter sur 50 serveurs, ou des milliers d'opérations indépendantes à effectuer ? Les faire une par une prendrait des heures. GNU parallel vous permet d'exécuter ces tâches en parallèle, en utilisant tous les cœurs de votre processeur.

Imaginez : au lieu de traiter 100 images une par une en 10 minutes, parallel les traite toutes en parallèle et termine en quelques secondes.

Installation

sudo apt install parallel # Debian/Ubuntu
sudo dnf install parallel # Fedora
sudo pacman -S parallel # Arch Linux

Le concept de base

parallel prend des entrées (sur stdin, depuis un fichier, ou depuis des arguments) et exécute une commande pour chaque entrée, en parallèle. Par défaut, il utilise autant de jobs que vous avez de cœurs CPU.

# Syntaxe générale parallel "commande {}" ::: argument1 argument2 argument3

Le symbole {} représente l'argument courant. D'autres placeholders existent :

PlaceholderDescription
{}L'argument entier
{.}L'argument sans extension
{/}Juste le nom du fichier (sans chemin)
{//}Juste le répertoire
{/.}Nom du fichier sans extension

Premiers exemples

Exemple 1 : traiter plusieurs fichiers

Compresser 4 fichiers avec gzip en parallèle :

parallel gzip {} ::: fichier1.txt fichier2.txt fichier3.txt fichier4.txt

Cela lancera 4 processus gzip simultanément.

Exemple 2 : lire depuis un fichier

# Créer une liste de serveurs echo -e "serveur1\nserveur2\nserveur3" > serveurs.txt # Pinguer tous les serveurs en parallèle parallel -a serveurs.txt ping -c 1 {}

Exemple 3 : utiliser un pipe

cat servers.txt | parallel ping -c 1 {}

Exemple 4 : traiter des fichiers d'un répertoire

# Compresser tous les fichiers .log du répertoire courant ls *.log | parallel gzip # Redimensionner toutes les images avec ImageMagick ls *.jpg | parallel convert {} -resize 800x600 {.}_800.jpg

Contrôler le nombre de jobs

Par défaut, parallel utilise autant de jobs que de cœurs CPU. Vous pouvez ajuster avec -j :

# Utiliser seulement 2 jobs simultanés parallel -j 2 gzip {} ::: fichier1.txt fichier2.txt fichier3.txt # Utiliser la moitié des cœurs parallel -j 50% gzip {} ::: *.txt # Travailler séquentiellement (1 job à la fois) parallel -j 1 gzip {} ::: *.txt

Quand utiliser peu de jobs ?

  • Les tâches utilisent beaucoup de RAM
  • Les tâches font des accès disque intensifs
  • Vous voulez laisser de la puissance pour autre chose
  • Les tâches écrivent dans le même fichier

Options utiles

-n : nombre d'arguments par commande

# Traiter 2 arguments à la fois parallel -n 2 echo "Fichiers:" {} {} ::: fichier1.txt fichier2.txt fichier3.txt

--dry-run : voir sans exécuter

# Afficher les commandes sans les exécuter parallel --dry-run gzip {} ::: *.txt

-v : mode verbeux

# Afficher les commandes au fur et à mesure parallel -v gzip {} ::: *.txt

--bar : barre de progression

parallel --bar gzip {} ::: *.txt

--eta : temps restant estimé

parallel --eta gzip {} ::: *.txt

--halt onerr : arrêter en cas d'erreur

# Arrêter si une commande échoue parallel --halt onerr gzip {} ::: *.txt # Arrêter si plus de 2 commandes échouent parallel --halt now,fail=2 gzip {} ::: *.txt

Utiliser plusieurs sources d'arguments

Vous pouvez combiner plusieurs sources d'arguments. Elles seront combinées de différentes façons avec :::+ et :::.

Produit cartésien (toutes les combinaisons)

# Exécuter gzip sur fichier1.txt et fichier2.txt AVEC serveur1 et serveur2 # = 4 combinaisons parallel echo "Compresser {} vers {}" ::: fichier1.txt fichier2.txt ::: serveur1 serveur2

Arguments correspondants (:::+)

# Associer les arguments un à un parallel echo "Traitement: {} -> {}" ::: input1.txt input2.txt :::+ output1.txt output2.txt

Avec :::+, le premier argument de la première liste est combiné avec le premier argument de la seconde liste, etc.

Placeholders avancés

# Avec un fichier /home/user/photos/vacances.jpg # {} = /home/user/photos/vacances.jpg # {.} = /home/user/photos/vacances # {/} = vacances.jpg # {//} = /home/user/photos # {/.} = vacances # Créer une miniature ls /home/user/photos/*.jpg | parallel convert {} -resize 200x200 {/.}_thumb.jpg

Redirections et sortie

Sortie dans l'ordre des arguments

Par défaut, la sortie peut apparaître dans le désordre (selon l'ordre de terminaison des jobs). Pour forcer l'ordre :

parallel --keep-order gzip {} ::: *.txt

Regrouper la sortie

# Grouper la sortie par argument parallel --group echo "Résultat de {}:" {} ::: A B C

Rediriger stdout et stderr séparément

parallel "commande {}" ::: *.txt > resultats.txt 2> erreurs.txt

Identifier la source dans la sortie

parallel --tag echo "{} traité" ::: *.txt

Scripts et fonctions

Utiliser une fonction bash

#!/bin/bash # Définir une fonction convert_image() { convert "$1" -resize 800x600 "${1%.jpg}_800.jpg" } export -f convert_image # Appeler la fonction avec parallel ls *.jpg | parallel convert_image

Script externe

# script.sh #!/bin/bash echo "Traitement de $1" gzip "$1" # Rendre exécutable chmod +x script.sh # L'appeler depuis parallel parallel ./script.sh {} ::: *.txt

Exemple concret : redimensionner des images

# Créer 100 images de test mkdir -p photos for i in $(seq 1 100); do convert -size 4000x3000 xc:blue photos/image_$i.jpg; done # Redimensionner en parallèle (4 jobs simultanés pour préserver la RAM) parallel -j 4 convert {} -resize 800x600 {.}_small.jpg ::: photos/*.jpg echo "100 images redimensionnées en parallèle !"

Exemple concret : pinguer plusieurs serveurs

# Liste de serveurs à tester echo -e "google.com\ngithub.com\nwikipedia.org\ncloudflare.com" > servers.txt # Pinguer tous les serveurs en parallèle et afficher le temps moyen cat servers.txt | parallel -j 4 "ping -c 3 {} | tail -1"

Exemple concret : téléchargement parallèle

# Télécharger plusieurs fichiers en parallèle parallel curl -O {} ::: \ https://example.com/fichier1.zip \ https://example.com/fichier2.zip \ https://example.com/fichier3.zip

Exemple concret : backup sur plusieurs machines

# Lancer rsync sur plusieurs serveurs en parallèle echo -e "serveur1:/backup\nserveur2:/backup\nserveur3:/backup" > destinations.txt cat destinations.txt | parallel rsync -av /home/data/ {}

Combiner avec xargs

parallel est souvent comparé à xargs, mais il est plus puissant :

# Avec xargs (séquentiel par défaut) ls *.txt | xargs gzip # Avec parallel (parallèle) ls *.txt | parallel gzip # parallel peut aussi remplacer xargs : ls *.txt | parallel -X xargs-like gzip

Limiter la bande passante avec --rate

# Limiter à 1MB/s par job (utile pour ne pas saturer le réseau) parallel --rate 1M curl -O {} ::: https://example.com/file1 https://example.com/file2

Bonnes pratiques

  • Commencez prudemment : lancez avec --dry-run pour vérifier
  • Surveillez la mémoire : trop de jobs simultanés peut épuiser la RAM
  • Vérifiez l'ordre de sortie : utilisez --keep-order si l'ordre compte
  • Utilisez --bar ou --eta pour suivre la progression sur des tâches longues
  • Mettez les chemins entre quotes si vos fichiers ont des espaces
  • Testez avec peu d'arguments avant de lancer sur des centaines

GNU parallel est un outil essentiel pour quiconque travaille avec de grandes quantités de tâches indépendantes. Que ce soit pour le traitement d'images, les sauvegardes, les téléchargements ou l'administration de serveurs, il transforme des heures de travail séquentiel en minutes de traitement parallèle.
