Leçon 151 : at — Planifier une tâche unique

at permet d'exécuter des commandes à une heure précise, une seule fois. Contrairement à cron qui répète des tâches périodiquement, at est idéal pour planifier une action ponctuelle dans le futur : un redémarrage différé, un rapport à générer demain matin, ou une alerte à une heure précise.

Installation

at n'est pas toujours installé par défaut. Vérifiez d'abord :

which at

Si absent, installez-le :

# Debian/Ubuntu sudo apt install at # Fedora/RHEL sudo dnf install at # Arch Linux sudo pacman -S at

Ensuite, activez et démarrez le service atd :

sudo systemctl enable --now atd

Syntaxe de base

at [options] heure [date]

Après avoir entré la commande, at ouvre un interpréteur où vous tapez les commandes à exécuter. Terminez par Ctrl+D.

Formats d'heure

at comprend de nombreux formats :

FormatExempleDescription
HH:MM14:30Heure au format 24h (aujourd'hui si déjà passée → demain)
HH:MM JJ/MM09:00 25/12Date au format jour/mois
HH:MM JJ.MM.AAAA10:00 01.01.2027Date complète avec année
midnightat midnightMinuit (00:00)
noonat noonMidi (12:00)
teatimeat teatime16:00 (l'heure du thé !)
now + X minutes/heurs/days/weeksat now + 2 hoursDans un délai précis
tomorrowat 09:00 tomorrowDemain à l'heure indiquée
AM / PM3pmFormat 12h (sans espace)

Exemples pratiques

1. Planifier une commande simple

at 14:30

L'interpréteur at s'ouvre. Tapez vos commandes :

at> echo "Il est 14h30 !" >> ~/rapports/alerte.txt at> job 1 at Mon Sep 21 14:30 2026

2. Planifier avec un délai relatif

# Dans 1 heure at now + 1 hour # Dans 30 minutes at now + 30 minutes # Dans 3 jours at now + 3 days # Dans 2 semaines at now + 2 weeks

3. Planifier à une date précise

# 25 décembre à 8h at 08:00 25/12 # 1er janvier 2027 à minuit at midnight 01.01.2027 # Demain à 7h at 07:00 tomorrow

4. Lire la commande depuis un fichier

Au lieu de taper交互ivement, envoyez un script :

at 06:00 tomorrow < ~/scripts/backup-quotidien.sh

5. Planifier avec un here-document

at 20:00 <

6. Planifier une commande en une seule ligne avec pipe

echo "systemctl reboot" | at 03:00 tomorrow

Options utiles

OptionDescription
-f fichierLire les commandes depuis un fichier
-mEnvoyer un email même si la commande ne produit rien
-MNe jamais envoyer d'email
-vAfficher la date d'exécution prévue
-c jobAfficher le contenu d'un job at (par PID)
-lLister les jobs en attente (équivalent à atq)
-d jobSupprimer un job (équivalent à atrm)
-q queueUtiliser une file d'attente spécifique (a-z, A-Z)

Gérer les jobs

Lister les jobs en attente

at -l # ou atq

Sortie :

3 Mon Sep 21 18:00 a root 4 Tue Sep 22 07:00 a root

Colonnes : PID, date/heure d'exécution, file, utilisateur.

Voir le contenu d'un job

at -c 3

Supprimer un job

at -d 3 # ou atrm 3

Files d'attente (queues)

Par défaut, at utilise la file a. Vous pouvez utiliser les files a à z (et A à Z) pour isoler ou prioriser vos jobs.

# File 'b' — haute priorité at -q b 09:00 tomorrow # File 'z' — basse priorité at -q z 20:00

Restreindre l'accès

Par défaut, seul root peut utiliser at. Pour autoriser d'autres utilisateurs, utilisez deux fichiers :

  • /etc/at.allow : liste blanche — si ce fichier existe, seuls les utilisateurs listés peuvent utiliser at
  • /etc/at.deny : liste noire — si at.allow n'existe pas, les utilisateurs listés dans at.deny sont interdits
# Interdire l'utilisateur 'guest' d'utiliser at echo "guest" | sudo tee /etc/at.deny

Exemples concrets

Redémarrage différé

# Redémarrer le serveur demain à 3h du matin echo "systemctl reboot" | at 03:00 tomorrow

Nettoyage de fichiers temporaires

# Vider le cache demain à 5h at 05:00 tomorrow <

Rapport quotidien différé

# Générer un rapport à 8h chaque matin (script externe) at 08:00 tomorrow -f ~/scripts/rapport-quotidien.sh

Éteindre le PC le soir

# Éteindre à 23h at 23:00 <

Notification par email

# Avec notification email (si MTA configuré) at -m 10:00 next monday <

Vérifier l'exécution

Les jobs at s'exécutent même si vous êtes déconnecté. Les résultats sont envoyés par email à l'utilisateur. Vérifiez votre boîte mail locale :

mail

Ou redirigez la sortie explicitement :

at 18:00 < ~/logs/rapport-$(date +\%Y\%m\%d).log 2>&1 EOF

Différence entre at, cron et batch

OutilUsageRépétition
atUne tâche ponctuelle à une heure préciseUne seule fois
cronTâches régulières (quotidiennes, hebdomadaires…)Périodique
batchTâche exécutée quand la charge le permetUne seule fois

Résumé

at est l'outil idéal pour planifier des tâches uniques sans configurer un fichier cron. Il suffit d'une heure et d'une commande.

CommandeUsage
at 14:30Planifier à 14h30
at now + 2 hoursDans 2 heures
at midnight 25/12Noël à minuit
at -f script.sh 08:00Exécuter un script à 8h
at -lLister les jobs
at -d 3Supprimer le job 3
at -c 3Voir le contenu du job 3
