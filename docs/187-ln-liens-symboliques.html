187. ln — Liens symboliques et liens durs

Vous avez besoin qu'un fichier ou dossier soit accessible à plusieurs endroits sans le dupliquer ? La commande ln crée des liens — des références supplémentaires vers un même fichier sur le disque. C'est un outil fondamental pour organiser vos fichiers sous Linux.

Pourquoi utiliser des liens ?

Imaginons que vous ayez un projet dans /home/user/projet/ et que vous vouliez y accéder rapidement depuis votre bureau. Vous avez deux solutions :

  • Copier le fichier — consomme de l'espace supplémentaire et diverge avec le temps
  • Créer un lien — une référence qui pointe vers le fichier original, sans duplication

Les deux types de liens

Lien dur (hard link)

Un lien dur est un second nom pour le même inode (la structure interne qui représente le fichier). Le fichier et son lien sont indiscernables pour le système.

Lien symbolique (symlink)

Un lien symbolique est un fichier spécial qui contient le chemin vers un autre fichier. Il fonctionne comme un raccourci : si le fichier cible est supprimé, le lien symbolique devient "cassée".

Créer un lien symbolique

ln -s fichier_original lien_symbolique

Exemple concret

# Créer un lien symbolique vers un fichier ln -s /home/user/documents/rapport.pdf ~/Bureau/rapport.pdf # Créer un lien symbolique vers un répertoire ln -s /var/log /home/user/log-système # Créer un lien avec un nom différent ln -s /opt/application ~/mon-app

Visualiser les liens

ls -la ~/Bureau/

La sortie affiche le lien avec une flèche (->) qui montre sa cible :

lrwxrwxrwx 1 user user 38 oct 27 08:00 rapport.pdf -> /home/user/documents/rapport.pdf

解读一下权限栏位：l au début indique un lien symbolique. La taille (38) correspond à la longueur du chemin cible, pas à la taille du fichier.

Créer un lien dur

ln fichier_original lien_dur

Exemple

# Créer un lien dur vers un fichier ln /home/user/documents/data.csv /home/user/backup/data.csv # Vérifier que c'est bien le même inode ls -li /home/user/documents/data.csv /home/user/backup/data.csv

Les deux fichiers affichent le même numéro d'inode, ce qui confirme qu'ils pointent vers la même donnée sur le disque.

Lien dur vs lien symbolique : lequel choisir ?

CaractéristiqueLien durLien symbolique
Cross-filesystemNon (même partition)Oui (chemin absolu ou relatif)
Vers répertoireNon (dangereux)Oui
Si cible suppriméeFichier toujours accessibleLien "cassée" (orphelin)
VisibilitéInvisible pour l'utilisateurFichier spécial avec ->
InodeMême inode que l'originalInode différent
PerformanceLégèrement plus rapideLégèrement plus lent (un redirect)

Quand utiliser le lien dur ?

  • Faire des sauvegardes rapides sans copier les données
  • Permettre à plusieurs utilisateurs d'accéder au même fichier sous des noms différents
  • Économiser de l'espace pour des fichiers volumineux utilisés à plusieurs endroits

Quand utiliser le lien symbolique ?

  • Créer des raccourcis vers des fichiers ou répertoires
  • Pointer vers un fichier sur une autre partition
  • Simplifier des chemins longs ou complexes
  • Déployer des configurations partagées

Atelier pratique : organiser votre projet

Étape 1 — Structure initiale

mkdir -p ~/projet/src ~/projet/docs echo "Code source du projet" > ~/projet/src/main.py echo "Documentation" > ~/projet/docs/README.txt

Étape 2 — Créer des liens pour un accès rapide

# Lien vers le code source sur le bureau ln -s ~/projet/src ~/Bureau/code-projet # Lien vers la documentation ln -s ~/projet/docs/README.txt ~/Bureau/readme-projet.txt # Vérifier ls -la ~/Bureau/

Étape 3 — Utiliser un lien symbolique pour une configuration

Si vous avez une configuration dans votre dossier personnel qui doit aussi être utilisée par un service :

# Créer un lien symbolique pour que le service accède à votre config sudo ln -s /home/user/.config/mon-app.conf /etc/mon-app.conf # Redémarrer le service pour prendre en compte sudo systemctl restart mon-app

Étape 4 — Vérifier que tout fonctionne

# Lire le fichier via le lien symbolique cat ~/Bureau/readme-projet.txt # Vérifier que le lien n'est pas cassé test -e ~/Bureau/code-projet && echo "OK" || echo "Lien cassé"

Créer des liens symboliques relatifs vs absololus

Lien absolu

ln -s /home/user/documents/fichier.txt ~/lien.txt

Le lien contient le chemin complet. Il fonctionne tant que la cible existe à cet endroit.

Lien relatif

cd ~/Bureau ln -s ../documents/fichier.txt lien-relatif.txt

Le lien contient un chemin relatif. Il reste valide si vous déplacez tout le répertoire (à condition que la structure relative soit préservée).

Quelle option choisir ?

  • Absolu : plus simple à comprendre, plus prévisible
  • Relatif : plus portable, fonctionne après un déplacement de l'arborescence

Atelier pratique : versioning avec des liens

Imaginons que vous avez plusieurs versions d'un projet et voulez toujours accéder à la dernière :

# Structure avec versions mkdir -p ~/projets/monapp/v1.0 ~/projets/monapp/v2.0 ~/projets/monapp/v3.0 # Créer un lien "latest" qui pointe toujours vers la dernière version ln -sfn ~/projets/monapp/v3.0 ~/projets/monapp/latest # L'option -n fait que si "latest" existe déjà, il est remplacé # Sans -n, ln -s créerait un fichier "latest" dans le répertoire cible

Options utiles de ln

OptionDescription
-sCréer un lien symbolique (par défaut : lien dur)
-fForcer l'écrasement si le lien existe déjà
-nTreat destination as a normal file if it is a symbolic link to a directory
-iDemander confirmation avant d'écraser
-vMode verbeux : afficher ce qui est créé

Résoudre les problèmes courants

Le message "Too many levels of symbolic links"

Cela signifie que vous avez un lien symbolique qui pointe en boucle. Vérifiez :

# Trouver où pointe le lien readlink lien-probleme # Résoudre le lien symbolique récursivement readlink -f lien-probleme

Le lien symbolique est cassé après un déplacement

Si vous avez déplacé un fichier cible, le lien symbolique ne fonctionne plus. Vous pouvez :

  • Recréer le lien vers le nouvel emplacement
  • Pointer vers un chemin absolue plutôt que relatif
# Recréer le lien rm ancien-lien ln -s /nouveau/chemin/fichier.txt ancien-lien

Lien vers un fichier qui n'existe pas encore

# Créer d'abord le lien ln -s /chemin/fichier-future.txt lien.txt # Puis créer le fichier cible echo "contenu" > /chemin/fichier-future.txt

Le lien symbolique peut pointer vers une cible qui n'existe pas encore. C'est utile pour préparer une structure avant de créer les fichiers.

Supprimer un lien

Un lien symbolique se supprime comme un fichier ordinaire avec rm :

# Supprimer le lien (pas le fichier cible !) rm lien_symbolique # Supprimer plusieurs liens rm lien1.txt lien2.txt lien3.txt # Vérifier que le fichier original existe toujours ls fichier_original

Cas d'usage réels

Gestion de versions de logiciel

# Installer une nouvelle version sudo ln -sfn /opt/apache-maven-3.9.6 /opt/maven # Maven est maintenant accessible via /opt/maven /opt/maven/bin/mvn --version

Configuration système

# Votre configuration Git dans votre dossier personnel ln -sf ~/dotfiles/.gitconfig ~/.gitconfig # Vos alias bash ln -sf ~/dotfiles/.bash_aliases ~/.bash_aliases

Raccourcis pour des chemins longs

# Raccourcir l'accès à un serveur ln -s /mnt/serveur-fichier/societe/projets/2026/contrats ~/contrats-2026 # Accéder facilement cd ~/contrats-2026

Partager une bibliothèque entre projets

# Partager la même bibliothèque entre deux projets ln -s /usr/local/lib/malib.so ~/projet1/lib.so ln -s /usr/local/lib/malib.so ~/projet2/lib.so

Résumé

CommandeDescription
ln -s source lienCréer un lien symbolique
ln source lienCréer un lien dur
ln -sf source lienRemplacer un lien existant
readlink lienVoir la cible d'un lien symbolique
readlink -f lienRésoudre complètement le lien (suivre les chaînes)
ls -la fichierVoir le type de fichier (l = symlink)
rm lienSupprimer un lien (pas la cible)

Bonnes pratiques

  • Utilisez des liens symboliques pour la plupart des cas (répertoires, cross-filesystem, clarté)
  • Réservez les liens durs aux cas où vous voulez une seconde entrée vers un fichier sans vous préoccuper du lien symbolique
  • Vérifiez toujours que la cible existe avant de créer un lien symbolique
  • Utilisez des chemins absolus pour les liens qui traversent des partitions ou des utilisateurs
  • Documentez vos liens symboliques importants pour ne pas les supprimer par erreur
  • Utilisez -v (mode verbeux) pour comprendre ce que ln fait exactement
