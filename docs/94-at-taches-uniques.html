Leçon 94 — at — Planifier une tâche unique

Qu'est-ce que at ?

at permet de planifier l'exécution d'une commande ou d'un script à un moment précis et unique. Contrairement à cron qui répète des tâches périodiquement, at exécute une seule fois, à l'heure choisie.

C'est idéal pour reporter une tâche lourde à plus tard, envoyer un rappel, ou différer l'exécution d'une commande pendant une période de faible activité.

Installation

Sur la plupart des systèmes, at est déjà installé. Sinon :

# Ubuntu / Debian
sudo apt install at
# Fedora / RHEL / CentOS
sudo dnf install at

Le service atd doit être actif :

sudo systemctl enable --now atd

Syntaxe de base

at [options] HEURE [DATE]

Exemples concrets

1. Planifier une commande pour aujourd'hui à 15h00

at 15:00
# Puis tapez la commande à exécuter :
echo "Rapport généré" >> /var/log/rapport.log
# Tapez Ctrl+D pour valider

2. Planifier avec un script complet

at 17:30
./sauvegarde.sh
tar -czf /backup/donnees_$(date +%Y%m%d).tar.gz /home/donnees
Ctrl+D

3. Exécuter dans 1 heure

at now + 1 hour
echo "Maintenance terminée" | mail -s "Alerte" admin@exemple.com
Ctrl+D

4. Planifier pour demain à 8h00

at tomorrow 08:00
/opt/scripts/nettoyage.sh
Ctrl+D

5. Planifier pour une date précise

at 09:00 25/12/2026
echo "Joyeux Noël !" > /tmp/noel.txt
Ctrl+D

6. En une seule ligne avec un pipe

echo "./script.sh" | at now + 5 minutes

7. Avec la commande -f pour lire depuis un fichier

at 06:00 -f /home/user/scripts/maintenance.sh

Gérer les tâches planifiées

Voir les jobs en attente

atq
# Ou
at -l

La sortie affiche le numéro de job, la date d'exécution et la file d'attente.

Supprimer un job

atrm NUMERO_DU_JOB
# Exemple : supprimer le job n°5
atrm 5

Voir le contenu d'un job

at -c NUMERO_DU_JOB

Options utiles

OptionRôle
-f fichierLire les commandes depuis un fichier
-mEnvoyer un email à l'utilisateur à la fin de l'exécution
-MNe jamais envoyer d'email
-q QUEUESpécifier une file d'attente (a-z, A-Z)
-vAfficher la date d'exécution prévue
-c jobAfficher le contenu d'un job

Files d'attente (queues)

at utilise des files d'attente désignées par des lettres. Par défaut, les jobs at vont dans la file a, et les jobs batch dans la file b.

# Planifier dans une file spécifique
at -q c 15:00 -f script.sh

Configuration et contrôle d'accès

L'accès à at est contrôlé par deux fichiers :

  • /etc/at.allow : liste des utilisateurs autorisés (si le fichier existe)
  • /etc/at.deny : liste des utilisateurs refusés
# Interdire l'accès à tous (sauf root)
sudo touch /etc/at.deny
# Autoriser un utilisateur spécifique
echo "alice" | sudo tee /etc/at.allow

Différence entre at et cron

Caractéristiqueatcron
TypeTâche uniqueTâche répétitive
PersistanceDisparaît après exécutionReste configurée indéfiniment
Cas d'usageAction différée ponctuelleTâches récurrentes (quotidiennes, hebdomadaires...)
ConfigurationCommande interactive ou fichierTable crontab par utilisateur

Bonnes pratiques

  • Utiliser des chemins absolus : le répertoire de travail au moment de l'exécution peut différer, privilégiez /home/user/scripts/mon_script.sh plutôt que ./mon_script.sh
  • Toujours rediriger la sortie : sans redirection explicite, la sortie est envoyée par email à l'utilisateur ou perdue. Ajoutez > /var/log/monjob.log 2>&1
  • Vérifier avant de planifier : testez votre commande manuellement avant de la mettre dans at
  • Combiner avec batch : si vous voulez exécuter quand la charge système est faible, utilisez batch au lieu de at
  • Conserver une trace : notez les jobs planifiés dans un fichier pour suivi

Exemple : rapport quotidien différé

# Planifier un rapport pour demain à 7h00
at tomorrow 07:00 -f /home/admin/rapport_quotidien.sh > /var/log/at_rapport.log 2>&1
# Vérifier que le job est bien planifié
atq

Exemple : rappel dans 30 minutes

echo "echo 'Noublie pas la réunion dans 5 minutes !' | wall" | at now + 25 minutes

at est l'outil idéal pour les tâches à exécuter une seule fois à un moment précis. Pour des actions différées simples sans email ni interaction, il remplace avantageusement un script avec sleep. Pour les tâches récurrentes, cron reste la solution appropriée.
