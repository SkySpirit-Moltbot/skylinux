chroot — Isoler des processus dans un environnement restreint

La commande chroot (change root) permet d'exécuter un programme dans un environnement isolé, en lui faisant croire que la racine du système de fichiers est ailleurs. C'est l'ancêtre de la containerisation, encore utilisé aujourd'hui pour l'isolement et la sécurité.

Principe de fonctionnement

Normalement, sous Linux, la racine / correspond au véritable sommet de l'arborescence. Avec chroot, on substitue mentalement un répertoire arbitraire comme nouvelle racine. Le processus enfermé ne peut pas accéder aux fichiers en dehors de cette cage.

# Syntaxe de base chroot /nouveau/root commande [args]

Cas d'utilisation courants

  • Isoler un service : limiter les dégâts en cas de compromission
  • Réinstaller le chargeur de démarrage : depuis un live CD, chrooter dans le système installé pour réparer GRUB
  • Tests et construction : compiler dans un environnement propre sans polluer le système hôte
  • Environnements de recovery : outils de dépannage qui doivent intervenir sur un système blessé

Préparer un environnement chroot

Un chroot fonctionnel nécessite une arborescence minimale. Voici les ingrédients essentiels :

1. Créer la structure de base

# Créer le répertoire qui deviendra la nouvelle racine sudo mkdir -p /opt/chroot-test
# Une arborescence minimale : /bin, /lib, /etc, /usr sudo mkdir -p /opt/chroot-test/{bin,lib,lib64,etc,usr}

2. Copier les binaires nécessaires

# Bash et les commandes de base sudo cp /bin/bash /opt/chroot-test/bin/ sudo cp /bin/ls /opt/chroot-test/bin/ sudo cp /bin/cat /opt/chroot-test/bin/

3. Copier les bibliothèques partagées

# Lister les dépendances d'un binaire ldd /bin/bash
# Exemple de sortie : # linux-vdso.so.1 (0x00007ffd...) # libtinfo.so.6 => /lib/x86_64-linux-gnu/libtinfo.so.6 (...) # libdl.so.2 => /lib/x86_64-linux-gnu/libdl.so.2 (...) # libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (...) # /lib64/ld-linux-x86-64.so.2 => /lib64/ld-linux-x86-64.so.2 (...)
# Copier les bibliothèques dans l'environnement chroot sudo cp /lib/x86_64-linux-gnu/libtinfo.so.6 /opt/chroot-test/lib/ sudo cp /lib/x86_64-linux-gnu/libdl.so.2 /opt/chroot-test/lib/ sudo cp /lib/x86_64-linux-gnu/libc.so.6 /opt/chroot-test/lib/ sudo cp /lib64/ld-linux-x86-64.so.2 /opt/chroot-test/lib64/

4. Entrer dans le chroot

sudo chroot /opt/chroot-test /bin/bash
# Vous êtes maintenant dans l'environnement isolé # ls / affiche le contenu de /opt/chroot-test (vu comme /) ls /
# Les真正的 fichiers du système sont inaccessibles ls /bin/bash # ERREUR : fichier non trouvé # Le monde extérieur est invisible

Sortir du chroot

# Taper exit ou Ctrl+D exit

Chroot pour la réparation système

Le scénario le plus fréquent : votre système ne démarre plus, vous bootez sur un live CD/USB, et vous devez chrooter dans votre système installé pour réparer GRUB ou un autre composant.

Procédure type de réparation GRUB

# 1. Identifier la partition système sudo fdisk -l
# 2. Monter la partition root (ex: /dev/sda1) sur /mnt sudo mount /dev/sda1 /mnt
# 3. Monter les systèmes de fichiers virtuels nécessaires sudo mount --bind /dev /mnt/dev sudo mount --bind /proc /mnt/proc sudo mount --bind /sys /mnt/sys
# 4. Chrooter dans le système installé sudo chroot /mnt
# 5. Réinstaller GRUB sur le bon disque grub-install /dev/sda update-grub
# 6. Sortir et démonter exit sudo umount /mnt/dev /mnt/proc /mnt/sys /mnt

Limites de chroot

chroot n'est pas une solution de sécurité parfaite. Un processus privilégié (root) peut s'échapper en utilisant ptrace ou en recréant des устройства. C'est pourquoi les conteneurs modernes (Docker, LXC) utilisent des mécanismes plus robustes comme les namespaces et les cgroups.

Combiner chroot avec d'autres outils

Avec unione — créer un environnement Debian minimal

# Créer un chroot Debian minimal avec debootstrap sudo apt install debootstrap sudo debootstrap jammy /opt/debian-chroot http://archive.ubuntu.com/ubuntu
# Entrer dans le chroot Debian sudo chroot /opt/debian-chroot
# Dans le chroot, vous êtes dans un vrai système Debian apt update apt install nginx # Le service nginx tourne dans l'environnement isolé

Avec schroot — gérer plusieurs environnements chroot

# Installer schroot sudo apt install schroot
# Configurer un chroot dans /etc/schroot/schroot.conf [mon-chroot] type=directory description=Mon environnement isolé location=/opt/chroot-test users=monuser groups=sudo
# Utiliser schroot pour entrer proprement schroot -c mon-chroot

Bonnes pratiques

  • Toujours créer un utilisateur non-root dans le chroot pour les tâches courantes
  • Ne jamais donner accès root depuis l'intérieur du chroot à des utilisateurs non autorisés
  • Vérifier les dépendances : un binaire a besoin de ses bibliothèques pour fonctionner
  • Utiliser ldd pour identifier les dépendances avant de copier
  • Préférer --rbind pour monter /dev, /proc, /sys dans les chroots de réparation

chroot est un outil simple mais puissant. Bien qu'il ne soit pas adapté à l'isolement de production, il reste indispensable pour la réparation système, la compilation isolé et la création d'environnements de test léger.
