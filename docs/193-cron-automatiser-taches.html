Cron — Automatiser des tâches sous Linux

Qu'est-ce que cron ?

Cron est un daemon (service en arrière-plan) qui exécute automatiquement des commandes ou des scripts à des moments précis. C'est l'outil de base pour planifier des tâches récurrentes sur un système Linux — sauvegardes automatiques, rotations de logs, vérifications, etc.

Le format d'une tâche cron

Chaque tâche cron est définie par une ligne dans le fichier crontab avec cinq champs de temps suivis de la commande à exécuter :

* * * * * commande
ChampValeurs possiblesDescription
1er0-59Minute
2e0-23Heure
3e1-31Jour du mois
4e1-12Mois
5e0-6Jour de la semaine (0 = dimanche)

Exemples concrets

Exécuter toutes les minutes

* * * * * /home/david/script.sh

Exécuter chaque heure pile

0 * * * * /home/david/script.sh

Exécuter chaque jour à 3h du matin

0 3 * * * /home/david/script.sh

Exécuter chaque lundi à 8h

0 8 * * 1 /home/david/script.sh

Exécuter le 1er de chaque mois à minuit

0 0 1 * * /home/david/script.sh

Exécuter toutes les 5 minutes

*/5 * * * * /home/david/script.sh

Spécialités : @reboot, @hourly, @daily

Cron propose des raccourcis pratiques pour les cas les plus courants :

RaccourciÉquivalentDescription
@reboot—Au démarrage de la machine
@yearly0 0 1 1 *Une fois par an (1er janvier)
@monthly0 0 1 * *Le 1er du mois
@weekly0 0 * * 0Chaque dimanche
@daily0 0 * * *Chaque jour à minuit
@hourly0 * * * *Chaque heure pile

Gestion du crontab

Éditer le crontab de l'utilisateur courant

crontab -e

Lister les tâches cron de l'utilisateur

crontab -l

Supprimer tout le crontab de l'utilisateur

crontab -r

Éditer le crontab système

Le fichier /etc/crontab est réservé à l'administrateur et inclut un champ supplémentaire pour le пользователь :

sudo nano /etc/crontab

Redirection de sortie

Par défaut, cron envoie les sorties par e-mail. Pour éviter cela, redirigez la sortie vers /dev/null :

0 3 * * * /home/david/script.sh > /dev/null 2>&1

Pour enregistrer la sortie dans un fichier log :

0 3 * * * /home/david/script.sh >> /home/david/logs/script.log 2>&1

Variables d'environnement dans cron

Cron exécute les commandes avec un environnement limité. Le PATH est souvent minimal. Définissez vos propres variables en haut du crontab :

PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin SHELL=/bin/bash 0 3 * * * /home/david/backup.sh

Vérifier que cron fonctionne

sudo systemctl status cron

Sur certaines distributions (comme CentOS/RHEL), le service s'appelle crond :

sudo systemctl status crond

Logs cron

Les executions de cron sont enregistrées dans les logs système. Sur Debian/Ubuntu :

grep CRON /var/log/syslog

Sur les systèmes avec journald :

journalctl -u cron | grep CRON

Exemple complet : sauvegarde quotidienne

# Variables d'environnement PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin # Sauvegarde quotidienne à 3h du matin 0 3 * * * /home/david/backup.sh >> /home/david/logs/backup.log 2>&1 # Nettoyage des logs toutes les semaines (dimanche à 4h) 0 4 * * 0 /home/david/clean-logs.sh > /dev/null 2>&1

Bonnes pratiques

  • Utilisez toujours des chemins absolus dans les commandes cron
  • Redirigez la sortie vers un log pour faciliter le débogage
  • Définissez le PATH en haut du crontab pour éviter les commandes introuvables
  • Testez d'abord votre script manuellement avant de l'automatiser avec cron
  • Protégez vos scripts avec des permissions restrictives (chmod 700)

En résumé

Cron est l'outil indispensable pour automatiser des tâches récurrentes sous Linux. Son format en cinq champs (minute, heure, jour, mois, jour de semaine) permet de couvrir tous les cas d'usage. Combiné avec des scripts shell, il devient un outil puissant pour l'administration système automatique.
