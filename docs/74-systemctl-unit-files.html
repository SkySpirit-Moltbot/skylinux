Leçon 74 : Les fichiers unit systemd

Introduction

Dans la leçon 21, vous avez appris à démarrer, arrêter et gérer les services avec systemctl. Mais savez-vous ce qui se cache derrière chaque service ? Chaque service systemd est défini par un fichier unit — un simple fichier texte qui indique au système comment démarrer, exécuter et surveiller votre programme.

Comprendre les fichiers unit vous permet de :

  • Créer vos propres services personnalisés
  • Configurer le redémarrage automatique en cas de plantage
  • Définir des dépendances entre services
  • Contrôler quand et comment un service démarre

Types de fichiers unit

Il existe plusieurs types de fichiers unit. Les plus courants :

  • .service — Un processus ou un daemon (le plus fréquent)
  • .socket — Un socket réseau ou IPC pour activer un service à la demande
  • .timer — Une planification (cron alternatif, vu en leçon 40)
  • .path — Surveiller un fichier/répertoire pour activer un service
  • .mount — Gérer un point de montage
  • .target — Grouper plusieurs units (comme un groupe de services)

Emplacement des fichiers unit

Les fichiers unit se trouvent à trois endroits, par ordre de priorité :

/etc/systemd/system/ → Fichiers créés par l'administrateur (priorité最高)
/run/systemd/system/ → Fichiers temporaires créés à runtime
/usr/lib/systemd/system/ → Fichiers installés par les paquets (par défaut)

Règle simple : écrivez vos fichiers personnalisés dans /etc/systemd/system/. Ils ne seront jamais écrasés par les mises à jour.

Structure d'un fichier .service

Les sections principales

SectionContenu
[Unit]Métadonnées et dépendances
[Service]Comment exécuter le service
[Install]Comment activer le service (startup)

Exemple complet : un service simple

[Unit]
Description=Mon serveur web Python
After=network.target
[Service]
Type=simple
ExecStart=/usr/bin/python3 /opt/webserver/app.py
Restart=on-failure
RestartSec=5
User=www-data
WorkingDirectory=/opt/webserver
[Install]
WantedBy=multi-user.target

详解 [Unit]

Description

Une texte descriptif qui apparaît dans les logs et via systemctl status.

Description=Service de backup automatique

After / Before

Définissent l'ordre de démarrage. Le service attend que les autres soient prêts.

After=network.target # Démarre APRÈS que le réseau soit prêt
After=network-online.target # Attend que le réseau soit vraiment fonctionnel
Before=time-sync.target # Démarre AVANT la synchronisation du temps

Wants / Requires

Définissent les dépendances (liens faibles ou forts).

Wants=network-online.target # Essaie de démarrer, mais continue même si ça échoue
Requires=network.target # ÉCHOUE si la dépendance n'est pas disponible

详解 [Service]

Type

TypeComportementQuand utiliser
simpleLe processus principal est le serviceDaemon qui tourne en foreground
forkingLe processus fork et le parent meurtDaemon classique (comme Apache)
oneshotExécute une tâche puis s'arrêteTâches uniques (ex: setup)
execSimilar à simple, mais attend que l'ExecStart soit prêtRecommandé pour les services modernes
notifyLe service envoie un signal quand prêtDaemon qui supporte systemd notifications
dbusAttend qu'un nom D-Bus soit enregistréServices avec nom D-Bus

Pour la plupart des services modernes, Type=exec ou Type=simple convient.

ExecStart, ExecStop, ExecReload

Les commandes à exécuter.

ExecStart=/usr/bin/mon_service --config /etc/mon_service.conf
ExecStop=/usr/bin/mon_service --stop
ExecReload=/bin/kill -HUP $MAINPID # Redémarrage without arrêt

Restart

Contrôle le redémarrage automatique.

Restart=no # Jamais (par défaut)
Restart=on-success # Redémarre si exit code = 0
Restart=on-failure # Redémarre si exit code != 0
Restart=on-abnormal # Redémarre sur signal anormaux (kill, crash)
Restart=always # Redémarre toujours

RestartSec

Temps d'attente avant de redémarrer (en secondes).

RestartSec=10 # Attend 10 secondes avant de redémarrer

User / Group

Exécuter le service sous un utilisateur spécifique.

User=www-data
Group=www-data

WorkingDirectory

Répertoire de travail du service.

WorkingDirectory=/var/lib/mon_service

Environment

Définir des variables d'environnement.

Environment=PORT=8080
Environment=DB_HOST=localhost
EnvironmentFile=/etc/mon_service/env # Charger depuis un fichier

TimeoutStartSec / TimeoutStopSec

Temps maximal pour démarrer ou arrêter.

TimeoutStartSec=60 # 60 secondes max pour démarrer
TimeoutStopSec=30 # 30 secondes max pour arrêter

RestartPrevent / RestartForceExitStatus

Cas spéciaux de restart.

RestartForceExitStatus=SIGTERM # Redémarre si tué par SIGTERM

详解 [Install]

WantedBy / RequiredBy

Indique dans quel target le service doit démarrer.

WantedBy=multi-user.target # Active au démarrage en mode texte
WantedBy=graphical.target # Active au démarrage en mode graphique

Also

Installe/désinstalle d'autres units ensemble.

Also=myservice.timer # Installe aussi le timer correspondant

Exemple : Service de backup

Créons un service qui exécute un script de backup toutes les nuits.

1. Créez le fichier unit

sudo nano /etc/systemd/system/backup.service
[Unit]
Description=Backup quotidien du serveur
After=network.target
[Service]
Type=oneshot
ExecStart=/opt/scripts/backup.sh
User=backupuser
EnvironmentFile=/etc/backup/env
[Install]
WantedBy=multi-user.target

2. Rechargez systemd

sudo systemctl daemon-reload

3. Activez et démarrez

sudo systemctl enable backup.service
sudo systemctl start backup.service

Bonnes pratiques

Sécurité

  • Toujours exécuter les services avec un utilisateur non-root via User=
  • 限制 LimitNOFILE pour éviter que le service mange tous les descripteurs
  • Utiliser ProtectSystem=strict pour limiter les accès aux fichiers
  • Utiliser NoNewPrivileges=true pour éviter l'escalade de privilèges
[Service]
User=www-data
ProtectSystem=strict
ProtectHome=true
NoNewPrivileges=true
PrivateTmp=true

Logging

Redirigez la sortie vers le journal systemd avec StandardOutput=journal.

StandardOutput=journal
StandardError=journal

Commandes utiles

CommandeDescription
systemctl cat mon_serviceAffiche le contenu du fichier unit
systemctl edit mon_serviceOuvre l'éditeur pour modifier le service
systemctl show mon_serviceAffiche toutes les propriétés du service
systemctl list-dependencies mon_serviceMontre les dépendances du service
journalctl -u mon_serviceVoir les logs du service

Exercice pratique

Créez un service systemd qui :

  1. Démarre un script Python toutes les 5 secondes en mode boucle
  2. Redémarre automatiquement en cas de crash
  3. S'exécute sous l'utilisateur nobody
  4. Démarre après le réseau

Correction

# /etc/systemd/system/mon_script.service
[Unit]
Description=Mon script Python en boucle
After=network.target
[Service]
Type=simple
ExecStart=/usr/bin/python3 /opt/mon_script.py
Restart=on-failure
RestartSec=5
User=nobody
[Install]
WantedBy=multi-user.target

Conclusion

Les fichiers unit systemd sont au cœur de l'administration Linux moderne. Maîtriser leur syntaxe vous permet de créer des services robustes, avec redémarrage automatique, gestion des dépendances et sécurité intégrée. C'est une compétence essentielle pour tout administrateur Linux.
