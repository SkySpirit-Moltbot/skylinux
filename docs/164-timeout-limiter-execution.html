timeout — Limiter le temps d'exécution d'une commande

La commande timeout permet d'exécuter une commande avec une limite de temps. Si la commande dépasse le délai imparti, elle est automatiquement terminée par un signal. C'est l'outil idéal pour éviter qu'un processus ne tourne indefiniment.

Syntaxe de base

timeout [OPTION] DURÉE COMMANDE [ARGUMENTS]

La DURÉE peut être exprimée en secondes (par défaut), ou avec un suffixe : s pour les secondes, m pour les minutes, h pour les heures, d pour les jours.

Exemples fondamentaux

Timeout simple en secondes

# Arrêter la commande après 5 secondes
timeout 5 sleep 10
# sleep 10 devrait durer 10 secondes, mais timeout l'arrête après 5

Avec suffixe de temps

timeout 2m ma_commande # 2 minutes
timeout 1h script_long.sh # 1 heure
timeout 30s ping localhost # 30 secondes

Options principales

OptionDescription
--signal SIGEnvoie le signal spécifié au lieu de TERM (par défaut)
-s SIGAlias court pour --signal
--preserve-statusRetourne le code de sortie de la commande même si elle a été tuée
--kill-after=DURÉEEnvoie KILL si la commande ne s'arrête pas après le premier signal
-vMode verbeux

Envoyer un signal spécifique

Par défaut, timeout envoie SIGTERM (signal 15) pour arrêter la commande. Vous pouvez spécifier un autre signal avec -s ou --signal.

# Envoyer SIGINT (Ctrl+C) après 10 secondes
timeout -s INT 10 curl https://exemple.com
# Envoyer SIGKILL (impossible à ignorer) après 5 secondes
timeout -s KILL 5 grep -r "motif" /dossier/

Forcer l'arrêt avec --kill-after

Si une commande ne répond pas au premier signal (elle peut ignorer SIGTERM), vous pouvez forcer un SIGKILL après un délai supplémentaire.

# Envoie TERM après 10s, puis KILL après 5s supplémentaires si toujours active
timeout --kill-after=5s 10m script_long.sh

Conserver le code de sortie

Par défaut, si la commande est tuée par timeout, le code de retour est 124. Utilisez --preserve-status pour conserver le véritable code de sortie de la commande.

# Sans --preserve-status : le code de sortie sera 124 (timeout)
timeout 2 cat fichier_inexistant
echo $? # 124
# Avec --preserve-status : on obtient le vrai code d'erreur
timeout --preserve-status 2 cat fichier_inexistant
echo $? # 1 (fichier inexistant)

Codes de sortie spéciaux

CodeSignification
124La commande a été terminée par timeout
125Erreur interne de timeout
126La commande n'a pas pu être exécutée
127La commande n'existe pas
AutreCode de retour normal de la commande

Utilisation dans les scripts Bash

Avec un pipe

Si vous utilisez un pipe, timeout doit encadrer l'ensemble du pipeline :

# Timeout sur un pipeline entier
timeout 30s cat gros_fichier | grep "motif" | head -20

Vérifier si une commande a expiré

#!/bin/bash
timeout 60s curl -s https://api.exemple.com/donnees > /tmp/data.json
if [ $? -eq 124 ]; then
echo "La requête a expiré après 60 secondes"
exit 1
fi
echo "Données récupérées avec succès"

Cas d'utilisation courants

  • Scripts de sauvegarde — limiter le temps d'une opération de backup nocturne
  • Requêtes réseau — éviter qu'une requête curl ou wget ne reste bloquée indefiniment
  • Tests de performance — imposer un temps maximum à une commande de benchmark
  • Scripts Cron — protéger contre des processus qui viendraient à se bloquer
  • Téléchargements — abandonner un téléchargement qui ne répond plus
# Exemple concret : télécharger avec timeout
timeout 30 curl -O https://fichier-lourd.example.com/backup.tar.gz
# Limiter la durée d'un script de sauvegarde
timeout 2h /opt/scripts/sauvegarde-quotidienne.sh

Bonnes pratiques

  • Choisissez toujours un temps suffisant pour que la commande termine normalement — timeout est une safety net, pas une course
  • Utilisez --kill-after quand vous savez que certaines commandes peuvent ignorer SIGTERM
  • Dans les scripts critiques, vérifiez le code de retour (124 = timeout) pour adapter le comportement
  • Combinez avec --preserve-status quand le code de sortie de la commande vous intéresse
