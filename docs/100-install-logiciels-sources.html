Leçon 100 — make install : Compiler et installer depuis les sources

📦 Introduction

Sous Linux, la plupart des logiciels sont disponibles via le gestionnaire de paquets de votre distribution (apt, dnf, pacman…). Mais parfois, le logiciel dont vous avez besoin n'est pas dans les dépôts, ou la version proposée est trop ancienne. Il faut alors compiler et installer depuis les sources.

Cette leçon vous guide pas à pas : téléchargement des sources, compilation avec make, et installation propre sur votre système.

🔍 Prérequis

Avant de compiler, installez les outils essentiels :

# Debian / Ubuntu
sudo apt install build-essential
# Fedora / RHEL / CentOS
sudo dnf groupinstall "Development Tools"
# Arch Linux
sudo pacman -S base-devel

Ces paquets fournissent gcc (compilateur C), make, et d'autres outils indispensables.

📥 Étape 1 — Télécharger les sources

Récupérez l'archive du logiciel. Elle se trouve généralement sur le site officiel ou un dépôt Git. Formats courants : .tar.gz, .tar.xz, .zip.

# Exemple : télécharger htop
wget https://github.com/htop-dev/htop/releases/download/3.2.2/htop-3.2.2.tar.xz

📂 Étape 2 — Extraire l'archive

tar -xvf htop-3.2.2.tar.xz
cd htop-3.2.2

⚙️ Étape 3 — Configurer le projet

La plupart des logiciels utilisent configure ou cmake pour détecter votre système et préparer la compilation.

Avec configure (projets plus anciens)

./configure

Vous pouvez ajouter des options pour personnaliser l'installation :

  • --prefix=/usr/local — où installer (défaut : /usr/local)
  • --disable-dependency-tracking — accélère la compilation
  • --prefix=$HOME/.local — installer dans votre dossier personnel
./configure --prefix=$HOME/.local

Avec cmake (projets modernes)

mkdir build && cd build
cmake .. -DCMAKE_INSTALL_PREFIX=$HOME/.local

🔨 Étape 4 — Compiler

make

Cette étape transforme le code source en exécutables. Selon la taille du projet, cela peut prendre de quelques secondes à plusieurs minutes.

Pour utiliser plusieurs cœurs (accélérer la compilation) :

make -j$(nproc)

📦 Étape 5 — Installer

sudo make install

Les fichiers sont copiés dans --prefix. Par défaut, les exécutables vont dans /usr/local/bin, accessible à tout le système.

🧹 Désinstaller proprement

Si le développeur a prévu un cible uninstall :

sudo make uninstall

Sinon, la seule solution est de supprimer manuellement les fichiers installés. C'est pourquoi utiliser --prefix=$HOME/.local est recommandé : vous pouvez tout supprimer d'un seul rm -rf ~/.local.

Autre alternative propre : utiliser checkinstall (Debian/Ubuntu) pour créer un paquet .deb et le désinstaller via le gestionnaire :

sudo apt install checkinstall
sudo checkinstall make install

📋 Récapitulatif

CommandeRôle

./configure --prefix=...Personnalise le répertoire d'installation
makeCompile le code source

🗂️ Résumé des emplacements

PréfixeEmplacement des exécutablesNotes

/opt/monlogiciel/opt/monlogiciel/bin Applications autonomes

⚠️ Bonnes pratiques

  • **Toujours lire le fichier README ou INSTALL** — chaque projet peut avoir des spécificités
  • **Vérifier les dépendances** — configure les listera souvent en cas d'absence
  • **Utiliser checkinstall** — pour une désinstallation propre via le gestionnaire de paquets
  • **Préférer --prefix=$HOME/.local** — pour les logiciels personnels, sans droits root
  • **Compiler depuis un dossier secondaire avec cmake** — garde les sources propres

💡 Exemple concret : installer neofetch depuis les sources

git clone https://github.com/dylanaraps/neofetch.git
cd neofetch
make
sudo make install
