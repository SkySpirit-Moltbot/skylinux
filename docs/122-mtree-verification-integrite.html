122 - mtree : Vérifier l'intégrité des fichiers et répertoires

Comment être sûr que vos fichiers n'ont pas été modifiés à votre insu ? Comment détecter un changement de permission, un fichier corrompu ou une intrusion ? La commande mtree est l'outil historique de Linux pour répondre à ces questions.

Qu'est-ce que mtree ?

mtree est un utilitaire qui génère une spécification (un fichier manifest) décrivant un ensemble de fichiers et répertoires. Ce manifest contient pour chaque élément des métadonnées : permissions, propriétaire, taille, somme de contrôle, timestamps… On peut ensuite comparer l'état actuel contre ce manifest pour détecter toute divergence.

mtree vient à l'origine de BSD et fait partie des utilitaires GNU sur Linux. Il est particulièrement utilisé pour :

  • Vérifier l'intégrité d'une installation ou d'une sauvegarde
  • Détecter des modifications non autorisées
  • S'assurer qu'un répertoire distant (via SSH, NFS…) n'a pas dérivé
  • Valider le contenu d'une archive avant extraction

Générer un manifest (spécification)

1. Spécification simple d'un répertoire

La forme la plus courante : créer un fichier qui décrit l'état actuel d'un répertoire.

# Générer un manifest de /opt/monapp
mtree -c -p /opt/monapp > manifest_monapp.txt

Explications :

  • -c : créer (generate output)
  • -p : chemin de base (root du répertoire à cataloguer)

Contenu typique du fichier généré :

# user: root
# date: Fri Jul 31 06:00:00 2026
/set type=file mode=0755 gid=0 uid=0
. type=dir
./bin mode=0755
./bin/monapp size=48210 sha256=3f2a8b...
./config type=dir mode=0755
./config/serveur.ini size=1204 sha256=9a1c7d...
./lib type=dir
./lib/core.so size=102400 sha256=b8e4f2...

2. Choisir les propriétés à inclure

Par défaut, mtree记录了很多属性. L'option -k (keys) permet de sélectionner quelles propriétés tracker :

# Ne tracker que les permissions et le propriétaire
mtree -c -p /opt/monapp -k mode,uid,gid > manifest_permissions.txt
# Tracker permissions, propriétaire ET somme de contrôle
mtree -c -p /opt/monapp -k mode,uid,gid,sha256 > manifest_complet.txt

Vérifier l'intégrité (comparaison)

1. Comparaison basique

Une fois le manifest créé, on peut vérifier si quelque chose a changé :

# Comparer l'état actuel contre le manifest
mtree -p /opt/monapp < manifest_complet.txt

Si tout est identique, aucune sortie. En cas de différences, mtree affiche chaque problème :

. changed
./bin/monapp changed
size expected 48210 found 48211
sha256 expected 3f2a8b... found 7c4d1a...
./config/serveur.ini missing
./log extra

Signification :

  • changed : au moins une propriété a changé
  • missing : le fichier existait dans le manifest mais plus sur le disque
  • extra : un fichier est présent sur le disque mais pas dans le manifest

2. Mode silencieux (exit code)

Pour les scripts, utilisez -q (quiet) pour n'afficher que les différences critiques et retourner un exit code :

# Script de vérification dans un cron
if ! mtree -p /opt/monapp < manifest_complet.txt; then
echo "ALERTE: Modification détectée dans /opt/monapp" | mail -s "mtree alert" admin@exemple.com
fi

Mettre à jour le manifest

Si vous avez fait des modifications légitimes (mise à jour, nouveau fichier), vous pouvez mettre à jour le manifest :

# Recréer le manifest après une mise à jour connue
mtree -c -p /opt/monapp -k mode,uid,gid,sha256 > manifest_complet.txt

Ou :

# Mettre à jour uniquement les sommes de contrôle
mtree -c -p /opt/monapp -k sha256 > manifest_sha256.txt

Exemples concrets

1. Vérifier un serveur web après une mise à jour

# 1. Créer le manifest initial
mtree -c -p /var/www/monsite -k mode,uid,gid,sha256 > /root/manifest_www.txt
# 2. Après une mise à jour, recréer le manifest
mtree -c -p /var/www/monsite -k mode,uid,gid,sha256 > /root/manifest_www.txt
# 3. Vérification automatique quotidienne
mtree -p /var/www/monsite < /root/manifest_www.txt || echo "INTRUSION!"

2. Vérifier un système de fichiers importé

# Sur la machine source : générer le manifest
mtree -c -p /sauvegardes/backup_journalier -k mode,uid,gid,sha256,size > manifest_backup.txt
# Sur la machine de restauration : vérifier avant utilisation
mtree -p /mnt/backup_restore < manifest_backup.txt

3. Vérifier un partage NFS

# Générer le manifest depuis le serveur NFS
mtree -c -p /export/partage -k mode,uid,gid,sha256 > /tmp/manifest_nfs.txt
# Sur le client NFS, vérifier l'intégrité
mtree -p /mnt/nfs/partage < /tmp/manifest_nfs.txt

4. Cron de vérification automatique

# /etc/cron.daily/verify-integrity
#!/bin/sh
mtree -p /opt/monapp < /root/manifest_monapp.txt > /var/log/mtree_check.log 2>&1
if [ $? -ne 0 ]; then
cat /var/log/mtree_check.log | mail -s "[ALERTE] mtree: modifications sur /opt/monapp" admin@exemple.com
fi

5. Spécification de format de sortie personnalisé

Vous pouvez générer un manifest dans un autre format (par exemple sans les sommes de contrôle pour une comparaison rapide) :

# Manifest léger pour vérifier rapidement les permissions
mtree -c -p /etc -k mode,uid,gid > /root/manifest_etc_perms.txt
# Vérification rapide des permissions système
mtree -p /etc < /root/manifest_etc_perms.txt

mtree dans les scripts d'installation

mtree est utilisé en coulisses par les gestionnaires de paquets BSD. Sous Linux, vous pouvez l'intégrer dans vos propres scripts d'installation :

#!/bin/bash
# Script d'installation avec vérification
APP_DIR="/opt/monapp"
MANIFEST="/root/.monapp_integrity.txt"
# Installation...
echo "Installation de l'application..."
# Générer le manifest après installation
echo "Génération du manifest d'intégrité..."
mtree -c -p "$APP_DIR" -k mode,uid,gid,sha256 > "$MANIFEST"
echo "Installation terminée. Manifest sauvegardé dans $MANIFEST"
echo "Pour vérifier: mtree -p $APP_DIR < $MANIFEST"

Bonnes pratiques

  • Stockez le manifest sur un support séparé (clé USB, serveur distant) pour qu'un attaquant ne puisse pas le modifier avec les fichiers
  • Utilisez sha256 ou sha512 de préférence à md5 (md5 est cassable)
  • Vérifiez régulièrement dans un cron, mais protecez le manifest lui-même
  • Après toute mise à jour légitime, régénérez le manifest
  • Combinez avec -e (empty) pour ignorer les répertoires vides non désirés
